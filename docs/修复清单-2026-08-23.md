## 高优先级（数据正确性）

- [x] **H1. 发票绑定采购单不校验币种，三单匹配跨币种比金额** ✅ 已修（`58096434`，含集成测试）
  - 位置：`services/procurement/internal/app/supplierinvoice.go:173-198`（绑行校验）、`supplierinvoice_match.go:127-156`（比较）
  - 问题：绑行只校验 `supplier_id` 归属，从不比较 PO 币种与发票币种；matcher 拿发票金额直接减 PO 应付额。CNY 发票绑 USD 单会产出假 MATCHED 或无意义 EXCEPTION，累计重复开票检查也会跨币种加总。
  - 修法：绑行查询把 `o.currency` 一并取出，与发票币种不一致时拒绝（对齐付款侧 `PAY_ALLOC_CURRENCY_MISMATCH` 的做法，新增如 `INV_LINE_CURRENCY_MISMATCH`）。

- [x] **H2. 发票侧无核销上限：可超核销、已结清发票仍可继续核销** ✅ 已修（`433fc42b`，含集成测试）
  - 位置：`services/procurement/internal/app/supplierpayment.go:345-417`（`AllocateSupplierPayment`）
  - 问题：只卡付款单侧余额（`adding > remaining`），从不检查发票累计核销是否超过 `total_amount`；状态只拒 `VOID`，`SETTLED` 发票照样可核。后果：对账余额变负、状态机说谎，且无报错提示。
  - 修法：在 `FOR UPDATE` 锁内读发票 `total_amount` 与未冲销核销合计，本次核销超出发票未结余额即拒绝；同时拒绝向 `SETTLED` 发票追加核销。注意同一请求里同一发票出现多行要合并计算（`touched` map 目前只去重重算、不去重金额）。

- [ ] **H3. REFUND 类型付款全链路无方向语义**
  - 位置：`services/procurement/internal/app/supplierpayment.go:33-35`、`services/procurement/internal/app/supplierstatement.go:85-135`
  - 问题：`REFUND` 只在 CHECK 约束和校验 map 出现，之后与 SETTLEMENT 完全同处理：正金额核销会把发票推成 SETTLED（用退回的钱结清发票），对账 `unallocated_amount` 被虚增。
  - 修法：先定语义再写码——要么禁止 REFUND 核销发票且不计入对账"未分配"，要么以负金额建模退款流向。

- [x] **H4. iam 权限迁移硬编码 `tenant_id = 1`（多租户潜伏，最新提交仍在复发）** ✅ 已修（`5737e65b`，含 00042 订正迁移与 check-iam-seeds CI 守卫）
  - 位置：`services/iam/db/migrations/00036_supplier_invoice_permissions.sql:13`、`00038_supplier_payment_permissions.sql:11`、`00039_supplier_statement_permissions.sql:10`；**2026-08-23 新合入的 `00040_order_close_permission.sql:11` 又犯了同样的错**（同批的 `00041` 写法正确）
  - 问题：授权用 `SELECT 1, r.id, p.id`，既有约定（`00033`/`00034`）是 `SELECT r.tenant_id, r.id, p.id`。tenant≠1 的租户其 SUPER_ADMIN 永远拿不到发票/付款/对账/订单结案四个权限。
  - 修法：改为 `SELECT r.tenant_id, …`。若坏迁移已在某环境跑过，需要补一个数据订正迁移，不能只改历史文件。同一错误已连续出现四次，建议在 `scripts/` 加 CI 守卫（禁止 role_permissions 插入字面量 tenant_id）。
  - 附带：`00038` 的 `procurement:payment:read/write` 与 `00033` 重复，`ON CONFLICT DO NOTHING` 使改名/menu_path 不生效；`00038` 的 Down 会误删 `00033` 创建的权限行，回滚陷阱一并处理。

## 中低优先级

- [ ] **M1. 预付款可挂到 DRAFT / REJECTED 采购单**
  - 位置：`services/procurement/internal/app/supplierpayment.go:400`
  - 问题：核销到 PO 只拒 `CANCELLED`；对账视图自己认定 committed 状态集是 `ORDERED/PARTIALLY_RECEIVED/RECEIVED`（`supplierstatement.go:60`），两边定义矛盾，钱可挂上被驳回永不下单的 PO。
  - 修法：核销目标 PO 限定 committed 状态集。

- [ ] **M2. 创建发票在 DB 事务内调用 fx RPC**
  - 位置：`services/procurement/internal/app/supplierinvoice.go:214-222`
  - 问题：`Begin` 之后调 `fxSnapshot`（内部走 fx 服务 gRPC），fx 抖动时事务占住连接。对照：`CreateSupplierPayment` 的编号 RPC 在事务外调用，做法正确。
  - 修法：把 `fxSnapshot` 挪到 `Begin` 之前。

- [ ] **M3. 明细-表头一致性校验在 NUMERIC(18,2) 落库舍入之前做**
  - 位置：`services/procurement/internal/app/supplierinvoice.go:206-211` + 迁移 `00013` 的 `amount NUMERIC(18,2)`
  - 问题：全精度校验 `sum(lines) == total`，落库 half-up 舍入后可能差一分钱（如两行 `50.005`），存储数据反而违反校验本想保证的不变量。
  - 修法：录入时限制行金额最多两位小数，或先按 18,2 舍入再校验。

- [ ] **M4. 数据范围旁路：录入发票可引用他人采购单**
  - 位置：`services/procurement/internal/app/supplierinvoice.go:156-198`（配合 `order_scope.go`）
  - 问题：绑行直接按 `tenant_id + id` 查 PO，不走 `AuthorizeOrder`；SELF 范围用户可绑他人 PO，`GetSupplierInvoice` 的 JOIN 会把 `po_no` 带回。
  - 修法：绑行时接入数据范围校验。

- [ ] **M5. 对账明细行不含手续费，与汇总对不上**
  - 位置：`services/procurement/internal/app/supplierstatement.go:189-245`
  - 问题：明细 UNION ALL 只取 `amount`，汇总 `unallocated_amount` 却扣了 `amount + fee_amount`；带手续费的核销下钻后解释不了汇总数。
  - 修法：明细行补 `fee_amount`，running balance 一并考虑。
