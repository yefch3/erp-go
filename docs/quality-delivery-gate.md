# 质检合格后交货

采购、仓库和运输统一执行：货物全部质检合格后才能交货。未申请质检、待检、检验中、不合格、部分合格或复检中的货物均禁止实际交货。提前安排船期、订舱、维护预计时间和准备出库草稿仍然允许。

## 放行依据

采购服务提供权威质检判定。采购单必须已有整单质检任务，任务已完成，存在检查记录，当前采购单每条明细均被检查覆盖且全部合格，合格及放行数量覆盖采购数量。仅记录异常处理完成或取消缺少数量不构成质检通过。已收齐但缺少整单质检的采购单也可申请补检，必须记录实际合格结果后才能放行。

工厂质检通过后，收货复查发现的不合格或质量争议同样阻断交货。扣款、让步接收、返工等处理备注不能替代同一收货批次及产品的明确复检合格依据；收货后的合格记录也不能替代缺失的工厂整单质检。

采购交货登记在同一事务内检查质检，再记录数量；生产进度中的“已送港”新增或更改实际日期也必须先通过质检，预计送港日期可以提前维护。当前库存没有待检批次隔离能力，因此未检货也不能通过采购入库成为可发库存。

仓库确认出库前，按实际拣货库存追溯采购入库来源，并核验所有来源采购单。库存按仓库、产品和规格合并，无法区分来源批次时采用保守规则：混合来源必须全部可核验且全部合格；手工、期初或无法追溯的来源不自动视为合格。

正式船期登记实际发运、实际离港时间及旧出运单确认开船时，核验实际关联的合同货物，并检查累计数量是否有足够采购质检依据。提前建立船期和修改预计日期不受此检查限制。

船舶接近或抵达起运港、跳过计划港口不代表货物已发运。修改预计时间或移除未使用港口也不能把这些操作自动变成已发运依据；自动推进实际发运状态同样受质检校验约束。

同商品的多条当前合同明细，优先保留各自明确关联的采购数量，历史采购数量只能分配一次。合同改版前已安排的船期和出运草稿，在同合同、商品信息完全一致且最新明细唯一时，可把旧明细映射到最新明细并合并累计交货量；无法唯一对应、商品规格改变或明细被删除时仍阻断，需先核对货物关联。

新增实际交付还须核验外销合同的当前执行条件。合同暂停、正在终止、已终止、已关闭或未放行时，禁止新的采购直交、首次实际送港、库存确认出库和首次实际发运。直交按本次交货明细核验关联合同，避免合并采购单中另一合同暂停而误拦本次正常货物；实际送港按整张采购单核验。已下单采购入公司仓库保管仍须质检合格；取消未发出的出库单、已记录送港事实的维护和真实已发运航程的到港结案属于善后，不新增交付。

独立补录物流单保留自己的单号和货物身份。关联真实销售合同后，实际发运按同租户、同合同最新正式货物快照映射：名称、规格、单位必须一致；填写编码时编码也必须一致，没有编码时必须只能对应一条真实合同明细。跨批次的同一明细仍算一条来源，多个不同明细或不同 SKU 无法唯一对应时拒绝放行。正式物流单与已关联补录单共享累计已发运数量，不能各自重复使用同一份合格数量。未关联、资料不符或来源无法核验的补录单仍不放行。

质检服务未配置、调用失败或返回无法判定时拒绝放行，保留原单据供重试。检查失败不得扣减库存、增加收货数量、推进实际发运状态或生成发货事件。

## 说明

历史库存不会自动补造合格结果。缺失采购质检来源的库存需先补齐可核验依据；本次不引入仓库待检批次或免检、特批放行入口。

采购质检 RPC 由库存、物流通过 `PROCUREMENT_ADDR` 调用；库存还通过 `EXPORT_ADDR` 实时核验合同执行状态。执行核验只返回能否继续交付，不授予采购、库存或物流人员合同价格、客户文件和收款资料读取权限。部署时先更新出口服务的执行核验权限，再更新采购及其余交付调用方。无需新增数据库迁移。

## 验收顺序

1. 对未检采购单登记交货或填写实际送港日期，应被拒绝；仅填写计划日期应可保存。
2. 申请质检，分别验证待检、检验中及不合格/复检状态均不能交货；所有明细实际检查合格后，原单据可继续分批交货。
3. 库存确认出库及登记船期实际发运也必须核验；提前建船期、订舱、修改预计日期应可进行。
4. 工厂通过后再登记仓内不合格或质量争议，出库应重新被拦；仅补处理备注不能放行，完成同批、同产品足量复检合格后才恢复。
5. 对已全量质检合格、尚未交付的单据暂停合同，直交、实际送港、出库和所有首次实际发运入口都应被拒绝且数量、流水和事件不变；恢复合同后原单据可以继续。真实已发运后暂停合同，仍可维护已有事实并完成后续航程。
6. 独立补录物流单关联合同并完成前置审批后，唯一匹配的货物在通过质检后应正常发运；与正式船期交叉尝试发运时，累计超出已合格数量的那一批必须被拒绝。
