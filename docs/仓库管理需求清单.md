# 仓库管理需求清单

> 状态截至 2026-08-23。本文档是仓库管理母模块的功能盘点、产品设计、设计边界与开发台账：
> ✅ 已完成并实测；⬜ 未做；🔶 部分完成/存在缺口。
> 每完成并实际测试一项，再更新对应状态；页面存在不等于功能完成。

> 本模块已有 `inventory` 服务、库存、收货、出库、库存预留、流水和移动加权成本基础能力，
> 不从零重做。开发时优先复用现有产品、采购、合同、出运、权限、编号和审计能力。

## 0. 定位

“仓库管理”是独立业务模块，负责回答以下问题：货在哪里、是什么规格、实际有多少、
多少已被业务占用、为什么发生变化，以及谁在什么时间执行了收发和调整。

核心关系：

```text
仓库主数据 → 库位（可选）→ 产品/SKU 库存
                         ├─ 在库数量
                         ├─ 已预留 / 已锁定 / 已冻结
                         ├─ 可用数量
                         └─ 库存成本

采购订单 → 收货/质检 → 入库 → 库存流水
销售合同 → 库存预留 → 拣货/出库 → 出运
仓库之间 → 调拨出库 → 在途 → 调拨入库
盘点/纠错 → 调整单 → 库存流水
```

面向未来对外销售时，每家公司拥有独立的仓库、库位、编号规则、库存和权限范围；
可以按公司启用或关闭库位、批次、序列号、质检等高级能力，不能为每个公司复制代码。
AI 不参与库存数量和成本记账，库存变化必须由可追踪的业务单据和确定规则产生。

### 0.1 产品原则

1. **仓库能力按公司启用，不按公司复制代码。** 同一套系统支持不使用仓库、统一使用仓库，以及按订单选择是否入库的公司。
2. **港口不等于仓库。** 货物直接交付到港口、码头或客户指定地点时，只记录采购交付和签收，不自动形成公司库存。
3. **是否记库存取决于履约路线。** 只有明确选择“先入库再发货”，并完成收货入库时，才产生库存余额和库存流水。
4. **历史单据保存当时配置快照。** 公司以后关闭仓库能力，不影响已经产生的采购单、收货单、库存流水和审计记录。
5. **复杂功能按需显示。** 未启用仓库、库位、质检、批次或成本的公司，不应看到不能使用的空菜单和多余字段。

### 0.2 仓库使用模式

这里配置的是公司如何使用仓库，不是把“仓库管理”改成履约模块。租户管理员设置默认的仓库使用模式；选择“按订单选择”时，可在采购订单或订单明细中决定本次货物是否进入仓库。修改模式前，必须展示受影响的仓库、库存和未完成单据数量。

| 仓库使用模式 | 简单解释 | 货物流向 | 是否形成库存 | 系统显示 |
|---|---|---|---|---|
| **不使用仓库** `NO_WAREHOUSE` | 货物不进入公司仓库 | 供应商 → 港口或指定地点 | 否 | 到货跟踪、签收凭证、导入和提醒 |
| **使用仓库** `USE_WAREHOUSE` | 货物先收货入库，再从仓库发出 | 供应商 → 自家仓库/港口仓库/第三方仓库 → 出库 | 是 | 收货、库存、出库、调拨、盘点、导入和提醒 |
| **按订单选择** `SELECT_PER_ORDER` | 每张订单或每条明细决定是否入库 | 直送或入库，两种路线均可 | 只有选择入库的明细形成 | 显示已启用功能，并按订单实际选择记账 |

业务页面只显示中文名称及“是否进入仓库”的简短说明；内部代码仅供接口、数据库和开发使用，不直接暴露给普通业务人员。“履约方式”只用于描述某一张订单的实际路线，不作为仓库模块或公司模式名称。

为避免把“公司模式”“仓库类型”和“业务页面”混在一起，产品结构固定为四层：

```text
仓库管理（母模块）
├─ 公司仓库使用模式：不使用仓库 / 使用仓库 / 按订单选择（公司级流程配置，不是子模块）
├─ 仓库资料类型：自家仓库 / 港口仓库 / 第三方仓库（资料分类，不是三套系统）
├─ 业务子模块：工作台 / 仓库资料 / 到货收货 / 库存 / 出库 / 调拨盘点 / 导入提醒
└─ 单据履约路线：直发港口或指定地点 / 先入库再发货（每张业务单据的选择）
```

补充规则：

- 港口/码头可以只是“交付地点”；只有公司确实控制当地库存，并把它配置成可记账的港口仓库或第三方仓库时，才参与库存。
- 港口仓库和第三方仓库可以选择“只记录交付凭证”或“同步库存”两种管理方式；第一阶段只实现系统内人工维护，不接第三方 API。
- 有未清库存或未完成入库/出库单时，不允许直接切换为“不使用仓库”。
- 仓库使用模式变化写入审计历史，并记录操作人、原因、变化前后配置和时间。

### 0.4 WH0 现状审计结论（2026-08-23）

本节记录对现有 ERP 代码、数据库、接口、权限和页面的实际审计结果，作为 WH1 以后开发的边界。后续优先扩展现有能力，不重新建立一套平行库存系统。

#### 可以直接复用的能力

| 范围 | 已有实现 | 后续用途 |
|---|---|---|
| 库存服务 | 已有独立 `services/inventory` 服务、Proto/gRPC、Gateway 路由和迁移框架 | 继续作为仓库与库存领域的唯一后端入口 |
| 库存数据 | 已有 `warehouses`、`stocks`、库存流水、预留、锁定、冻结、在途和可用量 | WH1 扩展仓库资料；WH3 统一库存总览与流水 |
| 出库能力 | 已有可出库查询、出库单创建、确认和取消 | WH6 在现有出库能力上增加仓库作业流程 |
| 采购联动 | 采购服务会发布 `PurchaseReceived`，库存服务已有 Kafka 消费入口 | WH2 建立正式收货单后复用事件链路，避免重复入账 |
| 成本基础 | 已有移动加权平均成本、币种和金额字段 | WH3/WH7 补齐权限、对账和联合验收 |
| 基础数据 | 已有港口、供应商/工厂、员工等选择组件和接口 | 复用为仓库地点、第三方服务商、负责人和联系人来源 |
| 权限框架 | 已有 IAM 角色权限迁移、Gateway 鉴权和 `inventory:stock:read/write` | WH1 沿用现有鉴权方式，后续再细分配置和成本权限 |

#### 必须补齐的缺口

- `warehouses` 当前只有编码、名称、旧类型、地址、单一负责人和状态，尚不能表达自家仓库、港口仓库、第三方仓库的专属资料、多名内部负责人、外部联系人和“仅凭证/同步库存”。
- 当前仓库类型仍为 `NORMAL / BONDED / TRANSIT / VIRTUAL / PORT_TERMINAL`，与产品层的 `OWN / PORT / THIRD_PARTY` 不一致；必须通过可回滚迁移兼容旧值，禁止直接覆盖历史仓库。
- 系统还没有公司级仓库使用模式、功能开关和模式变更审计，无法按租户区分“不使用仓库 / 使用仓库 / 按订单选择”。
- 当前手工收货和采购收货会直接更新库存，没有正式的收货单、收货明细、状态流转、差异、附件和幂等确认记录。
- 现有 `/receipts` 页面属于财务客户收款，不是仓库收货；仓库收货必须使用独立路由（建议 `/warehouse/receipts`），不能复用或覆盖该页面。
- 尚无仓库导入、预检、错误报告、提醒生成与去重能力。
- `services/inventory` 当前未发现 Go 测试文件；WH1 起每个批次必须补迁移、业务校验、Gateway 权限和前端构建测试。

#### 已确认的技术决策

1. 保留现有库存余额、流水、预留、出库和成本结构，只做兼容式扩展，不删除现有数据。
2. WH1 的下一条库存迁移使用 `00006_warehouse_profiles.sql`，必须支持 Up/Down/Up，并保留现有 `WH01`、`PORT_TERMINAL` 和业务引用。
3. 公司仓库模式与仓库资料先归库存服务管理；未来若建立统一系统设置中心，只迁移配置入口，不复制业务数据。
4. 港口只是地点；只有明确配置为可记账仓库且启用“同步库存”时，才进入库存余额。
5. 采购收货、仓库收货与库存入账必须共用一个幂等业务入口，防止 Kafka 重试或人工重复点击造成重复库存。
6. 仓库收货使用独立菜单和路由，避免与财务“收款记录”发生名称和路径冲突。

#### WH1 的准确范围

WH1 只建立后续开发所需的配置和骨架，不提前实现 WH2～WH7：

- 建立公司仓库使用模式、功能开关和配置变更历史。
- 扩展三类仓库资料，支持内部负责人、外部联系人、地点和库存记账方式；兼容旧仓库类型和旧数据。
- 建立“仓库管理”母菜单、模式化工作台空状态、仓库资料页和仓库设置页的基础路由。
- 建立统一仓库/交付地点选择接口和前端组件，供采购、合同和出运后续复用。
- 按现有 IAM/Gateway 规范建立基础查看与维护权限。
- 添加迁移回滚、类型/必填校验、租户隔离、路由权限和前端构建测试。
- 不在 WH1 实现正式收货、质检、库存导入、提醒、调拨、盘点或新的成本算法。

预计主要修改范围：`services/inventory` 的迁移、查询、应用层和 Proto，`services/gateway` 的仓库配置路由，`frontend` 的路由、菜单、页面、选择组件和三语文案，以及对应测试。实施前仍需按当时最新 `main` 复核文件清单。

## 1. 模块与菜单结构

- ⬜ 左侧提供独立“仓库管理”母菜单，不把库存页面散落在采购或出运模块中。
- ⬜ 母模块按顺序提供“仓库工作台 / 仓库资料 / 到货与收货 / 库存管理 / 出库发货 / 调拨盘点 / 导入中心 / 提醒中心 / 仓库设置”子模块。
- ⬜ 选择**不使用仓库**的公司仍可维护港口或第三方交付地点及联系人，并显示到货/签收、导入和提醒；不显示库存、库位、调拨、盘点及库存成本。
- ⬜ 选择**使用仓库或按订单选择**的公司根据已启用能力显示仓库、库位、入库、库存、出库、调拨和盘点。
- ⬜ 工作台根据仓库使用模式显示关键数字：待签收、待入库、待质检、库存异常、待出库和逾期任务；没有意义的指标不显示为 0 卡片。
- ⬜ 列表和单据详情使用独立路由，刷新后保留筛选条件。
- ⬜ 页面使用简洁面包屑，不在每个页面重复展示完整仓储流程图。
- ⬜ 中文、英文和西班牙文菜单及核心状态完整。
- ⬜ 桌面端、仓库平板和窄屏页面均可操作。

### 1.1 子模块职责

| 子模块 | 主要职责 | 使用范围 |
|---|---|---|
| 仓库工作台 | 汇总本人待办、到货、入库、库存与异常，提供快捷入口 | 全部模式 |
| 仓库资料 | 统一维护自家仓库、港口仓库、第三方仓库及其负责人、联系人和启停状态 | 全部模式；不使用仓库时可作为交付地点资料 |
| 到货与收货 | 从采购单承接直送签收或仓库收货，记录分批到货、凭证和差异 | 全部模式 |
| 库存管理 | 查询在库、可用、预留、冻结、批次、成本与流水 | 使用仓库/按订单选择 |
| 出库发货 | 从合同或业务需求创建拣货、出库和发运交接 | 使用仓库/按订单选择 |
| 调拨盘点 | 仓库间调拨、库位移动、盘点和库存调整 | 启用后显示 |
| 导入中心 | 下载模板、预检、导入、错误报告、批次记录与可控撤销 | 全部模式 |
| 提醒中心 | 集中处理逾期、差异、低库存、待确认和导入异常 | 全部模式 |
| 仓库设置 | 公司仓库使用模式、库位/批次/质检开关、编号和提醒规则 | 管理员 |

## 2. 仓库与库位主数据

### 2.1 仓库

- ⬜ 仓库保存系统 ID、租户内唯一编码、名称、固定类型、国家/地区、城市、时区、详细地址、经纬度（可选）、库存记账方式和状态。
- ⬜ 第一阶段仓库类型固定为：**自家仓库** `OWN`、**港口仓库** `PORT`、**第三方仓库** `THIRD_PARTY`；工厂、港口交付地点和在途地点不再伪装成仓库类型。
- ⬜ 仓库编码默认系统生成，并允许租户管理员配置前缀和流水规则。
- ⬜ 内部负责人从启用员工中选择，可配置多人，但必须明确一名主要负责人；负责人不等于仓库操作权限。
- ⬜ 外部联系人支持多人，并明确一名主要联系人；草稿可暂缺，仓库启用并用于新业务前，港口仓库和第三方仓库必须至少有一名有效主要联系人。
- ⬜ 仓库停用前显示在库数量、未完成收货、未完成出库和调拨数量。
- ⬜ 有库存或未完成单据时禁止直接停用；必须先清理、调拨或关闭业务。
- ⬜ 仓库停用后保留历史单据和流水，但不能用于新业务。

#### 2.1.1 内部负责人和外部联系人

- ⬜ **内部负责人**代表本公司负责这座仓库的员工，保存员工、职责、是否主要负责人、生效/失效日期和备注。
- ⬜ 同一仓库允许配置采购、收货、库存、财务等多名内部负责人，但同一时间只能有一名主要负责人。
- ⬜ 内部负责关系变化写入历史；员工离职或停用时提示重新指定主要负责人。
- ⬜ **外部联系人**代表港口、码头、仓储公司或 3PL 的对接人员，不创建 ERP 登录账号，也不自动获得权限。
- ⬜ 外部联系人保存姓名、所属机构、岗位/职责、手机、电话、邮箱、WhatsApp/微信、首选语言、时区、服务时间、是否主要联系人、状态和备注。
- ⬜ 单据生成时保存当时的负责人和联系人快照；以后修改主数据不覆盖历史单据。

#### 2.1.2 不同仓库类型的专属资料

| 类型 | 必要专属资料 | 常用可选资料 |
|---|---|---|
| 自家仓库 | 仓库名称、地址、时区、内部主要负责人 | 营业时间、装卸能力、库区/库位、容量提示、安全要求 |
| 港口仓库 | 关联港口/UN/LOCODE、码头或场站名称、运营方、外部主要联系人 | 预约方式、截关/提货要求、免堆期、保税属性、常用费用说明 |
| 第三方仓库 | 第三方服务商、服务地点、合同/协议编号、外部主要联系人 | 服务范围、计费方式、SLA、营业时间、接口/对账说明、合同有效期 |

- ⬜ 关联港口从基础数据的港口资料选择；第三方服务商从启用的供应商资料选择，不在仓库页面重复新建。
- ⬜ 港口、运营方、服务商或合同变更必须留历史，不静默覆盖已发生业务。
- ⬜ 每座港口仓库和第三方仓库单独配置“只记录交付凭证”或“同步库存”；只有“同步库存”才产生库存余额。
- ⬜ 仓库已经被业务引用后不允许直接修改类型；需停用旧仓库并新建正确类型，历史仍指向原记录。

### 2.2 库区与库位（租户可选）

- ⬜ 租户可以选择“只按仓库管理”或启用“仓库 + 库区 + 库位”。
- ⬜ 库位保存仓库、库区、编码、名称、用途、容量提示、拣货顺序和状态。
- ⬜ 库位用途至少支持：正常、待检、合格、冻结、不合格、退货和暂存。
- ⬜ 未启用库位管理的公司不需要填写库位，所有库存归属仓库默认库位。
- ⬜ 有库存的库位不能停用；移动库位必须通过移库/调拨单留下流水。
- ⬜ 库位编码在同一仓库内唯一，不要求跨租户或跨仓库唯一。

## 3. 库存模型与可用量

- ⬜ 库存最少按“租户 + 仓库 + 产品/SKU”隔离；启用库位或批次后增加对应维度。
- ⬜ 区分在库、预留、锁定、冻结和可用数量，不用单一“库存数量”承担所有含义。
- ⬜ 可用数量规则统一为 `在库 - 预留 - 锁定 - 冻结`，所有模块调用同一服务计算。
- ⬜ 默认禁止负库存；是否允许紧急负库存必须是租户级配置并受单独权限控制。
- ⬜ 数量使用 decimal，单位来自产品/SKU，不能用浮点数或自由文本单位。
- ⬜ 同一库存维度的并发收发必须使用数据库锁或原子更新，防止超卖和重复扣减。
- ⬜ 库存列表支持仓库、库位、产品、SKU、状态、有货/缺货和关键词筛选。
- ⬜ 库存详情显示当前数量、业务占用、最近流水、来源单据和成本摘要。
- ⬜ 产品改名或停用不修改历史流水快照；库存仍可完成清理和出库。

### 3.1 批次、序列号和库存状态（租户可选）

- ⬜ 租户可以按产品分类配置是否启用批次号、生产日期、有效期或序列号。
- ⬜ 启用批次管理后，收货必须填写批次，出库必须明确消耗批次。
- ⬜ 启用序列号后，同一租户内序列号不能重复入库。
- ⬜ 批次到期、冻结或不合格库存不能进入正常可用量。
- ⬜ 未启用这些能力的公司保持简单库存流程，不增加无用字段。

## 4. 收货、质检与入库

### 4.1 收货单

- ⬜ 收货来源至少支持：采购订单、客户退货、调拨入库和手工调整。
- ⬜ 从采购订单收货时自动带出供应商、工厂、产品/SKU、订单数量、已收数量和剩余数量。
- ⬜ 允许分批收货，但累计数量不能无权限超出订单数量。
- ⬜ 收货单状态至少区分：草稿、待确认、已入库、已取消。
- ⬜ 草稿可编辑；确认入库后不得直接改数量，只能通过退货或冲销单纠正。
- ⬜ 相同外部单号或幂等键重复提交不能重复增加库存。
- ⬜ 收货记录操作人、时间、来源单据、备注和附件。

### 4.2 质检（租户可选）

- ⬜ 租户可以关闭质检；关闭时合格收货直接入正常库存。
- ⬜ 启用质检时，收货先进入待检/冻结库存，不计入可用量。
- ⬜ 质检结果支持合格、部分合格、不合格，并记录抽检数量、原因、操作人和附件。
- ⬜ 合格数量转入正常库存，不合格数量转入不合格/退货状态。
- ⬜ 质检结果确认后通过独立纠正单修改，不能覆盖原记录。

## 5. 预留、拣货与出库

- ⬜ 合同生效或业务确认后可以预留库存，预留必须绑定具体合同/业务明细。
- ⬜ 预留、锁定和实际出库是不同状态，释放规则分别记录。
- ⬜ 创建出库单时选择合同和可出库明细，系统显示需求、已出、可用、预留和缺口。
- ⬜ 出库数量不得超过允许数量或实际可用库存；后端必须再次校验，不能只依赖前端。
- ⬜ 出库单状态至少区分：草稿、待拣货、已锁定、已出库、已取消。
- ⬜ 草稿不扣减在库数量；锁定占用可用量；确认出库才减少在库并形成成本流水。
- ⬜ 取消草稿/锁定单释放占用；已确认出库不能取消，只能创建退货入库或冲销单。
- ⬜ 支持部分出库，并防止累计出库超过合同或业务需求。
- ⬜ 出库完成后向出运/合同模块回写实际出库数量和状态。

## 6. 调拨、移库、盘点与调整

### 6.1 调拨与移库

- ⬜ 同仓库库位之间使用移库单，不改变公司总库存和成本。
- ⬜ 不同仓库之间使用调拨单，状态至少为草稿、已发出、在途、已收货、已取消。
- ⬜ 调拨发出后从来源仓扣减并进入在途库存，目标仓确认后转入目标库存。
- ⬜ 不能以一条直接数据库更新同时完成跨仓调拨，必须保留发出与接收记录。
- ⬜ 调拨差异记录实收数量、短少/破损原因和处理人。

### 6.2 盘点与库存调整

- ⬜ 支持按仓库、库位、分类或 SKU 创建盘点任务。
- ⬜ 盘点期间可按配置冻结目标库存或允许业务继续并记录截止时间。
- ⬜ 记录账面数量、实盘数量、差异、原因、盘点人和复核人。
- ⬜ 差异确认后通过调整单形成正负库存流水，不直接改写库存余额。
- ⬜ 超过租户配置阈值的调整必须审批；小额调整也必须有权限和原因。
- ⬜ 所有已确认调整不能编辑或删除，只能使用反向调整纠正。

## 7. 库存成本与币种

- ⬜ 第一阶段继续使用现有移动加权平均法，入库时更新平均成本和总成本。
- ⬜ 同一成本池必须明确币种，不把不同币种直接平均。
- ⬜ 外币采购入库时保存原币、汇率、记账币和换算时间，来源可追溯。
- ⬜ 预留、锁定、冻结和移库不改变公司库存总价值。
- ⬜ 确认出库时冻结当次单位成本和出库金额，之后平均成本变化不回写历史。
- ⬜ 手工成本调整需要独立权限、原因和审计。
- ⬜ FIFO、标准成本等其他计价法暂不实现，但表和接口避免把移动平均写死为无法迁移的格式。

## 8. 跨模块联动

- ⬜ 产品模块提供启用产品/SKU 和单位；仓库模块不允许自由输入模糊产品名称形成库存。
- ⬜ 采购订单提供待收货明细，确认入库后回写累计收货数量和状态。
- ⬜ 合同/销售需求触发库存核算、预留和缺口，缺口可生成采购需求。
- ⬜ 出库完成后合同和出运模块获得实际出库数量，不各自计算库存。
- ⬜ 船期/出运可以引用已出库或待装运货物，但不能直接修改库存余额。
- ⬜ 业务模块选择仓库时只显示启用且当前用户有权限的仓库。
- ⬜ 仓库、产品或供应商后续改名不修改历史单据快照。
- ⬜ 跨服务写入使用幂等键、Outbox/Kafka 或已有可靠机制，重试不能重复收发货。

### 8.1 采购履约路线

采购订单审批并下单时必须保存履约方式快照，后续仓储页面按快照承接，不能根据公司当前设置临时猜测。

**路线 A：直发港口 / 指定地点**

```text
采购单已下单 → 供应商交付跟踪 → 到港/到指定地点 → 员工签收或上传交付凭证 → 采购完成
```

- ⬜ 保存港口或自定义地址、要求到货日期、实际到货日期、签收数量、差异、签收人和凭证。
- ⬜ 不创建仓库收货单，不增加在库数量，不产生库存成本流水。
- ⬜ 港口签收只证明采购履约；除非该地点已配置为“同步库存”的港口仓库或第三方仓库，否则不能显示为库存。

**路线 B：先入库再发货**

```text
采购单已下单 → 供应商交付跟踪 → 仓库收货 → 可选质检 → 入库记账 → 库存/后续出库
```

- ⬜ 采购单必须选择启用仓库；启用库位或质检时再要求对应字段。
- ⬜ 只有确认入库后才增加库存和更新移动平均成本。
- ⬜ 分批收货分别形成记录，并回写采购单累计已收数量。

**混合履约**

- ⬜ 同一客户业务可以拆成多张采购单，或按采购单明细选择直发/入库；每条明细只能属于一条有效履约路线。
- ⬜ 已经收货、签收或形成库存流水后，不允许直接切换履约方式；必须冲销原业务后重新选择。
- ⬜ 页面必须明确显示“直发不入库存”或“先入库再发货”，避免员工把港口交付误认为仓库入库。

### 8.2 统一选择组件

- ⬜ 采购、合同、出运和仓储复用同一仓库/库位/港口选择器，不各自维护不同数据源。
- ⬜ 选择器只返回当前租户已启用且用户有数据权限的记录。
- ⬜ 仓库选择结果统一显示仓库类型、名称、国家/城市、库存记账方式、内部主要负责人和外部主要联系人，避免只看到名称无法判断用途。
- ⬜ 先选仓库后只显示该仓库可用库位；选择港口时显示 UN/LOCODE、名称、国家、时区及其关联港口仓库。
- ⬜ 选择第三方服务商后，只显示该服务商下已启用的第三方仓库；第三方仓库显示“仅凭证”或“同步库存”标签。
- ⬜ 业务单据保存选择时的仓库名称、地址、内部负责人和外部联系人快照；以后资料变更不篡改历史单据。

## 9. 多租户、权限与审计

- ⬜ 所有仓库、库位、库存、单据和流水都必须包含 `tenant_id`，查询和唯一约束包含租户范围。
- ⬜ 任一接口都不能通过修改 ID 查看其他租户仓库、库存、成本或单据。
- ⬜ 每家公司独立配置：仓库使用模式、编号规则、库位、批次/序列号、质检、负库存和调整审批阈值；仓库资料类型为系统固定枚举，不允许租户创建语义冲突的类型。
- ⬜ 权限至少拆分：查看仓库资料、维护仓库资料、维护外部联系人、分配内部负责人、使用仓库、查看库存、查看成本、收货、质检、出库、调拨、盘点、调整和审批。
- ⬜ 数据范围支持本人负责仓库、指定仓库、部门仓库和全部仓库，最终规则与员工权限模块统一。
- ⬜ 内部负责人必须来自当前租户的在职员工；外部联系人只是业务资料，不创建 ERP 账号、不参与内部权限判断。
- ⬜ 员工只能查看其数据范围内仓库的完整联系人信息；无权限列表只显示仓库名称和必要地点信息。
- ⬜ 仓库操作员看数量但不一定看成本；财务/管理员按权限查看成本金额。
- ⬜ 所有确认、取消、冲销、冻结、解冻和调整记录操作人、时间、原因及前后数量。
- ⬜ 库存流水只追加，不允许普通接口修改或删除。

## 10. 导入中心

导入功能用于批量初始化或批量录入，不代替正常业务审批，也不能绕过库存流水直接覆盖余额。

### 10.1 支持的导入类型

- ⬜ 仓库、库区和库位主数据导入；仓库模板同时包含通用字段和按类型启用的专属字段。
- ⬜ 内部负责人关系和外部联系人使用独立工作表导入，以仓库编码关联；同一仓库最多一名内部主要负责人和一名外部主要联系人。
- ⬜ 期初库存导入：仓库、库位、产品/SKU、批次、数量、单位、单位成本和币种。
- ⬜ 采购收货/直发签收导入：用于已有外部记录的批量补录，仍按履约模式校验。
- ⬜ 盘点结果导入：只写入盘点任务，复核确认后才生成库存调整。
- ⬜ 第一阶段不支持通过导入直接修改已确认的收货、出库或库存流水。

### 10.2 导入流程与规则

```text
选择导入类型 → 下载当前版本模板 → 上传 Excel/CSV → 预检与字段映射
→ 人工确认 → 批量写入 → 结果与错误报告
```

- ⬜ 模板包含模板编码和版本；系统只接受当前支持版本，并明确提示缺失/未知表头。
- ⬜ 仓库类型、库存记账方式、负责人/联系人关系和主要标识必须使用系统标准值；不符合类型专属必填规则的行不能导入。
- ⬜ 上传后先执行预检，不立即写库；显示总行数、有效行、警告行、错误行和重复行。
- ⬜ 错误必须精确到工作表、行号、字段、原值和原因，并可下载错误报告。
- ⬜ 必填、格式、单位、租户范围、仓库/产品状态、唯一性和业务数量均由后端校验。
- ⬜ 同一文件哈希、外部批次号或幂等键重复提交时阻止重复记账。
- ⬜ 导入不能静默覆盖已有数据；相似数据提示员工选择跳过或单独处理。
- ⬜ 期初库存仅限管理员在正式启用仓库前导入；导入完成生成可对账的期初单和库存流水。
- ⬜ 尚未被业务引用的主数据导入批次可以整批撤销；已经形成库存/业务引用时只能通过冲销或调整纠正。
- ⬜ 每次导入保存文件名、模板版本、批次号、操作人、时间、处理结果和撤销/纠正记录。

## 11. 提醒中心与异常处理

### 11.1 提醒类型

- ⬜ 全部模式：采购交付逾期、待签收、签收数量差异、缺少交付凭证、重复导入和导入失败。
- ⬜ 使用仓库/按订单选择：待收货、待质检、收货差异、冻结库存、批次临期、调拨逾期、盘点差异和待出库。
- ⬜ 港口仓库和第三方仓库：合同/协议临期、外部主要联系人缺失或失效、SLA 临期和服务商停用影响提醒。
- ⬜ 低库存/安全库存提醒仅在公司启用库存能力并为产品配置阈值后出现。
- ⬜ 数量不足、单位不一致、重复单据、跨仓越权等阻止提交的问题使用即时错误，不伪装成普通提醒。
- ⬜ 业务失败必须保持原库存不变，禁止单据成功但流水失败或反之。

### 11.2 提醒行为

- ⬜ 级别分为提示、警告、紧急；颜色和图标统一，红色只用于真正阻断或紧急问题。
- ⬜ 每条提醒绑定业务对象、负责人、截止时间和处理入口，点击直接进入对应单据。
- ⬜ 支持标记已读、确认收到、稍后提醒和完成；完成提醒不等于自动确认业务单据。
- ⬜ 同一业务对象和提醒规则只保留一条活动提醒，状态变化后更新或关闭，防止重复弹窗。
- ⬜ 公司可以配置提前天数、逾期阈值、接收角色和是否发送邮件；第一阶段至少提供站内铃铛、提醒中心和“我的待办”。
- ⬜ “不使用仓库”的公司不出现低库存、库位、盘点等无关提醒；若只是维护港口/第三方交付地点，只出现交付、联系人和凭证类提醒。

## 12. UI 与交互规范

### 12.1 视觉方向

- ⬜ 保持专业、克制、易读：深海军蓝导航、冷灰页面背景、白色内容卡片、青绿色主操作。
- ⬜ 绿色表示完成，橙色表示待处理/轻微风险，红色仅表示错误/紧急；不用大面积高饱和色或装饰性渐变。
- ⬜ 字号、行高、边框、圆角、间距和状态标签复用 ERP 现有设计变量，不为仓储另造一套视觉系统。
- ⬜ 主按钮每个页面原则上只保留一个；次要操作进入“更多”菜单，危险操作与普通操作分开。
- ⬜ 状态不能只靠颜色表达，必须同时有中文/英文文字和必要图标。

### 12.2 仓库工作台

```text
┌ 仓库管理 / 仓库使用模式：按订单选择                       [导入] [新建收货]
├ 待签收 3 ─ 待入库 5 ─ 待质检 2 ─ 异常 1
├ 我的待办（按紧急程度和截止时间）     │ 今日到货 / 出库计划
├ 近期异常与提醒                       │ 常用入口
└ 只显示当前模式真正可用的数据和操作
```

- ⬜ 统计卡可以点击筛选对应列表；没有意义的功能不显示空卡片。
- ⬜ “不使用仓库”工作台突出待到港、待签收、交付差异和凭证，不展示库存价值。
- ⬜ “使用仓库/按订单选择”工作台增加待入库、待质检、待出库、冻结和盘点差异。

### 12.3 列表与详情

- ⬜ “仓库资料”页面左侧按“全部 / 自家仓库 / 港口仓库 / 第三方仓库”分类并显示数量，右侧使用统一列表，不拆成三套页面。
- ⬜ 仓库列表展示编码、名称、类型、地点、库存记账方式、内部主要负责人、外部主要联系人和状态；联系人隐私字段按权限脱敏。
- ⬜ 仓库详情使用“基本资料 / 内部负责人 / 外部联系人 / 仓储能力 / 变更记录”标签页；自家仓库、港口仓库和第三方仓库只在基本资料与仓储能力中显示各自适用字段。
- ⬜ 新建仓库先选择类型，再动态展示该类型需要的字段；类型一旦被业务引用，不允许直接修改，只能停用后新建正确资料。
- ⬜ 列表按收货单、出库单、调拨单等业务单据分组，不把一个单据的每条产品拆成难读的重复行。
- ⬜ 首屏只展示编号、业务对象、仓库/地点、进度、截止时间、状态和主操作；详细数量在展开或详情中查看。
- ⬜ 搜索与筛选位于同一区域，已选筛选可见且可一键重置；分页位置保持一致。
- ⬜ 最右操作列固定，主操作直接显示，下载、取消、历史等放入下拉菜单。
- ⬜ 详情页顶部显示单据编号、状态、来源和关键日期，下方使用“明细 / 进度 / 附件 / 变更记录”标签页。
- ⬜ 数量差异同时显示订单数量、本次数量、累计数量和剩余数量，避免只显示百分比。

### 12.4 导入与提醒 UI

- ⬜ 导入采用四步向导：选择类型、上传预检、确认导入、结果；离开前提示未完成状态。
- ⬜ 预检表格可只看错误/警告，错误单元格就地高亮并提供修复说明。
- ⬜ 提醒中心可按级别、类型、仓库、负责人和状态筛选；每条提醒有明确处理按钮。
- ⬜ 空状态说明“为什么没有数据”和“下一步怎么做”；功能因仓库使用模式关闭时给出管理员配置入口，而不是空白页。
- ⬜ 桌面端内容宽度、表格横向滚动和弹窗高度经过 1366×768 验收；平板端关键操作无需横向拖动。

## 16. 明确不做 / 暂缓

- AI 自动确认收货、出库、盘点差异或库存调整。
- 为每个客户公司复制独立仓库代码或数据库逻辑。
- 自动化立体仓、输送线、机器人、电子秤和 PLC 设备集成。
- 完整运输管理、车队、快递面单和路径优化。
- 复杂波次拣选、交叉转运和劳动力绩效管理。
- 第一阶段实现 FIFO、LIFO、标准成本等多套计价引擎。
- 物理删除已确认的收货、出库、调拨、盘点和库存流水。
- 在仓库模块重复开发采购、合同、船期或财务结算功能。
- 把港口到货自动视为公司库存，或为了没有仓库的公司创建虚假仓库。
- 第一阶段不连接所有第三方仓库 API；先保证人工凭证和库存账准确。
