# 采购履约与自动进度

采购订单“更多操作”中的“查看履约”进入“采购履约”弹窗。采购不再手填生产节点或重复录入质检结果。

## 页面入口

- **交付情况**：供应商反馈、质检结果、交付摘要和运输摘要按业务顺序展示；实际进度每15秒刷新，也可手动刷新。各来源加载失败分别提示。
- **供应商确认**：未确认时提供录入；有记录后默认只读，点击“修改确认”带出上一次保存的数量、单价、日期和备注。去掉数量百分比，避免混淆确认和交货进度。采购要求日期与供应商确认交期分开展示，空交期明确标示“交期待确认”。现有确认规则不变，确认值单独保存，不覆盖原采购数量、单价和要求日期。确认历史可展开查看。
- **跟进记录**：追加沟通和备货说明，保存填写人及时间，不改订单、合同、质检或交货状态。结案、取消或尚未进入履约的订单不能新增备注。
- **历史资料**：在概览底部折叠展示原生产节点、附件、旧质检资料和到货异常记录，页面只读，不迁移、覆盖或删除原数据。
页面仅保留“交付情况”和“跟进记录”两个页签，不再提供到货异常登记或处理入口；已有异常的说明、数量、状态、处理结果及登记/处理人员和时间只读保留。质量问题仍通过正式质检、采购处理及复检流程跟踪。

列表全部操作统一放在“更多操作”中，其中保留“查看履约”；履约阶段不重复显示与当前筛选相同的阶段标签，保留供应商确认状态。历史订单仍可查看履约资料，已结案订单不可修改供应商确认。

## 业务规则

供应商确认与备货跟进后，由采购申请整单质检。未检、待检、质检中、部分合格、不合格、返工处理后尚未复检的货物仍不能实际交货。只有整单最终合格才能交货；预计船期可以提前安排。生产节点和跟进备注不构成质检凭证或交货凭证。

物流页展示的是包含本采购单货物的运输批次进度，不把整份外销合同的所有船期混在一起，也不把批次运输数量当成本采购单已交货数量。

## 接口与权限

- `POST /api/purchase-orders/{id}/follow-ups`：沿用 `procurement:production:write`，采购服务继续校验订单的数据范围。备注追加保存，不提供覆盖或删除入口。
- `GET /api/purchase-orders/{id}/execution`：新增 `followUps`，原 `confirmations`、`milestones`、`inspections` 等字段保留。
- `GET /api/purchase-orders/{id}/logistics-progress`：要求 `procurement:order:read`，先授权采购单，再从其需求解析合同及合同明细，匹配实际分配的物流货物。
- 内部 `GetCargoScheduleProgress` RPC：物流服务再次校验租户、合同、关联船期和货物明细，只返回船期编号、状态和预计/实际时间。采购不会因此获得完整船期、运费、货代合同或附件的读取和编辑权限。
- 原生产节点、旧质检服务接口保留兼容，不再由新履约页面发起录入。

## 部署

先应用采购增量迁移 `00083_order_follow_ups.sql`，再更新采购、物流、网关和前端。新增表不改动原订单及历史节点数据，不需要重建数据库。

## 验证范围

独立单据验证供应商确认保存、备注追加和刷新保留、无权限/空备注拒绝、历史保留、未检与部分合格交货拦截、返工复检后整单交货，以及计划船期、离港、到港和完成的自动展示。数据库集成测试覆盖备注不改变业务事实，以及物流摘要对租户、合同和货物的精确隔离。


## 采购、质检和物流的职责

- 采购订单的“更多操作 → 查看履约”包含“交付情况”和“跟进记录”。供应商反馈保存后默认只读，修改时带出上次记录，不覆盖原采购要求。
- “交付情况 → 质检结果 → 查看结果与报告”展示首检、复检、对应报告、整单附件和采购处理情况。采购可预览和下载报告，按权限记录供应商返工/换货处理，不能录入或修改检验结论。报告通过现有网关文件中转读取，PDF复用项目阅读器。
- 采购履约仅展示实际交付及物流摘要，不再提供交货执行动作或完整船期表。
- 物流“采购交货”展示直发货物的待交货及已交货记录；货代服务采购不属于货物交货任务。整单质检合格且尚未交完的直发单出现在物流“我的待办 → 待交货”。已交完、已结案或尚未合格的单据不进入该待办。
- 先进入仓库的采购单仍在“产品与仓储 → 待到货”页面登记入库，该页面只列仓库入库单，标题明确为“待入库”。直发交货不形成库存，实体仓库入库沿用原库存记账流程。
- 采购状态以同一份交接记录计算。直发按实际交货显示“部分交货 / 已交货”，仓库按实际收货显示“部分入库 / 已入库”；列表统一筛选“部分交付 / 已交付”。建船期、订舱、离港、到港均不增加采购交付数量。

## 实际交接记录

新增迁移 `00084_receipt_delivery_details.sql`，保存实际交接日期、提交标识以及交接凭据。原收货记录与库存事件继续复用，不重建第二套数量流水。旧记录没有补填实际日期时，界面沿用原登记日期展示，不覆盖旧数据。

`ReceiveOrder` 兼容原请求，新增可选 `actual_delivery_date`、`request_key` 和 `proof_files`。同一采购单内相同提交标识与相同内容返回原交接号，数量和库存事件不重复累计；同标识内容变化会被拒绝。新页面每次打开交接表单生成一个提交标识。物流凭据每次最多5份、总计2MB，与交接数量在同一事务中保存。

`GET /api/purchase-orders/{id}/receipt-proofs/{fileId}/download` 沿用采购读取权限及订单数据范围，文件还必须匹配租户和采购单。无新增角色或权限扩大。

部署时先将采购数据库迁移至84，再更新采购、网关及前端；物流服务无需替换。船期提前安排及整单最终质检合格后才可交货的规则不变。
