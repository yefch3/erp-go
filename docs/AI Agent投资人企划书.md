# AI Agent 外贸 ERP 投资人企划书

> 对外沟通版
> 日期：2026-08-28
> 用途：投资人初谈、产品介绍、融资材料底稿
> 说明：本文严格区分“已经具备的产品基础”和“下一阶段规划”，不将规划能力表述为已经上线。市场规模、客户数量、收入、融资金额等商业数据需由管理层确认后补充。

## 一、一句话介绍

我们正在把传统外贸 ERP 升级为一套能够**理解业务、解释问题、准备工作并在授权后完成操作**的 AI Agent ERP。

传统 ERP 要求人学习系统；我们的目标是让系统理解人的意图。

用户可以直接说：

> “把今天收到的客户询盘整理成公司模板，找出尺寸不完整的行，生成待复核任务，但先不要发给工厂。”

系统会读取用户有权访问的邮件和附件，识别产品、规格、数量与贸易要求，展示执行计划和异常项，在用户确认后生成结构化草稿，并把每个结果追溯到原始邮件或文件。

## 二、30 秒投资人版本

外贸企业的大量工作仍然发生在邮件、Excel、PDF、聊天和人工经验中。ERP 虽然保存了结果，却没有解决“人如何理解文件、跨模块找信息、判断下一步和重复录入”的问题。

我们已经建立了一套覆盖询盘、报价、合同、采购、库存、物流、收付款、审批和邮件协作的外贸 ERP，并完成了首个 AI 落点：把复杂邮件附件转换为公司标准询价 Excel，同时通过结构化输出、源数据锚点、行数守恒和人工复核避免漏行与错误入账。

下一阶段，我们将把这套能力扩展成企业级 AI Agent：

- 员工可以直接询问系统如何使用；
- Agent 可以解释一张业务单为什么卡住；
- Agent 可以跨模块汇总一笔订单的真实进度；
- Agent 可以生成报价、询盘、邮件、发票和对账草稿；
- 在权限和人工确认范围内，Agent 可以完成低风险操作；
- 重复任务可以保存为可审计、可暂停、有预算上限的自动化。

我们的差异不是“在 ERP 上加一个聊天框”，而是让 AI 在真实业务权限、数据范围、状态机、审批和财务守卫内工作。

## 三、客户面对的问题

### 3.1 企业买了 ERP，员工仍然在系统外工作

外贸业务天然由非结构化信息驱动：

- 客户询盘来自邮件正文、Excel、PDF、图片和不同语言；
- 工厂报价格式各不相同；
- 合同、采购、库存、物流和收款分散在不同模块；
- 大量知识掌握在老员工经验里；
- 新员工需要反复询问“这个字段是什么意思、下一步去哪里”；
- 管理者想知道“这单卡在哪里”，往往需要问多个部门。

传统 ERP 解决了记录问题，但没有解决理解和执行问题。

### 3.2 现有自动化的两个极端

第一类是固定规则自动化。它可靠，但只适合字段和流程高度确定的任务，无法处理格式混乱的文件、自然语言意图和业务例外。

第二类是通用 AI Agent。它看起来灵活，但如果直接控制页面或数据库，会带来企业无法接受的问题：越权、重复提交、金额错误、过程不可追溯，以及模型误判造成的业务后果。

市场真正需要的是第三种形态：

> **AI 负责理解和规划，ERP 负责权限、规则、审批与最终事实。**

## 四、我们的产品

### 4.1 四层能力

| 层级 | 用户得到什么 | 典型问题 |
|---|---|---|
| Ask：知识助手 | 有引用、易理解的系统说明 | “这个字段是什么意思？” |
| Understand：业务副驾 | 结合当前数据解释状态和异常 | “为什么这张采购单不能提交？” |
| Act：行动 Agent | 展示计划，经授权调用业务工具 | “帮我生成待复核询盘并分配给我。” |
| Automate：自动化 Agent | 按定时、事件或邮件触发重复工作 | “每天汇总三天内到期的事项。” |

### 4.2 产品交互

用户通过全局 AI 面板提出需求。系统不会立刻“黑盒执行”，而是展示：

1. Agent 对任务的理解；
2. 将读取哪些信息；
3. 准备调用哪些业务工具；
4. 哪些步骤只读，哪些会产生业务影响；
5. 哪一步需要确认；
6. 最终成功、失败和未执行的内容；
7. 对应的原始邮件、附件和业务单据。

这使 AI 从一次性回答升级为可管理的企业工作流。

## 五、最容易展示价值的五个场景

### 场景一：客户询盘自动结构化

客户发来一个包含多个子页、不同钢材类型和混合单位的 Excel。

传统方式：业务员逐页阅读、复制、换算、重新录入，容易漏行或混淆厚度、壁厚、宽度、直径和边长。

AI Agent 方式：

- 读取所有工作表；
- 识别每一条需求行；
- 将不同尺寸概念拆分到独立字段；
- 单位统一为标准数字；
- 保留原始描述与来源位置；
- 对歧义和缺失信息单独提示；
- 生成公司模板并进入人工复核。

投资人应看到的不是“AI 能读 Excel”，而是：**AI 输出受行业结构、行数守恒和业务模板约束，结果可以进入下一步流程。**

### 场景二：一问看懂整笔订单

用户问：“合同 CT-2026-xxx 现在到哪一步，最需要谁处理？”

Agent 汇总：

- 客户合同和审批状态；
- 采购需求和采购单；
- 到货和库存；
- 出运和船期；
- 应收和收款；
- 当前异常、逾期和责任角色。

用户不再需要打开五个模块或询问五个部门。

### 场景三：解释为什么不能操作

用户问：“为什么我看得到这张合同，却不能修改？”

Agent 根据当前用户权限、数据范围、单据负责人和审批状态解释原因，并指向正确处理方式，例如负责人转移、补齐字段或等待审批。

这降低培训和内部支持成本，也减少用户用错误操作反复试错。

### 场景四：邮件与报价副驾

Agent 可以：

- 识别邮件属于客户询盘、工厂报价、物流通知还是普通往来；
- 总结长线程；
- 生成中文、英文或西班牙文回复草稿；
- 从工厂报价中预填标准报价字段；
- 标出与询盘不一致的规格和数量。

所有外发邮件默认只生成草稿，用户确认后才发送。

### 场景五：可运营的自动化

用户可以建立自动化：

> “每天上午 9 点，汇总我负责且三天内到期的合同、应收和提单事项；如果发现客户询盘未处理，只生成草稿，不自动发送。”

每个自动化都有所有者、作用范围、预算、工具白名单、运行历史、失败熔断和暂停按钮。它不是一个无限授权的常驻机器人。

## 六、为什么现在能够做

### 6.1 我们不是从聊天 Demo 开始

目前产品已经具备 AI Agent 所需的业务基础：

- 覆盖询盘、报价、合同、采购、库存、船期、收付款、审批和邮件；
- 用户、角色、权限和多层数据范围；
- 正式业务状态机与审批流程；
- 防止重复创建和重复提交的幂等机制；
- 跨服务事件、失败重试和实时提醒；
- 中、英、西三语界面；
- 文件、邮件和结构化 Excel 处理能力。

这些能力决定了 Agent 可以被约束在真实业务系统中，而不是停留在“生成一段文字”。

### 6.2 首个 AI 场景已经验证技术路线

已经具备的 AI 能力包括：

- 服务端调用模型，API key 不进入浏览器；
- 支持邮件正文、图片、PDF、Word、PowerPoint 和 Excel；
- 严格结构化输出；
- 对表格预先计算需求行，防止模型漏行、合并行或重复行；
- 关键字段与源表事实校验；
- 异步任务和结果通知；
- token 用量、失败用量和租户月度额度记录；
- 人工预览后再进入下一业务环节。

这不是完整 Agent 已经上线，而是最重要的技术假设已经被一个真实业务场景验证。

## 七、技术与产品壁垒

### 7.1 行业工作流壁垒

通用模型知道“采购”是什么，但不知道一家外贸企业如何从询盘走到报价、合同、采购、质检、出运、船期和收款，也不知道哪些状态可以改、哪些必须审批、哪些数字不能混算。

我们的产品将这些规则固化为可调用的领域工具和业务守卫。模型负责选择工具，但不能修改规则。

### 7.2 数据结构与追溯壁垒

每个 AI 结果不仅有答案，还应包含：

- 来源邮件、附件、工作表、行或文档章节；
- 原始值、推断值和规则计算值的区别；
- 使用的模型、工具和版本；
- 用户确认记录；
- 最终对应的业务单号。

这种“从原始非结构化信息到正式业务事实”的追溯链，是企业采用 AI 的核心条件。

### 7.3 安全与治理壁垒

Agent 不拥有超级权限。每次调用仍然受：

- 当前用户身份；
- 原业务模块权限；
- 部门与个人数据范围；
- 单据负责人规则；
- 状态机；
- 幂等；
- 人工确认；
- 正式审批流程。

这比单纯使用浏览器自动化更难建设，但也更难被一个通用聊天产品替代。

### 7.4 评测与反馈飞轮

每次人工修改都能转化为“哪里需要改进”的评测样本：

- 是否漏行；
- 字段是否对应错误；
- 是否选择了错误工具；
- 哪一步经常被用户拒绝；
- 哪类文件需要更强模型；
- 哪类问题应该直接拒答。

我们不依赖未经审查的在线自动学习，而是用可复现评测持续改进 prompt、检索、路由和工具定义。

## 八、与其他方案的区别

| 方案 | 优点 | 局限 |
|---|---|---|
| 传统 ERP | 数据结构和权限稳定 | 用户仍需学习系统，大量非结构化工作留在系统外 |
| 通用聊天助手 | 上手快、表达能力强 | 缺少企业状态机、权限、业务工具和最终执行闭环 |
| RPA/浏览器自动化 | 可操作没有 API 的旧系统 | 页面变化脆弱，难处理业务语义与异常，治理成本高 |
| 单点 OCR/文档 AI | 某类文件识别准确 | 只解决录入，不理解跨模块流程和后续动作 |
| 我们的 Agent ERP | 理解非结构化信息，并在 ERP 守卫内完成端到端工作 | 建设更复杂，需要分阶段开放 |

我们的路线不是替代 ERP，而是让 AI 成为 ERP 的自然语言执行层。

## 九、产品路线图

### 第一阶段：AI 知识助手

- 阅读经过发布的产品说明；
- 用用户语言解释功能；
- 每个答案带引用；
- 区分普通员工、管理员和运维文档；
- 建立反馈和评测基线。

**商业意义**：降低培训与客服成本，建立客户每天使用 AI 入口的习惯。

### 第二阶段：业务副驾

- 页面上下文解释；
- 合同、采购、库存、物流、收款跨模块查询；
- 按钮缺失和流程阻塞诊断；
- 管理者风险简报。

**商业意义**：从“如何使用软件”进入“如何处理业务”。

### 第三阶段：业务草稿

- 工厂报价解析；
- 发票 OCR；
- 产品匹配建议；
- 邮件分类、摘要和回复草稿；
- 银行对账格式兜底。

**商业意义**：直接减少高频人工录入和核对时间。

### 第四阶段：行动 Agent

- 自然语言转执行计划；
- 低风险写操作；
- 幂等、人工确认和完整运行记录；
- 部分失败可恢复。

**商业意义**：从 Copilot 进入可量化的工作替代。

### 第五阶段：自动化与外部协作

- 定时、邮件和业务事件触发；
- 个人与部门自动化配方；
- 预算、熔断和权限回收；
- 对无 API 外部系统进行受限 UI Agent 试点。

**商业意义**：形成持续使用和更高客单价模块。

## 十、商业模式建议

### 10.1 收费结构

建议采用“ERP 订阅 + AI 能力包 + 高级自动化”的组合：

1. **基础 ERP 订阅**：按公司规模、用户数或模块收费；
2. **AI 助手包**：包含知识问答和基础业务副驾；
3. **AI 用量包**：文档提取、复杂推理等按次数/token 档位；
4. **自动化包**：按启用的配方数量、运行额度或业务场景收费；
5. **企业私有部署/本地模型**：面向对数据外发敏感的客户；
6. **实施与知识库服务**：客户 SOP、模板、工具和自动化落地。

不建议简单把所有 AI 成本包含在无限使用套餐中。模型调用、文件处理和无人值守自动化都需要租户预算与公平使用策略。

### 10.2 单位经济模型

正式融资材料应补充以下真实数据，而不是使用未经验证的行业平均数：

```text
单租户月收入
- 基础 ERP 订阅
- AI 能力包
- 自动化/实施收入
= ARPA

单租户月变动成本
- 模型 token 与文件工具
- 对象存储与计算
- 邮件/第三方服务
- 客户支持
= COGS

ARPA - COGS = 单租户贡献毛利
```

AI 用量账应按租户、用途和模型统计，才能知道哪些场景真正创造毛利，哪些只是昂贵演示。

## 十一、市场进入策略

### 11.1 从明确痛点切入

第一销售切入口不应该是“我们有 Agent”，而应该是客户可以立即理解的结果：

- 复杂询盘不漏行地转成公司模板；
- 工厂报价自动预填；
- 一句话看懂订单进度；
- 邮件、PDF、Excel 不再重复录入；
- 新员工不需要反复问老员工怎么操作。

### 11.2 从一个行业纵向做深

钢材和外贸业务拥有大量规格、单位、文件、邮件和跨部门流程，是验证 AI Agent ERP 的理想场景。

先把一个行业的尺寸、模板、术语、异常和流程做深，再将底层 Agent、权限、知识库和自动化能力复用到其他外贸品类。这样形成的是“行业深度 + 平台复用”，而不是一开始做一个没有行业壁垒的通用 Agent。

### 11.3 客户扩展路径

```text
询盘结构化
→ 邮件与报价副驾
→ 跨模块业务问答
→ 行动 Agent
→ 部门自动化
→ 企业知识库与私有部署
```

每一步都建立在上一层已经产生的数据、信任和使用习惯上。

## 十二、里程碑与投资人应关注的指标

### 产品指标

- 周活跃 AI 用户占 ERP 活跃用户比例；
- 每位用户每周完成的 AI 任务数；
- 文档答案有帮助率和引用正确率；
- 草稿采用率与人工修改率；
- Agent 计划完成率和人工确认通过率；
- 每项任务平均节省时间；
- 可预数表格漏行率；
- 越权、未确认副作用和重复写入数量，目标均为 0。

### 商业指标

- AI 功能试用到付费转化率；
- 使用 AI 前后的客户留存与席位扩张；
- AI ARPA 和单租户模型成本；
- 每个场景的贡献毛利；
- 部署一个新客户知识库/自动化的平均时间；
- 从单场景扩展到多个 AI 模块的客户比例。

### 建议里程碑

| 里程碑 | 证明什么 |
|---|---|
| M1：知识助手内测 | 引用、权限、成本和反馈机制成立 |
| M2：跨模块只读副驾 | Agent 能在真实业务权限内理解 ERP |
| M3：首个付费草稿场景 | AI 明确减少人工时间，客户愿意付费 |
| M4：低风险行动 Agent | 计划、确认、幂等和审计可用于生产 |
| M5：自动化付费客户 | AI 从使用功能升级为持续业务基础设施 |

## 十三、风险与应对

| 风险 | 应对方式 |
|---|---|
| 模型幻觉 | 有依据才回答、引用原文、低置信拒答、固定评测集 |
| 文档/表格漏行 | 源数据预解析、行数守恒、字段来源、人审 |
| 越权与数据泄漏 | 当前用户身份、原业务权限、数据范围、最小上下文 |
| 错误业务操作 | 风险分级、计划预览、人工确认、领域状态机 |
| 重复写入 | 幂等键、业务唯一约束、运行步骤账 |
| Prompt Injection | 外部内容视为不可信，工具旁路 guardrail 和白名单 |
| 模型成本不可控 | 按模型计价、租户预算、突发限流、自动化独立额度 |
| 对单一模型供应商依赖 | 提供方抽象、端侧模型与 API 模型按用途切换 |
| UI Agent 不稳定 | ERP 内部坚持 API 工具；外部 UI 自动化只做隔离试点 |
| 销售过度承诺 | 对外明确“已具备、开发中、规划中”三种状态 |

### 已经具备

- 权限、数据范围、审批、幂等和业务状态守卫；
- 邮件及多格式附件处理；
- 询盘 Excel 的 AI 结构化能力；

- 中、英、西三语产品。

### 下一阶段准备建设

- 公共模型、成本、配额与评测体系。

## 十六、建议的投资人演示流程

整场演示控制在 8–10 分钟：

1. **1 分钟：痛点**——展示一封复杂询盘和多个工作表；
2. **2 分钟：现有能力**——生成详细尺寸模板，证明不漏行、可追溯；
3. **2 分钟：知识助手原型**——询问字段、流程和按钮为什么不可用；
4. **2 分钟：Agent 目标效果**——展示执行计划、确认点和运行时间线设计；
5. **1 分钟：订单全景**——一句话解释合同卡点；
6. **1 分钟：壁垒**——权限、状态机、来源、评测，不是聊天壳；
7. **1 分钟：商业化与里程碑**。

演示必须明显标注：

- 绿色：当前产品已经具备；
- 蓝色：正在建设；
- 灰色：路线图规划。

不要用静态原型冒充真实已执行的业务动作。

## 十七、12 页融资 Deck 建议结构

1. 封面：AI Agent 外贸 ERP；

4. 产品演示：复杂询盘结构化；
5. 产品演示：跨模块订单全景与阻塞诊断；
6. 为什么我们能做：现有 ERP、业务守卫和首个 AI 场景；
7. 技术与数据壁垒：领域工具、权限、追溯、评测；
8. 市场与切入行业：用真实数据补充；
9. 商业模式：ERP + AI + 自动化 + 私有部署；
10. 路线图与里程碑；
11. 团队与执行能力：由管理层补充；
12. 融资需求与资金用途：由管理层补充。

## 十八、结束语

传统 ERP 的核心问题已经从“有没有系统”变成“人能不能高效地使用系统完成工作”。

大模型让软件第一次可以理解人的意图和非结构化信息，但企业真正愿意付费的不是一个会聊天的模型，而是一个：

- 知道业务事实在哪里；
- 理解谁有权做什么；
- 能解释为什么；
- 能在授权后完成工作；
- 做完之后可以核对和追责；
- 成本与风险都有上限的 AI Agent。

我们的机会，是把 AI 从 ERP 的附加功能，变成外贸企业新的工作入口。
