# 主邮箱（公司邮箱）

2026-09-16 定的口径。三步落地，这份文档随每一步更新。

## 是什么

到今天为止，每个邮箱都**属于某个人**：绑的时候永远绑给登录的那个人，请求里连
「绑给谁」这一项都没有。

主邮箱是另一种东西：**公司的资产，员工只是暂时拿着用。** `sales01@公司` 这种。

| | 个人邮箱 | 主邮箱 |
|---|---|---|
| 归谁 | 员工自己 | 公司 |
| 谁来绑 | 员工自己输密码 | **管理员**输密码，当场连一次邮件服务器验证 |
| 员工能否改密码 / 解绑 | 能 | **不能**（界面不显示，服务端也拒） |
| 进 ERP 后 | 进邮件模块时输一次邮箱密码解锁 | **自动开着**，不问密码 |
| 员工离职 | 问一句：保留还是删 | **管理员收回，分给下一个人**；历史邮件跟着邮箱走 |
| 一个人几个 | 随意 | **同时只有一个**，可以换 |

## 已经定下的四条

1. **换人时历史跟邮箱走。** A 用了半年交给 B，B 看到全部——邮箱是公司的，
   里面的客户往来是公司的资产。
2. **主邮箱登录即开，个人邮箱照旧过门。** 锁是一个邮箱一把（`UnlockStore`），
   所以登录时只发主邮箱那一把；个人邮箱要用时还是输一次密码。
3. **一对一。** 一个人同时只有一个主邮箱，一个主邮箱同时只归一个人。
   账号必须绑一个主邮箱；离职自动收回；可以换。
4. **已有员工不硬卡。** 给管理员一个「还没配主邮箱的员工」清单慢慢补。

## 第一步（已做）：分配、员工端限制、登录即开

### 数据

`mail_accounts.kind`：`PERSONAL`（存量全是）/ `COMPANY`。部分唯一索引保证一个人
同时最多一个 `COMPANY` 且 `unbound_at IS NULL` 的行。

`mail_binding_log.actor_id`：谁动的手。员工自己操作时和 `employee_id` 是同一个
人；管理员替员工分配时是管理员。新增两个动作：`ASSIGN`（分配）、`REPLACE`
（换主邮箱时收回旧的那一条）。

迁移：`services/mail/db/migrations/00067_company_mailbox.sql`。

### 接口

| 路由 | 权限 | 做什么 |
|---|---|---|
| `POST /api/employees/{id}/company-mailbox` | `iam:employee:write` | 管理员替员工分配：地址 + 密码 + 服务商。先问 IAM 这个人在不在本公司，再拿密码去邮件服务器真的登录一次，成功才存。已有一个不同地址的主邮箱 → 旧的收回、新的分上 |
| `GET /api/employees/{id}/company-mailbox` | `iam:employee:read` | 他现在配的是哪个（地址、验证时间、密码是否失效） |
| `POST /api/mailbox/unlock-company` | `mail:email:read` | 登录的这个人有主邮箱的话，发它那一把开锁令牌。不问密码。只发这一个箱的 |

**这是有意开的第二条进邮箱凭据存储的路。** 员工自己那条（`/api/mailbox/verify`）
的规矩「绑的永远是自己、请求体里没有绑给谁」原样不动，`routes_test.go` 和
`throttle_test.go` 里的钉子测试照旧。新路只放行「管理员工账号」的权限——能开
账号、重置密码的人，就能配主邮箱，不另造一种权限。

### 员工那边

- 左栏主邮箱带「主邮箱」标记，悬停说明「由管理员管理」；**没有「解绑」按钮**
- 进邮件模块：锁着就先向服务器要主邮箱那一把（`tryUnlockCompanyMailbox`），
  有就直接进；没有主邮箱的照旧过门
- 切到主邮箱而手里没它的令牌（比如刚清过浏览器存储）：先要一把再决定关不关门
- 服务端再拒一道：员工对主邮箱地址重填授权码 → `MAIL_COMPANY_MAILBOX_MANAGED`；
  员工解绑主邮箱 → 同一个码。界面只是提示，不是边界

### 管理员那边

员工详情页 →「账号与角色」→「主邮箱」一行：现在配的是哪个 + 「配置 / 更换」。
表单和员工自己绑邮箱的是**同一个组件**（`MailboxCredentialsForm`，`submit-to`
换成替员工分配那条路）。

### 密码失效了怎么办

主邮箱的密码被改了、被服务商锁了：`needs_reauth` 为真。这时**登录即开不给令牌**
（`MAIL_COMPANY_MAILBOX_REAUTH`「主邮箱当前登录不上，请联系管理员重新设置密码」），
员工详情页上那一行标红。要管理员重新填一次密码——员工自己填不了。

### 测试

- `companymailbox_integration_test.go`：分配后归属 / kind / 默认 / 留痕；员工解绑
  和改密码都被拒且箱原样；别人拿不走这个地址；换主邮箱旧的收回新的分上、个人
  箱不受影响、留痕条数对；员工自己绑的那条路一个字没变
- `routes_test.go`：三条新路由都注册了

## 第二步（待做）：交接、离职自动收回

- 管理员「收回」：员工立刻失去访问，历史留在邮箱里
- 「分给 B」：**历史整体转移**——一个事务里把这个邮箱名下的邮件、会话、草稿
  的归属从 A 改成 B，记一笔交接
- 挂在 IAM「标记离职」上：标记成功的同时收回主邮箱、清掉他手上的登录
  （`deactivateEmployee` 已经在收登录态，收主邮箱放同一处）
- 离职清单上提醒管理员：去服务商后台改一次密码，把新密码填回 ERP——换人就换锁
