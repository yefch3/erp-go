# 独立补录物流实单

- 入口：物流 → 实单 → 建立物流实单。使用现有 `shipping:schedule:write` 权限。
- 物流实单有独立编号；留空生成 `LO-########`，同一租户不允许重复。外销合同号只是手填的待关联参考，不要求系统存在合同。
- 可先只填写合同参考号并保存，稍后在详情的“补齐资料”中编辑客户简称、港口、货代、承运方、费用、日期及货物。
- 费用未填写与零费用分开记录。填写产品行时必须有产品名称、正数数量和单位，空白行由界面跳过。
- 保存仅创建物流草稿，不发布合同事件、不生成付款或船期。进入审批后锁定补录资料；被退回后可以补齐再提交。
- 后续办理沿用原有完整性校验、审批、合同核验、付款流程。本次没有补录历史付款或历史审批结果。
- `manual_shipping_orders` 保存补录标识、独立编号、创建人和时间；所有读取和写入使用服务端租户上下文。货代及承运方的目录 ID 经网关按当前公司校验。
- `contract_id` 保持 0。内部 `contract_version_id=-handoff_id` 和负数货物引用用于避免与正常合同流转任务的唯一键冲突，不代表真实外销合同或明细。
- 合同号支持搜索选择销售合同。保存时可按正式合同号或原始外部合同号精确匹配，只有唯一匹配才建立关联；无匹配或存在歧义时保持待关联。
- 已有补录单可在详情点击“关联合同”，选择或匹配后确认。单号使用销售合同的正式 `contract_no`，原手填号保存在 `original_contract_no`。关联使用同租户的 `linked_contract_id`，保存关联人和时间；不改动独立物流身份、审批状态或产生流转事件。
- 已关联的合同不允许通过补齐资料被覆盖或换成另一份合同。有销售合同查看权限的用户可从详情跳转查看。
- `/shipping/contract-options` 只返回当前公司合同 ID、合同号、原合同号，不返回销售价格、客户资料或文件。销售服务独立验证物流权限。

验证：物流独立建单、编辑、未知合同号、重复单号、同号跨租户、跨租户读取与编辑拒绝、费用未填、明细校验、审批后锁定；并回归正常合同版本校验。
