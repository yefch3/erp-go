## 一、阻塞业务的

不做，用户就得退回 Excel 或手工——也就是这套系统在这一段没有替代掉任何东西。

### A1 ✅ 采购订单与采购需求的数据范围（2026-08-22 全部完成）

**订单半边（2026-08-21）**：`order_scope.go`，模块 `procurement_order`，
按 `buyer_id` 围栏：列表 SQL 过滤 + 全部按单寻址的 RPC 在 grpcin 加闸，
越权一律答「不存在」。供应商发票同模块围栏（按录入人）。角色页
「采购订单可见范围」旋钮；iam 00037 种子。

**需求半边（2026-08-22，属主决策拍板后收尾）**：业务定的归属规则——
**合同拆出的需求归合同负责人，手工需求归创建人；采购单归实际执行的
采购员，订单明细上保留合同负责人**（换人下单不丢谈单人）。实现：
`ContractEffective` 事件带上 `sales_employee_id/sales_employee`，需求生而继承；
模块 `procurement_requirement` 围栏（列表过滤 + 详情/关闭/重开/覆盖订单/
模板导出按单加闸）；`owner_id=0` 的历史行只有「全部」范围可见
（fail-closed）；角色页新增「采购需求可见范围」旋钮，iam 00041 种子。

> **上线两步（一次性）**：① 跑 `scripts/backfill-requirement-owners.sh`
> 从 export 合同表补齐存量属主；② 管理员在角色页把**采购类角色**的
> 需求范围开到「全部」——待采购池子是工作队列，按人切会把活干断；
> 销售角色保持「仅本人」，只看自己客户的采购动向。

### A2 ✅ 工厂报价横向比较（2026-08-22 核验后收尾完成）

**核验修正**：原文写的六条缺口里有三条是**过时信息**——P5/P6 询价工作流
（PR #108 之后的几期）早已建成：版本化报价（`version_no` 自增，比较页只用
最新版）、按产品分组的横向比较（价格/交期/MOQ/付款条件/有效期/最低价标记，
`ListSupplierQuoteComparison`）、成本方案逐行选不同工厂报价（含完整性校验）。
又一个「做完了没更新状态」的案例，和 B2 同病。

**真实缺口三条，2026-08-22 一并补完**：
- 导入错误不带行号 → 逐行报 Excel 行号与原因，一次报全
  （`SC_QUOTE_ROWS_INVALID`）
- 跨币种没法比价（最低价只在同币种内比）→ 比较行带账本币换算价
  （读取时现算、不落库；汇率不可得则该列留空，前端退回同币种排序）
- 中标无原因、不进历史 → 确认成本方案必填原因
  （`SC_COST_REASON_REQUIRED`），操作人/时间/原因写入
  `cost_scenarios.confirm_reason` 与案件变更记录（COST/CONFIRMED）

### A3 ✅ 质检记录（2026-08-22 完成）

质检表 `purchase_inspections` 挂收货单：结果（合格/不合格）、抽检与
不合格数量、附件、处置（退货/扣款/让步接收/返工 + 备注）。合格生而
已处置；不合格开着等处置决定。收货—质检—入库的关系定为：收货即入
码头库（现状不变），质检事后登记，不合格不改库存——处置是人的决定，
记录供扣款与纠纷取证。

**结案闭环**：结案做成 `closed_at` 列而非新状态（状态机 RECEIVED 封顶，
对账/工作台按状态过滤处一概不用改）。三道闸：全部收满、无未解决到货
异常、无未解决质检；拒绝时带两类未决数量。权限单独一码
`procurement:order:close`（iam 00040，种子只给 SUPER_ADMIN）。
前端：执行跟踪新增质检页签，列表 RECEIVED 单主动作变「结案」，
结案后亮绿色标签。

### A4 ✅ 供应商应付对账（2026-08-22 全线上线，状态回写补记）

P1–P6 加银行流水 CSV 已全部建成并上线：供应商发票（三单匹配、
EXCEPTION 亮警）、付款与核销（append-only、冲销为负行、状态派生）、
预付与押金、对账视图（五组数字并排 + 逐笔流水滚动余额）、多币种汇率
快照与汇兑损益、银行对账单导入与付款匹配。本条早已完成但状态一直
没回写——又一个「做完了没更新状态」，2026-08-22 补记。

## 二、明显提升效率的

有替代做法，但很痛。

### B1 ✅ 成本方案闭环（2026-08-22 核验后收尾完成）

**核验修正**：三条缺口里一条半是过时信息——「已生成客户报价」状态
（`CUSTOMER_QUOTE_CREATED`）早就存在；「拒绝后建新版」机械上也早就通
（`CreateCostScenario` 允许在该状态下再建方案，确认时自动 SUPERSEDE 旧版）。
真断的是**信息回路**，2026-08-22 补完：

- 报价单拒绝时记录客户原话（`quotations.respond_note`，选填——客户
  没说就留空），列表展示
- 案件页看得见被拒：最新报价单被拒时，成本方案区顶部亮横幅（带客户
  原话），引导基于反馈建新一版——采购员不用自己想起来去翻报价单页
- 成本构成分区展示：方案详情拆出产品成本 / 附加费用（含明细表）/
  落地成本 / 利润 / 客户报价，不再只有一个总数

### B2 ✅ 船期的数据范围与操作记录（核验后发现早已建成）

**2026-08-21 核验修正**：原文「与 A1 同一个病，船期这边也没治」是**过时
信息**。实际上船期这边机制完整且在用：`services/shipping/internal/app/access.go`
（模块 `shipping`，负责人 + 客户负责人双维度），`authorizeSchedule` 有
14 处调用覆盖详情/编辑/取消/路线/单证/提醒，列表与统计走 `visibleTo`
过滤，范围种子在 iam 迁移 00016；变更记录 `addChange` 有 19 处调用。
本条不再是待办。

### B3 ✅ 船公司/货代主数据（2026-08-22 核验后收尾完成）

**核验修正**：这条的过时程度是三兄弟里最重的——「手工文字」早已不是现状。
主数据就是**供应商**（B4 供应商管理把业务类型做成了多选：船公司/承运人、
国际货代、报关、仓储……同一家可兼多角色 ✓，编码/名称/国家/联系人/状态/
变更历史全在 ✓）；船期表单早已是下拉选择并存 `carrier_id` + 名称快照
（停用后历史保留 ✓，迁移 00004 的注释写明了快照设计）；网关也早在校验
「启用的供应商」。

**真缺三针，2026-08-22 缝上**：下拉不过滤（钢厂和停用的都混在候选里）
→ 只列启用的 CARRIER/FORWARDER 并集；网关不透传 `business_type` → 透传；
服务端不验角色（选一家钢厂当船公司也放行）→ 业务类型必须含
CARRIER/FORWARDER（`SHIPPING_CARRIER_ROLE`）。**按船公司统计延误率的
地基自此打通**（carrier_id 可聚合），报表本身另立条目再做。

### B4 ✅ 采购工作台收口（2026-08-22 完成）

五条缺口全部补齐：订单指标拆成「待审批 / 待正式发单」两个行动数字
（待发单走 ListOrders 新增的 `unsent` 过滤，沿用列表自己的数据范围围栏）；
指标点进去落在筛好的列表上（订单页接收 `?status=`/`?unsent=1`）；
今日重点补上逾期 RFQ（新 RPC `ListOverdueFactoryRfqs`，按询价案件属主
围栏）、待审批订单、待确认成本方案三源；按紧急程度 + 截止日期排序
（逾期的最上）；重点卡头部显示分来源数量。

### B5 ✅ 采购订单列表收口（2026-08-22 完成，尾巴同日缝上）

列表只留「详情 + 当前主动作」（草稿→提交、批完→发单、发完→收货、
收完→结案，按状态推导），其余动作收进「更多」下拉；状态列增加发单
子标签（已发单/未发单/发送失败），审批状态与发单状态从此分开可见。

**两个尾巴已缝**：状态列在已发单之后再挂工厂回签子标签（待工厂确认/
工厂已确认/差异审批中/确认被驳回，取最新一条回签，列表 SQL 一个子查询
带出）；详情页顶部加「下一步」条，与列表主动作同一套推导，点了直接
落进对应弹窗——看完单子不用回列表找按钮。

## 三、建议顺序与理由

1. **A1 + B2 一起做** —— 同一套数据范围机制，分两次做是浪费。
   工作量最小、消除的风险最大，且属于安全问题。
2. **A2 工厂报价比较** —— 采购员日常最痛的那一刀，且是 B1 的前提。
3. **A3 → A4** —— 质检与对账是一条链，连着做，顺序不能反。
4. **B1 成本方案闭环** —— 等 A2 落地后自然接上。
5. **B4 + B5 工作台与列表收口** —— 前面几件做完，工作台的数字才有意义。
6. **B3 船公司主数据** —— 独立，可以插空做。
