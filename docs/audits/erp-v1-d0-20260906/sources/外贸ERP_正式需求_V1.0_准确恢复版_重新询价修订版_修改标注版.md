# 销售模块

## 页面 1：客户询盘

### 一、页面用途

客户询盘用于记录客户需要采购的产品和交货要求，并将询价需求同时发送给采购和物流。

### 二、操作人员

主要操作人员：

1. 负责该询盘的销售。

可以查看的人员：

1. 负责该询盘的销售；
2. 该销售的上级；
3. 老板。

其他普通销售不能查看这条询盘。

### 三、数据来源

客户询盘可以通过以下两种方式创建：

1. 销售收到客户邮件后，将邮件转为客户询盘；
2. 销售手动新建客户询盘。

哪个销售收到邮件或创建询盘，哪个销售就是该询盘的负责人。

### 四、页面内容

客户询盘主要包括：

1. 询盘编号；
2. 客户；
3. 联系人；
6. 产品；
7. 规格；
8. 数量；
9. 单位；
10. 交货要求；
11. 装货港；
12. 目的港；
13. 备注；

采购报价和货代报价的详细内容统一在“客户报价”页面查看。

### 五、提交询价

销售检查并补充客户需求，确认无误后，点击“提交询价”。

提交后：

1. 产品询价自动发送给所有采购人员；
2. 货代询价自动发送给所有物流人员；
3. 不需要指定采购员；
4. 不需要指定物流员；
5. 不需要领导审批；
6. 所有采购人员都可以添加采购报价；
7. 所有物流人员都可以添加货代报价。

### 六、页面操作

未提交时：

1. 保存；
2. 编辑；
3. 提交询价。

询价中时：

1. 撤回询价。

已撤回时：

1. 编辑；
2. 重新提交询价。

### 七、撤回询价

负责该询盘的销售可以在“更多操作”中点击“撤回询价”。

只有在客户尚未确认报价时，才允许撤回询价。

点击后，系统提示：

“确定撤回吗？采购和物流已经填写的报价将被清除，重新提交后需要重新报价。”

销售确认撤回后：

1. 询盘立即从所有采购人员的当前询价列表中消失；
2. 询盘立即从所有物流人员的当前询价列表中消失；
3. 采购和物流不能继续添加报价；
4. 原采购报价和货代报价全部清除；
5. 不需要填写撤回原因；
6. 不需要向用户显示操作记录；
7. 销售可以修改客户询盘。

客户已经确认报价后，不允许再撤回询盘。

合同已经产生后，只能从合同业务继续处理，不能通过撤回询盘反向清除已经形成的历史报价、合同或后续实单。

### 八、重新提交

销售修改完成后，点击“重新提交询价”。

重新提交后：

1. 产品询价重新发送给所有采购人员；
2. 货代询价重新发送给所有物流人员；
3. 采购和物流根据修改后的内容重新报价；
4. 新报价不继承之前已经清除的报价。

如果重新提交后仍然发现错误，销售可以再次撤回、修改和重新提交。

### 九、页面状态

客户询盘只保留三个状态：

未提交 → 询价中 → 已撤回

已撤回的询盘重新提交后，状态变回“询价中”。

### 十、操作结果

销售提交客户询盘后：

1. 采购模块自动收到产品询价；
2. 物流模块自动收到货代询价；
3. 销售的“客户报价”页面自动出现这条询盘；
4. 销售可以等待并查看采购和物流提交的报价。

### 十一、与采购和物流的交互

1. 销售负责填写并提交客户需求；
2. 采购人员在采购模块填写采购报价；
3. 物流人员在物流模块填写货代报价；
4. 采购和物流不在销售模块中填写报价；
5. 采购报价提交后，自动显示在销售的“客户报价”页面；
6. 货代报价提交后，自动显示在销售的“客户报价”页面；
7. 销售可以查看报价，但不能修改采购或物流填写的报价；
8. 销售撤回询盘后，采购和物流中的对应询价立即消失，原报价同时清除；
9. 销售重新提交后，采购和物流重新收到询价并重新报价。

### 十二、完整流程

客户邮件或手动创建  
→ 建立客户询盘  
→ 创建询盘的销售自动成为负责人  
→ 销售检查并补充客户需求  
→ 提交询价  
→ 所有采购人员收到产品询价  
→ 所有物流人员收到货代询价  
→ 采购和物流分别报价  
→ 报价提交后自动进入“客户报价”页面  
→ 销售查看并使用报价

如果询盘有错误：

销售撤回询价  
→ 采购和物流中的询价消失  
→ 原采购报价和货代报价清除  
→ 销售修改询盘  
→ 重新提交  
→ 采购和物流重新报价


# 销售模块

## 页面 2：客户报价

### 一、页面用途

客户报价页面用于接收采购提交的工厂报价和物流提交的货代报价，并由销售计算最终提供给客户的报价。

这里的“客户报价”是公司最终给客户的报价。

### 二、操作人员

主要操作人员：

1. 负责该询盘的销售。

可以查看的人员：

1. 负责该询盘的销售；
2. 该销售的上级；
3. 老板。

采购和物流人员不能查看销售最终给客户的报价。

### 三、数据来源

销售提交客户询盘后，该询盘自动进入“客户报价”页面。

系统自动带入：

1. 询盘编号；
2. 客户；
3. 产品；
4. 规格；
5. 数量和单位；
6. 交货要求；
7. 装货港和目的港；
8. 采购模块提交的工厂报价；
9. 物流模块提交的货代报价。

销售不需要点击“生成客户报价”，也不需要重复录入客户询盘中的内容。

### 四、页面内容

客户报价页面只保留三个主要部分：

1. 工厂报价；
2. 货代报价；
3. 给客户的报价。

### 五、工厂报价

采购人员在采购模块向工厂询价，并将完整的工厂报价提交到客户报价页面。

采购提交后，负责销售立即可以看到。

工厂报价主要显示：

1. 产品；
2. 工厂或供应商；
3. 规格；
4. 报价；
5. 币种；
6. 有效期；
7. 采购人员；
8. 提交时间；
9. 贸易条件。

同一个询盘可以有多家工厂报价。

销售可以为不同产品选择不同工厂的报价；一家工厂可以覆盖一个、多个或全部产品。

销售只能查看和选择，不能添加、删除或修改工厂报价。

### 六、货代报价

物流人员在物流模块向货代询价，并将完整的货代报价提交到客户报价页面。

物流提交后，负责销售立即可以看到。

货代报价可以包括：

1. 货代公司；
2. 海运费；
3. 港杂费；
4. 内陆运输费；
5. 其他运输费用；
6. 币种；
7. 物流人员；
8. 提交时间；
9. 贸易条件。

同一个询盘可以有多家货代公司的报价，同一家货代也可以提供不同运输方案。

销售可以基于采购和物流提交的报价生成给客户的报价 PDF。

生成客户报价 PDF 时，不要求一定只选择一个运输方案，可以在同一份 PDF 中放入多个运输方案供客户选择。

销售只能查看和使用物流报价，不能添加、删除或修改货代报价。

### 七、给客户的报价

销售根据采购报价和物流报价，再选择公司预先设置好的报价公式。

系统根据选择的数据自动计算给客户的报价。

系统自动带入：

1. 客户；
2. 产品；
3. 规格；
4. 数量；
5. 单位；
6. 装货港；
7. 目的港。

给客户的报价主要包括：

1. 产品；
2. 规格；
3. 数量和单位；
4. 报价公式；
5. 销售单价；
6. 总金额；
7. 币种；
8. 交货条件；
9. 报价有效期；
10. 备注。

报价公式属于公司内部计算内容，不需要给客户看，也不显示在导出的客户报价 PDF 中。

原文中的“FOR价格”为笔误，统一更正为“FOB价格”。

系统计算完成后，销售可以根据实际情况手动修改最终报价。

### 八、报价公式

系统可以预先导入公司常用的报价公式。

当前确认的报价公式如下：

1. CFR 价格 = FOB RMB ÷（实时汇率 - 0.05）+ 海运费 + 资金利息费 5 USD/MT ÷ 30天 × 天数；
2. CFR 价格 = FOB USD 价格 + 海运费 + 资金利息费 5 USD/MT ÷ 30天 × 天数；
3. CFR 价格 =（工厂出厂价 + 内陆运费 + 港区港杂费）RMB ÷（实时汇率 - 0.05）+ 海运费 + 资金利息费 5 USD/MT ÷ 30天 × 天数；
4. CFR 价格 =（工厂出厂价 + 分条费 + 短导费 + 内陆运费 + 港区港杂费）RMB ÷（实时汇率 - 0.05）+ 海运费 + 资金利息费 5 USD/MT ÷ 30天 × 天数；
5. FOB 价格 =（工厂出厂价 + 分条费 + 短导费 + 内陆运费 + 港区港杂费）RMB ÷（实时汇率 - 0.05）+ 资金利息费 5 USD/MT ÷ 30天 × 天数。

报价公式可以使用：

1. 工厂报价；
2. 海运费；
3. 港杂费；
4. 内陆运输费；
5. 其他运输费用；
6. 汇率；
7. 税费；
8. 利润；
9. 按吨费用；
10. 工厂加工费用；
11. 备注。

汇率使用财务“汇率”子模块中人工审核并确认后的有效汇率。

所有最终金额统一四舍五入保留两位小数。

禁止通过正常登记形成超收或超付。

多币种业务需要形成单一总额时，统一使用该业务的默认结算币种。

退款通过原收付款记录的反向冲销处理，不作为超收或超付。

销售使用报价公式时：

1. 选择工厂报价；
2. 选择一个或多个货代报价或运输方案；
3. 选择报价公式；
4. 点击“计算报价”；
5. 检查计算结果；
6. 根据需要调整最终价格；
7. 保存给客户的报价；
8. 根据需要生成客户报价 PDF。

报价公式只用于帮助销售快速计算，不限制销售修改最终价格。

### 九、页面操作

客户报价页面只保留以下操作：

1. 选择工厂报价；
2. 选择一个或多个货代报价或运输方案；
3. 选择报价公式；
4. 计算报价；
5. 保存；
6. 编辑；
7. 导出报价单；
8. 客户已确认。

不需要以下操作：

1. 生成客户报价；
2. 工厂询价；
3. 货代询价；
4. 添加工厂报价；
5. 添加货代报价；
6. 询价完成；
7. 报价汇总；
8. 成本确认；
9. 领导审批。

### 十、保存和修改

销售可以随时保存给客户的报价。

客户要求调整价格或其他条件时，销售直接编辑原报价，然后重新导出报价单。

客户确认前：

1. 可以继续修改；
2. 不需要撤回；
3. 不需要重新创建报价；
4. 不需要重新审批。
5.最终解释权在销售上

### 十一、客户确认

客户接受报价后，负责销售点击“客户已确认”。

系统自动进入“外销合同”，并带入：

1. 客户；
2. 产品；
3. 规格；
4. 数量和单位；
5. 客户确认的价格；
6. 币种；
7. 贸易条件；
8. 装货港和目的港；
9. 其他已经填写的报价信息。
10.合同号 
11.合同日期

销售只需要检查并补充合同内容，不需要重复录入。

### 十二、页面状态

客户报价只保留三个状态：

待报价 → 已报价 → 客户已确认

待报价：

销售还没有保存给客户的报价。

已报价：

销售已经保存给客户的报价，但客户还没有确认。

客户已确认：

客户已经接受报价，可以进入外销合同。

### 十三、与采购模块的交互

1. 销售提交客户询盘后，采购模块收到产品询价；
2. 采购人员在采购模块向工厂询价；
3. 采购人员在采购模块填写和提交工厂报价；
4. 工厂报价提交后，自动显示在客户报价页面；
5. 销售只能查看和选择工厂报价；
6. 工厂报价需要修改时，由采购人员在采购模块修改后重新提交；
7. 销售不能在客户报价页面代替采购询价或修改工厂报价。

### 十四、与物流模块的交互

1. 销售提交客户询盘后，物流模块收到货代询价；
2. 物流人员在物流模块向货代询价；
3. 物流人员在物流模块填写和提交货代报价；
4. 货代报价提交后，自动显示在客户报价页面；
5. 销售只能查看和选择货代报价；
6. 货代报价需要修改时，由物流人员在物流模块修改后重新提交；
7. 销售不能在客户报价页面代替物流询价或修改货代报价。

### 十五、询盘撤回时的处理

销售撤回客户询盘后：

1. 对应的工厂报价从客户报价页面清除；
2. 对应的货代报价从客户报价页面清除；
3. 已经计算但尚未确认的客户报价同时清除；
4. 采购和物流不能继续提交报价；
5. 销售修改客户询盘后重新提交；
6. 采购和物流根据新内容重新询价和报价。

### 十六、与外销合同的交互

客户确认报价后：

1. 销售点击“客户已确认”；
2. 系统自动创建或打开对应的外销合同；
3. 客户报价中的主要信息自动带入合同；
4. 销售检查并补充合同内容；
5. 不需要重新录入已经存在的数据；
6. 客户确认报价和创建外销合同本身不需要领导审批；新合同签字前仍需要按照外销合同页面的规则进行一次上级确认。

### 十七、完整流程

销售提交客户询盘  
→ 采购模块收到产品询价  
→ 物流模块收到货代询价  
→ 采购向工厂询价  
→ 采购提交工厂报价  
→ 物流向货代询价  
→ 物流提交货代报价  
→ 工厂报价和货代报价自动进入客户报价页面  
→ 销售选择工厂报价  
→ 销售选择货代报价  
→ 销售选择报价公式  
→ 系统计算给客户的报价  
→ 销售检查或调整最终价格  
→ 保存并导出报价单  
→ 客户要求修改时直接编辑  
→ 客户接受后点击“客户已确认”  
→ 自动进入外销合同


# 销售模块

## 页面 3：外销合同

### 一、页面用途

外销合同页面用于查看和管理公司的所有客户合同。

进入页面后，首先显示合同列表，不直接打开合同填写页面。

### 二、操作人员

主要操作人员：

1. 负责该合同的销售；
2. 该销售的上级；
3. 老板。

查看权限：

1. 负责销售可以查看和处理自己的合同；
2. 该销售的上级可以查看合同并进行确认；
3. 老板可以查看全部合同；
4. 其他普通销售不能查看不属于自己的合同。

### 三、合同列表

进入“外销合同”页面后，默认显示当前账号权限范围内的全部合同记录。

合同列表主要显示：

1. 系统合同号；
2. 原合同号；
3. 客户；
4. 合同金额；
5. 币种；
6. 负责销售；
7. 合同状态；
8. 更新时间；
9. 操作。

系统合同号由系统自动生成，始终存在。

对应采购订单号与销售系统合同号保持一致。

原合同号用于填写纸质合同、客户合同或外部合同编号。没有原合同号时可以留空，列表中显示“—”，以后可以通过编辑补充。

### 四、查询合同

合同列表只保留简单的查询条件：

1. 搜索合同号或客户；
2. 合同状态；
3. 负责销售；
4. 查询。

不增加过多筛选条件。

### 五、列表操作

页面右上角只保留一个手工录入入口：

1. 录入执行中合同。

正常的新合同不在这里手工新建。

每条合同根据当前状态显示相应操作。

待上级确认或待签字：

1. 继续处理。

执行中或已完成：

1. 查看。

用户也可以点击合同号进入合同详情。

### 六、合同来源

外销合同只保留两种来源：

1. 由客户报价进入；
2. 录入执行中合同。

正常的新合同不允许手工创建。

### 七、由客户报价进入

客户接受销售报价后，销售在“客户报价”页面点击“客户已确认”。

系统自动建立外销合同，并带入：

1. 客户；
2. 产品；
3. 规格；
4. 数量和单位；
5. 客户确认的价格；
6. 合同总金额；
7. 币种；
8. 贸易条件；
9. 装货港和目的港；
10. 其他已经填写的信息。

销售只需要检查并补充缺少的合同内容。

### 八、正常新合同的创建方式

正常新合同不允许手工创建。

客户接受销售报价后，销售在“客户报价”页面点击“客户已确认”，系统自动建立外销合同。

历史上已经签署并开始执行的合同，通过“录入执行中合同”录入。

### 九、录入执行中合同

“录入执行中合同”用于录入公司使用系统以前已经签署并开始执行的历史合同。

这类合同不需要重新补走以前的审批和签字流程。

录入时主要填写：

1. 原合同号；
2. 客户；
3. 负责销售；
4. 合同日期；
5. 产品和合同金额；
6. 当前执行情况；
7. 已完成数量；
8. 未完成数量；
9. 已收款金额；
10. 未收款金额；
11. 已签署合同附件；
12. 备注。

保存后直接进入“执行中”。

系统只继续处理合同尚未完成的部分。

### 十、合同内容

合同详情主要分为三个区域：

（一）基本信息

1. 系统合同号；
2. 原合同号；
3. 客户和联系人；
4. 负责销售；
5. 签订日期；
6. 生效日期；
7. 交货日期；

9. 付款方式；
10. 贸易条件；
11. 装货港；
12. 目的港。

（二）合同明细

1. 产品；
2. 规格；
3. 数量；
4. 单位；
5. 单价；
6. 金额；
7. 合同总金额；
8. 币种。

产品可以从产品库中选择，也可以直接手动输入，不强制提前建立产品资料。

（三）合同文件与补充信息

1. 合同条款；
2. 合同附件；
3. 已签署合同；
4. 备注。

### 十一、新合同的上级确认

新合同签字前必须经过上级负责人同意。

销售填写并检查合同后，点击“提交上级确认”。

上级负责人收到合同后，只保留两个操作：

1. 同意；
2. 退回修改。

上级同意后：

1. 合同进入“待签字”；
2. 销售可以安排双方签字；
3. 签字完成后上传已签署合同；
4. 销售点击“开始执行”。

上级退回后：

1. 合同返回负责销售；
2. 销售直接修改原合同；
3. 修改完成后重新提交确认；
4. 不需要重新建立合同。

### 十二、合同签字

只有上级负责人同意后，合同才能进入签字阶段。

签字完成后，销售上传双方签署的合同文件。

上传完成后，销售点击“开始执行”。

合同正式进入采购、物流和财务的后续工作。

### 十三、页面操作

新合同填写时：

1. 保存；
2. 编辑；
3. 提交上级确认。

等待上级确认时：

1. 查看；
2. 上级同意；
3. 上级退回修改。

待签字时：

1. 查看；
2. 上传签署合同；
3. 开始执行。

执行中时：

1. 查看详情；
2. 编辑可以补充的信息；
3. 查看执行进度；
4. 完成合同。

已完成时：

1. 查看详情。

录入执行中合同时：

1. 保存并继续执行；
2. 取消。

### 十四、合同状态

合同列表只显示四个主要状态：

待上级确认 → 待签字 → 执行中 → 已完成

录入执行中合同保存后，直接进入“执行中”。

### 十五、与采购模块的交互

新合同签字并开始执行后：

1. 系统将需要采购的产品信息发送到采购模块；
2. 采购人员继续建立和执行采购订单；
3. 销售可以查看采购进度，但不能修改采购人员的业务数据。

录入执行中合同时：

1. 系统不重新发起已经完成的采购流程；
2. 只将尚未完成的采购内容发送到采购模块；
3. 已经存在的负责采购人员可以继续负责后续工作。

### 十六、与物流模块的交互

新合同签字并开始执行后：

1. 系统将需要运输的合同信息发送到物流模块；
2. 物流人员继续安排运输、发货和船运工作；
3. 销售可以查看物流进度，但不能修改物流人员的业务数据。

录入执行中合同时：

1. 系统不重新发起已经完成的物流流程；
2. 只继续处理尚未完成的运输内容。

### 十七、与财务模块的交互

合同开始执行后：

1. 合同应收信息自动进入财务“入账”；
2. 财务可以看到系统合同号和原合同号；
3. 财务按照实际收款情况登记客户收款；
4. 销售不需要查看具体的已收金额、未收金额或收款明细；
5. 财务确认已经收到客户预付款、收到信用证、合同约定不需要预付款，或特殊情况允许执行后，采购和物流才进入正式实单流程。

录入执行中合同时：

1. 已收款金额作为历史数据录入；
2. 未收款金额继续进入财务“入账”；
3. 不重复登记已经完成的收款。

# 采购模块

## 页面 1：采购询价

### 一、页面用途

采购询价页面用于接收销售提交的产品需求，并记录采购人员向不同工厂或供应商取得的报价。

采购人员进入采购模块后，系统直接显示销售提交的全部有效询价。

不设置额外的采购工作台或中间页面。

### 二、操作人员

所有采购人员都可以：

1. 查看销售提交的全部有效询价；
2. 查看客户需要的产品；
3. 向一家或多家工厂询价；
4. 添加工厂报价；
5. 提交自己的工厂报价；
6. 查看其他采购人员已经提交的报价。

不需要提前指定采购员，也不需要领导分配询价任务。

### 三、数据来源

销售在“客户询盘”页面点击“提交询价”后，产品需求自动进入采购模块。

系统自动带入：

1. 询盘编号；
2. 负责销售；
3. 产品；
4. 规格；
5. 数量；
6. 单位；
7. 交货要求；
8. 装货港；
9. 目的港；
10. 客户附件；
11. 备注；
12. 提交时间。

采购不需要重新录入客户询盘中已经存在的信息。

### 四、询价列表

采购模块只保留两个同级页面：

1. 采购询价；
2. 采购订单。

采购人员进入采购模块后，默认显示采购询价列表。

询价列表主要显示：

1. 询盘编号；
2. 产品数量；
3. 总需求数量；
4. 交货要求；
5. 负责销售；
6. 已收到的工厂报价数量；
7. 报价状态；
8. 提交时间；
9. 操作。

列表只保留简单的查询条件：

1. 搜索询盘编号、客户或产品；
2. 全部报价状态；
3. 查询。

没有工厂报价时，操作显示“去报价”。

已经有工厂报价时，操作显示“查看并报价”。

### 五、一条询盘包含多个产品

一条客户询盘可以包含一个或多个产品。

询盘详情中的产品明细需要分别显示：

1. 产品；
2. 规格；
3. 数量；
4. 单位；
5. 交货要求；
6. 备注。

产品和规格必须分开显示，不能放在同一列。

例如：

产品：热轧钢卷  
规格：2.0 × 1250 mm  
数量：100  
单位：TON

同一条询盘中可以同时包含热轧钢卷、镀锌钢卷、彩涂钢卷和其他产品。

### 六、查看询盘详情

采购点击“去报价”或“查看并报价”后，进入询盘详情。

询盘详情主要显示：

1. 询盘编号；
2. 客户；
3. 负责销售；
4. 交货要求；
5. 装货港；
6. 目的港；
7. 客户附件；
8. 产品明细；
9. 已经提交的工厂报价。

询盘详情只用于查看客户需求和已有报价。

采购点击“添加工厂报价”后，进入工厂报价填写界面。

### 七、多家工厂报价

同一个询盘可以添加多家工厂或供应商的报价。

同一个采购人员可以添加：

1. 工厂 A 的报价；
2. 工厂 B 的报价；
3. 工厂 C 的报价。

其他采购人员也可以继续添加他们取得的工厂报价。

不限制一个采购人员只能提交一家工厂，也不限制一条询盘只能有一家工厂报价。

每家工厂对应一张独立的工厂报价。

### 八、一家工厂可以报价部分产品

一家工厂可以对询盘中的全部产品报价，也可以只对部分产品报价。

采购建立工厂报价时：

1. 先选择或输入工厂；
2. 系统自动列出询盘中的全部产品；
3. 采购勾选该工厂可以提供的产品；
4. 在对应产品后填写工厂单价和交货日期；
5. 不能提供的产品不勾选，也不需要填写价格。

一家工厂的报价可以覆盖一个、多个或全部产品。

### 九、工厂报价填写界面

工厂报价填写界面采用全宽表格，不使用狭窄的右侧填写栏。

页面顶部填写一次：

1. 工厂或供应商；
2. 币种；
3. 统一的预计交货日期；
4. 更多信息。

工厂或供应商可以从已有数据中选择，也可以直接手动输入。

“更多信息”默认收起，需要时再填写：

1. 报价有效期；
2. 付款方式；
3. 报价附件；
4. 备注。

### 十、产品报价表

产品报价表主要显示：

1. 选择；
2. 产品；
3. 规格；
4. 需求数量；
5. 单位；
6. 工厂单价；
7. 交货日期；
8. 备注。

产品和规格分别使用独立列。

采购直接在每个产品所在行填写工厂单价和交货日期，不需要再次录入产品信息。

如果所有产品使用相同的交货日期，可以在页面顶部统一填写。

如果不同产品的交货日期不同，可以在产品所在行单独修改。

### 十一、大量产品的处理

当一条询盘包含几十或几百个产品时，页面结构保持不变。

产品报价表提供：

1. 搜索产品或规格；
2. 查看全部产品；
3. 只看未报价产品；
4. 只看已报价产品；
5. 每页显示20、50或100条；
6. 产品分页；
7. 报价进度；
8. 从 Excel 粘贴价格。

报价进度显示：

已报价数量 / 产品总数量

例如：

已报价 86 / 126 项

采购可以从 Excel 复制价格并批量粘贴到报价表中，不需要逐条输入大量产品价格。

### 十二、保存和提交

工厂报价填写完成后，采购可以选择：

1. 保存；
2. 提交报价。

保存：

1. 当前填写内容保存在采购模块；
2. 未正式提交前，只有填写报价的采购人员可以继续编辑；
3. 销售暂时看不到这条报价；
4. 不设置“草稿”状态。

提交报价：

1. 报价正式提交；
2. 负责销售立即可以在“客户报价”页面看到；
3. 系统记录报价人和提交时间；
4. 采购可以继续添加其他工厂报价。

### 十三、已提交的工厂报价

询盘详情中显示已经提交的工厂报价。

每条工厂报价主要显示：

1. 工厂或供应商；
2. 已报价产品数量；
3. 产品总数量；
4. 币种；
5. 预计交货日期；
6. 报价有效期；
7. 报价人；
8. 提交时间；
9. 操作。

报价覆盖情况可以显示为：

3 / 3 项  
2 / 3 项  
1 / 3 项

所有采购人员可以查看已经提交的工厂报价。

### 十四、修改报价

未提交的报价可以由填写人继续编辑、保存或提交。

已经提交的报价如果需要修改，采购部门其他有权限的采购人员也可以继续处理和修改。

修改保存后，销售“客户报价”页面中的报价同步更新。

系统记录实际修改人和修改时间。

### 十五、页面操作

采购询价列表：

1. 去报价；
2. 查看并报价。

询盘详情：

1. 查看客户需求；
2. 查看已有工厂报价；
3. 添加工厂报价；
4. 返回询价列表。

工厂报价填写：

1. 选择或输入工厂；
2. 搜索产品或规格；
3. 筛选未报价或已报价产品；
4. 从 Excel 粘贴价格；
5. 保存；
6. 提交报价；
7. 返回询盘详情。

不需要：

1. 领取询价；
2. 指定采购员；
3. 转交采购员；
4. 领导审批；
5. 询价完成；
6. 报价汇总；
7. 关闭询价。

### 十六、页面状态

询价只保留两个状态：

待报价：

当前还没有任何采购人员提交工厂报价。

已有报价：

已经有至少一家工厂的报价提交给销售。

“已有报价”不代表询价结束。

其他采购人员仍然可以继续添加工厂报价。

工厂报价不设置“草稿”状态。首次点击“提交报价”后视为正式提交。

### 十七、销售撤回询价

销售发现客户询盘有错误并撤回询价后：

1. 对应询价立即从所有采购人员的当前询价列表中消失；
2. 采购人员不能继续添加或提交报价；
3. 未提交的工厂报价清除；
4. 已提交的工厂报价清除；
5. 销售的“客户报价”页面不再显示这些工厂报价；
6. 不需要填写处理原因；
7. 不向普通用户显示操作记录。

销售修改客户询盘并重新提交后：

1. 询价重新进入所有采购人员的采购询价列表；
2. 采购人员根据修改后的需求重新询价；
3. 原工厂报价不自动恢复；
4. 采购人员重新添加和提交报价。

### 十八、与销售模块的交互

1. 销售提交客户询盘；
2. 产品需求自动进入采购询价列表；
3. 所有采购人员都可以查看；
4. 采购人员在线下向一家或多家工厂询价；
5. 采购人员在系统中添加工厂报价；
6. 一家工厂可以报价一个、多个或全部产品；
7. 采购点击“提交报价”；
8. 工厂报价自动进入销售的“客户报价”页面；
9. 负责销售立即可以看到；
10. 销售可以为不同产品选择不同工厂的报价；
11. 销售不能修改采购提交的工厂报价。

### 十九、与采购订单的交互

采购询价页面只负责询价和提交工厂报价，不在这里建立采购订单。

# 采购模块

## 页面 2：采购订单

### 一、页面用途

采购订单页面用于处理已经签订外销合同，并且已经具备正式采购条件的真实订单。

这里不是前期用于计算客户报价的采购询价，而是客户合同签订后的实单采购。


> **【本次修改 M03】以下为本次新增或调整内容：采购模块 / 页面 2：采购订单 / 一、页面用途。**

正式与工厂签订采购合同前，采购需要重新向工厂询价，可以继续使用原工厂，也可以更换工厂，最终确定供货工厂、采购价格、交货时间和付款条件。

### 二、进入采购订单的条件

销售与客户签订外销合同后，还不能直接要求采购签订采购合同。

外销合同已经经过上级确认、双方签字、上传签署合同并由销售点击“开始执行”后，合同先进入财务“入账”。

财务确认以下任意一种情况后，采购订单正式进入采购模块：

1. 财务确认已经收到客户预付款；
2. 财务确认已经收到信用证；
3. 客户合同约定不需要预付款；
4. 其他特殊情况经过确认，可以开始采购。


> **【本次修改 M04】以下为本次新增或调整内容：采购模块 / 页面 2：采购订单 / 二、进入采购订单的条件。**

条件满足后，相关采购需求自动进入“采购订单”页面的待确认工厂报价环节。采购先重新询价并确定最终工厂，再按最终工厂生成对应采购订单；不按售前工厂提前锁定正式订单。

### 三、数据来源

采购订单的数据来自已经签署并且具备采购条件的外销合同。

系统自动带入：

1. 外销合同号；
2. 原合同号；
3. 客户；
4. 产品；
5. 规格；
6. 数量；
7. 单位；
8. 客户要求的交货时间；

> **【本次修改 M05】以下为本次新增或调整内容：采购模块 / 页面 2：采购订单 / 三、数据来源。**

9. 售前销售选择的工厂及报价（仅作重新询价参考）；
10. 负责销售；
11. 客户预付款、信用证或允许采购的确认情况；
12. 相关附件；
13. 备注。

采购不需要重新录入外销合同中已经存在的信息。

### 四、按工厂生成采购订单

一份外销合同可以包含多个产品，也可以使用多家不同工厂。


> **【本次修改 M06】以下为本次新增或调整内容：采购模块 / 页面 2：采购订单 / 四、按工厂生成采购订单。**

重新询价完成并确定每个产品的最终供货工厂后，系统按照最终工厂自动拆分采购订单。

属于同一家工厂的产品，可以放在同一张采购订单中。

属于不同工厂的产品，分别生成不同的采购订单。

采购订单号与对应的销售系统合同号保持完全一致。

例如：

外销合同 CT-001 中：

1. 产品A由工厂甲供应，对应采购订单号为 CT-001；
2. 产品B和产品C由工厂乙供应，对应采购订单号为 CT-001；
3. 产品D由工厂丙供应，对应采购订单号为 CT-001。

6. 谁完成本次工厂报价确认并提交，系统记录谁是本次经办人；
7. 本次经办人只代表完成了这次操作，不代表成为整份合同的固定负责人；
8. 提交后，采购部门其他有权限的采购人员仍可以继续处理。

采购订单只需要一次上级确认，不设置多层审批。

1. 同意；
2. 退回修改。

1. 采购订单进入“待签采购合同”；
2. 经办采购可以与工厂签署采购合同。

上级退回后：

1. 采购订单返回“待确认工厂报价”；
2. 采购修改价格或采购条件；
3. 修改完成后重新提交；
4. 不需要重新建立采购订单。

### 十四、签署采购合同

采购合同主要包括：

12. 交货日期；
13. 质量要求；
14. 其他采购条款。

采购合同签字前必须经过采购上级确认。

双方签字后，采购将签署完成的采购合同上传系统。

签署后的采购合同由财务上级或老板进行核验。

核验通过后，采购订单进入“待付款”。

### 十五、提交财务付款

7. 预付款比例；
8. 付款日期；
9. 工厂收款账户；
10. 已签署采购合同；
11. 其他付款附件；
12. 备注；
13. 申请付款的采购人员。

采购不需要在财务模块重复建立付款信息。

### 十六、财务付款

财务收到付款申请后：

1. 查看采购合同和付款信息；

3. 登记实际付款金额；
4. 登记实际付款日期；

是否需要先付款以及满足什么付款条件后可以执行，以采购合同约定为准。

满足采购合同约定的执行条件后，采购订单进入正式执行阶段。

采购继续跟踪工厂生产、备货、交货和验货。

# 物流模块

## 页面 1：物流询价

### 一、页面用途

物流询价页面用于接收销售提交的运输需求，并记录物流人员向不同货代公司取得的报价。

物流人员进入物流模块后，系统直接显示销售提交的全部有效询价。

不设置额外的物流工作台或中间页面。

### 二、操作人员

所有物流人员都可以：

1. 查看销售提交的全部有效物流询价；
2. 查看客户的产品和运输要求；
3. 向一家或多家货代公司询价；
4. 添加货代报价；
5. 提交自己的货代报价；
6. 查看其他物流人员已经提交的报价。

不需要提前指定物流人员，也不需要领导分配询价任务。

### 三、数据来源

销售在“客户询盘”页面点击“提交询价”后，运输需求自动进入物流模块。

系统自动带入：

1. 询盘编号；
2. 客户；
3. 负责销售；
4. 产品；
5. 规格；
6. 数量；
7. 单位；
8. 重量；
9. 体积；
10. 包装方式；
11. 贸易条件；
12. 交货要求；
13. 装货港；
14. 目的港；
15. 客户附件；
16. 备注；
17. 提交时间。

物流不需要重新录入客户询盘中已经存在的信息。

### 四、物流询价列表

物流人员进入物流模块后，首页直接显示物流询价列表。

询价列表主要显示：

1. 询盘编号；
2. 客户；
3. 产品数量；
4. 总重量或总体积；
5. 装货港；
6. 目的港；
7. 贸易条件；
8. 交货要求；
9. 已收到的货代报价数量；
10. 报价状态；
11. 负责销售；
12. 提交时间；

1. 搜索询盘编号、客户或产品；
2. 全部报价状态；
3. 查询。

没有货代报价时，操作显示“去报价”。

已经有货代报价时，操作显示“查看并报价”。

### 五、一条询盘可以包含多个产品

一条客户询盘可以包含一个或多个产品。

询盘详情中的产品明细需要分别显示：

1. 产品；
2. 规格；

4. 单位；

6. 体积；
7. 包装方式；

### 六、查看询盘详情

询盘详情主要显示：

1. 询盘编号；
2. 客户；

4. 贸易条件；
5. 交货要求；
6. 装货港；
7. 目的港；
8. 产品明细；

10. 包装方式；

13. 已经提交的货代报价。

物流点击“添加货代报价”后，进入货代报价填写界面。

### 七、多家货代报价

同一条物流询价可以添加多家货代公司的报价。

同一个物流人员可以添加：

1. 货代A的报价；
2. 货代B的报价；
3. 货代C的报价。

其他物流人员也可以继续添加他们取得的货代报价。

不限制一个物流人员只能提交一家货代，也不限制一条询价只能有一家货代报价。

每家货代的每个运输方案对应一张独立报价。

同一家货代如果提供了不同航线、船期或运输方案，可以分别添加多张报价。

3. 目的港；

9. 航程；
10. 币种；
11. 报价有效期；
12. 报价附件；
13. 备注。

4. 计费单位；

8. 其他运输费用。

不需要的费用可以不填写。

系统根据费用明细自动计算该货代方案的费用合计。

### 十、多种币种

一张货代报价可以包含不同币种的费用。

例如：

1. 海运费使用 USD；
2. 港杂费使用 CNY；
3. 内陆运输费使用 CNY。

系统分别显示各币种的费用合计。

没有选择汇率时，不强制把所有费用转换成同一种币种。

### 十一、货物数量较多时的处理

当询盘包含几十或几百个产品时，产品明细使用全宽表格。

产品明细提供：

1. 搜索产品；
2. 搜索规格；
3. 每页显示20、50或100条；
4. 产品分页；
5. 查看总重量；
6. 查看总体积；
7. 查看包装数量。

物流不需要针对每个产品重复填写海运费或港杂费。

货代报价默认按照整批货物和运输方案填写。

如果部分产品需要分开运输，可以另外添加一张运输方案。

### 十二、保存和提交

货代报价填写完成后，物流可以选择：

1. 保存；
2. 提交报价。

保存：

1. 当前填写内容保存在物流模块；
2. 未正式提交前，只有填写报价的物流人员可以继续编辑；
3. 销售暂时看不到这条报价；
4. 不设置“草稿”状态。

提交报价：

1. 报价正式提交；
2. 负责销售立即可以在“客户报价”页面看到；
3. 系统记录报价人和提交时间；
4. 物流可以继续添加其他货代报价。

### 十三、已提交的货代报价

询盘详情中显示已经提交的货代报价。

每条货代报价主要显示：

1. 货代公司；
2. 装货港；
3. 目的港；
4. 船公司；
5. 航线；
6. 预计开船日期；
7. 预计到港日期；
8. 航程；
9. 费用合计；
10. 币种；
11. 报价有效期；
12. 报价人；
13. 提交时间；
14. 操作。

所有物流人员可以查看已经提交的货代报价。

### 十四、修改货代报价

未提交的货代报价可以由填写人继续编辑、保存或提交。

已经提交的货代报价如果需要修改，物流部门其他有权限的物流人员也可以继续处理和修改。

修改保存后，销售“客户报价”页面中的货代报价同步更新。

系统记录实际修改人和修改时间。

### 十五、页面操作

物流询价列表：

1. 去报价；
2. 查看并报价。

询盘详情：

1. 查看客户需求；
2. 查看产品和运输信息；
3. 查看已有货代报价；
4. 添加货代报价；
5. 返回询价列表。

货代报价填写：

1. 选择或输入货代公司；
2. 填写运输方案；
3. 添加费用明细；
4. 保存；
5. 提交报价；
6. 返回询盘详情。

不需要：

1. 领取询价；
2. 指定物流人员；
3. 转交物流人员；
4. 领导审批；
5. 询价完成；
6. 报价汇总；
7. 关闭询价。

### 十六、页面状态

物流询价只保留两个状态：

待报价：

当前还没有任何物流人员提交货代报价。

已有报价：

已经有至少一家货代公司的报价提交给销售。

“已有报价”不代表询价结束。

其他物流人员仍然可以继续添加货代报价。

货代报价不设置“草稿”状态。首次点击“提交报价”后视为正式提交。

### 十七、销售撤回询价

销售发现客户询盘有错误并撤回询价后：

1. 对应询价立即从所有物流人员的当前询价列表中消失；
2. 物流人员不能继续添加或提交报价；
3. 未提交的货代报价清除；
4. 已提交的货代报价清除；
5. 销售的“客户报价”页面不再显示这些货代报价；
6. 不需要填写处理原因；
7. 不向普通用户显示操作记录。

销售修改客户询盘并重新提交后：

1. 询价重新进入所有物流人员的物流询价列表；
2. 物流人员根据修改后的需求重新询价；
3. 原货代报价不自动恢复；
4. 物流人员重新添加和提交报价。

### 十八、与销售模块的交互

1. 销售提交客户询盘；
2. 运输需求自动进入物流询价列表；
3. 所有物流人员都可以查看；
4. 物流人员在线下向一家或多家货代公司询价；
5. 物流人员在系统中添加货代报价；
6. 一家货代可以提供一个或多个运输方案；
7. 物流点击“提交报价”；
8. 货代报价自动进入销售的“客户报价”页面；
9. 负责销售立即可以看到；
10. 销售可以选择合适的货代报价计算给客户的报价；
11. 销售不能修改物流提交的货代报价。

### 十九、与物流执行的交互

物流询价页面只负责询价和提交货代报价，不在这里建立正式运输任务。


> **【本次修改 M13】以下为本次新增或调整内容：物流模块 / 页面 1：物流询价 / 十九、与物流执行的交互。**

客户确认报价、外销合同经过上级确认、双方签字并开始执行后，系统带入售前货代报价作为参考；财务确认执行条件后，物流重新询价，可更换货代或实际承运船公司，再确定最终运输条件。

物流执行的建立条件、操作、状态和与采购的交互，在“页面 2：物流执行”中单独确定。

# 物流模块

## 页面 2：正式船期管理

### 一、页面用途

正式船期管理用于处理外销合同签署后的正式运输工作。

这个页面负责：

1. 再次向货代确认最终费用和船期；
2. 提交物流上级确认；
3. 与货代签署合同；
4. 向财务申请付款；
5. 跟踪订舱、进仓、报关、开船和到港；
6. 在船期提前或延后时提醒相关人员。

### 二、页面结构

物流模块只保留两个主要页面：

1. 物流询价；
2. 正式船期管理。

正式船期管理内部只保留两个界面：

1. 正式船期任务列表；
2. 正式船期任务详情。

重新确认货代、上级确认、签署合同、申请付款、订舱、开船和到港等操作，都在同一个船期详情中完成。

不再为每个环节建立单独的子页面。

### 三、进入正式船期管理的条件

销售与客户签署外销合同后，还不能直接开始正式运输。

外销合同已经经过上级确认、双方签字、上传签署合同并由销售点击“开始执行”后，合同先进入财务“入账”。

财务确认以下任意一种情况后，系统自动建立正式船期任务：

1. 财务确认已经收到客户预付款；
2. 财务确认已经收到信用证；
3. 客户合同约定不需要预付款；
4. 其他特殊情况经过确认，可以开始执行。

条件满足后，系统自动将运输任务显示在“正式船期管理”页面。

### 四、数据来源

正式船期任务的数据来自已经签署并且具备执行条件的外销合同。

系统自动带入：

1. 外销合同号；
2. 原合同号；
3. 客户；
4. 产品；
5. 规格；
6. 数量；
7. 单位；
8. 重量；
9. 体积；
10. 包装方式；
11. 贸易条件；
12. 装货港；
13. 目的港；
14. 客户要求的交货时间；

> **【本次修改 M14】以下为本次新增或调整内容：物流模块 / 页面 2：正式船期管理 / 四、数据来源。**

15. 售前销售选择的货代及运输方案（仅作重新询价参考）；
16. 采购预计备货时间；
17. 负责销售；
18. 相关附件；
19. 备注。

物流不需要重新录入外销合同中已经存在的信息。

### 五、正式船期任务列表

物流人员进入“正式船期管理”后，首先看到全部正式船期任务。

任务列表只显示最重要的信息：

1. 船运任务号；
2. 外销合同号；
3. 客户；
4. 装货港和目的港；
5. 货代公司；
6. ETD；
7. ETA；
8. 当前状态；
9. 船期提醒；
10. 本次经办人；
11. 更新时间；
12. 操作。

列表只保留简单的查询条件：

1. 搜索船运任务号、外销合同号、客户或货代；
2. 船期状态；
3. 查询。

当前需要处理的任务显示“继续处理”。

已经进入运输或已经完成的任务显示“查看”。

### 六、船期任务详情

点击“继续处理”或“查看”后，进入船期任务详情。

详情顶部显示当前进度：

确认货代  
→ 上级确认  
→ 签署合同  
→ 付款  
→ 订舱  
→ 开船  
→ 到港

详情内容只分为五个区域：

1. 货物信息；
2. 货代费用和船期；
3. 合同与付款；
4. 运输进度；
5. 附件。

系统自动展开当前需要处理的区域。

已经完成的内容默认收起，需要查看时再展开。

页面始终只突出一个当前主要操作。

### 七、不自动指定物流负责人

系统不把前期提交货代报价的物流人员自动设置为正式船期任务负责人。

正式船期任务采用以下规则：

1. 所有物流人员都可以查看全部正式船期任务；
2. 所有物流人员都可以处理待确认货代的任务；
3. 不需要提前领取任务；
4. 不需要领导分配任务；
5. 不设置整份外销合同的固定物流负责人；
6. 谁完成本次货代确认并提交，系统记录谁是本次经办人；
7. 本次经办人只代表完成了这次操作，不代表成为整份合同的固定负责人；
8. 提交后，物流部门其他有权限的物流人员仍可以继续处理。

### 八、再次确认货代报价

由于客户付款、信用证和采购生产可能需要一定时间，前期货代报价和船期可能已经失效。

物流需要确认：

2. 最终海运费；

4. 内陆运输费；
5. 拖车费；
6. 报关费；
7. 文件费；
8. 保险费；
9. 其他运输费用；
10. 船公司；
11. 航线；
12. 可订船期；
13. ETD；
14. ETA；
15. 航程；
16. 报价有效期；
17. 付款方式；
18. 其他运输条件。

如果继续使用原货代及运输方案，且重新询价确认原报价和船期仍然有效，物流可以确认使用；更换货代、船公司或方案时，必须重新确认对应费用和运输条件。

如果货代提供了新的报价或船期，物流填写最终确认的费用和船期。

系统不需要计算价格上涨或下降，也不需要显示价格变化。

### 九、运输费用

运输费用使用简单的费用明细表。

费用明细包括：

1. 费用名称；
2. 金额；
3. 币种；
4. 计费单位；
5. 数量；
6. 小计；
7. 备注。

常用费用包括：

1. 海运费；

3. 内陆运输费；
4. 拖车费；
5. 报关费；
6. 文件费；
7. 保险费；
8. 其他运输费用。

不需要的费用可以不填写。

系统按照币种分别计算费用合计，不强制将不同币种转换成同一种币种。

### 十、保存和提交

物流确认货代报价和船期时，可以选择：

1. 保存；
2. 提交上级确认。

保存后：

1. 当前填写内容暂时保存；
2. 物流可以稍后继续处理；
3. 任务保持“待确认货代”。

提交上级确认后：

1. 最终货代费用和船期确认完成；
2. 任务进入“待上级确认”；
3. 系统记录本次提交人为本次经办人；
4. 物流上级收到确认任务。

### 十一、物流上级确认

物流上级可以看到：

1. 外销合同号；
2. 船运任务号；
3. 客户；
4. 产品和货物数量；
5. 总重量和总体积；
6. 装货港和目的港；
7. 货代公司；
8. 船公司和航线；
9. 最终运输费用；
10. 各币种费用合计；
11. ETD；
12. ETA；
13. 航程；
14. 付款方式；
15. 需要支付的预付款；
16. 报价附件；
17. 备注；
18. 本次经办人。

正式船期任务只需要一次上级确认，不设置多层审批。

物流上级只保留两个操作：

1. 同意；
2. 退回修改。

5. 系统自动展开需要修改的区域；
6. 物流直接修改原来的费用、船期或合同条件；
7. 修改完成后重新提交上级确认。

### 十二、签署货代合同

物流上级同意后，物流与货代确认并签署合同。

5. 航线；
6. 装货港；
7. 目的港；
8. 货物信息；
9. 最终费用；
10. 币种；
11. 付款方式；
12. 预付款金额或比例；
13. ETD；
14. ETA；
15. 其他运输条款。

货代合同签字前必须经过物流上级确认。

双方签字后，物流上传签署完成的货代合同。

签署后的货代合同由财务上级或老板进行核验。

核验通过后，任务进入“待付款”。

### 十三、向财务申请付款

货代合同上传并核验通过、任务进入“待付款”后，物流点击“申请付款”。

付款申请包括：

1. 外销合同号；
2. 船运任务号；
3. 货代合同号；

5. 运输费用明细；
6. 各币种费用合计；
7. 合同总金额；
8. 本次申请付款金额；
9. 预付款比例；
10. 付款日期；
11. 货代收款账户；
12. 已签署货代合同；
13. 其他付款附件；
14. 备注；
15. 申请付款的物流人员。

物流不需要在财务模块重复建立付款信息。

### 十四、财务付款

财务收到付款申请后：

1. 查看货代合同和付款信息；
2. 按照合同安排预付款或其他付款；
3. 登记实际付款金额；
4. 登记实际付款日期；
5. 上传付款凭证。

财务完成付款后，物流可以在船期任务中看到付款情况。

如果货代合同允许先订舱后付款，物流可以按照合同条件先继续订舱。

### 十五、正式船期执行

正式船期信息包括：

2. 外销合同号；
3. 货代公司；
4. 船公司；
5. 船名；
6. 航次；
7. 装货港；
8. 目的港；
9. 订舱号；
10. 提单号；
11. 预计备货日期；
12. 实际备货日期；
13. 进仓日期；
14. 报关日期；

### 十六、多个运输批次

一份外销合同可以分成一个或多个运输批次。

如果全部产品使用同一条船、同一时间发运，可以放在同一个船运任务中。

如果产品需要分批发运，系统分别建立多个船运任务。

每个船运任务独立记录：

1. 本次运输的产品；
2. 本次运输数量；
3. 货代；
4. 船公司；
5. 船名和航次；
6. ETD；
7. ETA；
8. 费用；
9. 当前状态。

一份外销合同可以对应多个船运任务。

### 十七、与采购模块的交互

正式船期管理需要显示采购提供的备货信息：

1. 采购订单号；
2. 工厂；
3. 产品；
4. 规格；
5. 数量；
6. 预计备货日期；
7. 实际备货日期；
8. 已完成数量；
9. 未完成数量；
10. 验货情况。

采购更新备货时间后，船期任务中的备货信息自动更新。

物流只能查看采购提供的备货信息，不能修改采购数据。

如果采购分批完成产品，物流可以按照实际备货情况建立多个运输批次。

### 十八、船期提前提醒财务

系统保存每次更新前的ETA。

当最新ETA早于原ETA时，系统自动识别船期提前。

系统立即提醒财务：

1. 船运任务号；
2. 外销合同号；
3. 客户；
4. 原ETA；
5. 最新ETA；
6. 提前天数；
7. 当前待付款金额；
8. 相关合同和付款信息。

如果最新ETA临近周末或节假日，提醒标记为“紧急”。

提醒直接显示在：

1. 正式船期任务列表；
2. 船期任务详情顶部；
3. 财务对应的出账记录。

财务完成资金准备后，点击“已准备”。

物流只显示财务“已准备”的处理结果。

实际付款完成后，对应提醒自动结束。

如果货物已经提前到港但财务仍未处理，系统再次提醒财务。

这样可以避免遇到周末、节假日或银行休息时间无法及时取款和转账。

### 十九、船期延后提醒采购

这里需要区分船舶开航前和开航后。

如果船舶还没有开航，ETD或进仓日期发生延后：

1. 系统立即提醒采购；
2. 提醒采购通知相关工厂暂缓发货；
3. 提醒中显示采购订单号；
4. 显示相关工厂；
5. 显示原ETD；
6. 显示最新ETD；
7. 显示延后天数；
8. 显示新的进仓时间。

采购通知工厂后，点击“已通知工厂”。

物流确定新的进仓和开船时间后，采购再安排工厂发货。

如果船舶已经开航，只是ETA延后：

1. 系统更新最新ETA；
2. 不再提醒采购停止工厂发货；
3. 在船期任务和销售查看页面显示延误提醒。


提醒提前天数、临近周末或节假日的判断、业务时区和节假日日历均作为系统设置项维护。

付款相关提醒显示在财务对应业务记录中。

### 二十、提醒功能

4. ETD临近；
5. ETA临近；
6. 船期提前；

11. 缺少运输单据。

- 30天内到期
- 未填写到期日

合同金额－累计已收金额＝未收金额

- 备注
- 操作人
- 操作时间

未完成记录的“更多操作 ▼”包括：

# 质检模块初步设计

### 一、模块用途

质检模块用于工厂完成生产或备货后，对准备出货的产品进行检查，并保存质检结果、照片和报告。

质检模块主要与三个部门交互：

采购 → 提供采购订单和备货信息  
质检 → 检查货物并上传报告  
物流 → 质检合格后安排发货

完整流程：

采购订单生产或备货完成  
→ 系统自动进入质检模块  
→ 质检人员进行检查  
→ 填写结果并上传报告  
→ 合格后通知采购和物流  
→ 部分合格或不合格时通知采购经理联系工厂处理  
→ 工厂处理完成后重新质检  
→ 合格后进入发货流程

### 二、页面数量

质检模块暂时只保留一个主页面：

质检任务

页面中只使用两个标签：

- 待质检
- 已完成

不增加复杂的质检申请、审批、报告和历史记录子页面。

所有内容都在列表和详情中完成。

---

### 三、质检任务如何产生

工厂完成生产或备货后，系统自动把相关信息发送到质检模块，不需要采购人员点击“申请质检”。

系统自动带入：

- 外销合同号
- 采购单号
- 采购合同号
- 客户
- 工厂
- 产品
- 规格
- 采购数量
- 本次质检数量
- 预计发货日期
- 工厂联系人
- 工厂地址
- 采购负责人
- 相关附件
- 备注

采购负责人暂定为采购经理。

采购人员不需要在质检模块中重新填写这些资料。

### 四、质检适用规则

V1 不设置“无需质检”或“免检”流程。

所有进入质检流程的订单按照本模块规则完成质检。

- 待质检

- 待复检

### 七、填写质检结果

- 质检报告

系统根据所有产品结果确定整张任务结果。

---

### 八、质检合格

全部产品合格后：

- 任务进入“已完成”。
- 采购人员立即看到“质检合格”。
- 物流人员立即收到可以安排发货的通知。
- 物流可以查看质检报告和相关照片。
- 采购订单显示“质检合格”。
- 正式船期页面可以继续安排进仓和发货。

不需要再增加领导审批。

---

### 九、部分合格

存在部分合格时：

- 系统显示哪些产品或数量可以发货。
- 系统显示哪些产品需要工厂处理。
- 采购经理与工厂确认处理方式。
- 合格部分是否先发货，由采购根据实际情况决定。
- 未合格部分处理完成后，可以申请复检。

避免因为一个产品的问题，把整张采购单全部冻结。

---

### 十、质检不合格

质检不合格后：

- 任务显示“待复检”。
- 采购经理立即收到提醒。
- 物流人员可以看到暂时不能发货。
- 采购经理联系工厂返工、补货或更换。
- 原质检报告和问题照片继续保留。
- 工厂处理完成后，在同一任务中进入复检。

重新质检不创建另一套复杂流程，而是在同一任务详情中增加一次质检记录。

---

### 十一、复检记录

同一任务可以进行多次质检。

详情中按照时间显示：

第一次质检  
→ 检查日期  
→ 检查结果  
→ 问题说明  
→ 照片和报告

第二次质检  
→ 检查日期  
→ 检查结果  
→ 改进情况  
→ 照片和报告

直到最终合格。

这样既能看到历史问题，也不需要建立多个重复的质检任务。

---

### 十二、已完成页面

已完成列表显示：

- 外销合同号
- 采购单号
- 工厂
- 产品
- 最终质检结果
- 最终合格数量
- 完成日期
- 质检人员
- 操作

已完成记录只保留：

- 查看详情
- 下载报告
- 补充附件

不再显示“开始质检”“修改结果”等无用操作。

已完成的质检结果不提供“重新打开”修改。

### 十三、权限建议

采购人员可以：

- 查看自己负责采购单的质检进度
- 查看和下载质检报告

质检人员自行负责质检任务的实际处理。

质检人员可以：

- 查看全部待质检任务
- 开始质检
- 填写质检结果
- 上传照片和报告
- 完成质检

物流人员可以：

- 查看与自己发货工作有关的质检结果
- 查看货物是否允许发货
- 下载质检报告

销售负责人、销售上级和老板可以：

- 查看相关外销合同的质检结果
- 查看和下载质检报告

### 十四、与现有模块的交互

采购订单  
→ 申请质检  
→ 自动进入质检模块

质检合格  
→ 返回采购订单  
→ 通知物流可以发货

→ 返回采购处理  
→ 物流暂不安排该部分货物发货

重新质检合格  
→ 更新采购订单  
→ 通知物流继续安排发货

质检报告  
→ 销售、采购、物流可以在对应业务详情中直接查看

---

### 十五、简化原则

质检模块不增加：

- 多层审批
- 单独的报告管理页面
- 单独的复检页面
- 复杂的质检状态
- 重复填写采购订单资料
- 无实际用途的操作记录页面

系统只保留必要的质检结果、照片、报告、操作人和时间。

# 我的待办模块

一、模块用途

“我的待办”用于集中显示当前登录人员需要处理的业务事项。

用户不需要分别进入销售、采购、物流、财务和质检模块寻找自己需要处理的工作。

系统自动根据各业务模块的当前状态和用户权限产生待办。

“我的待办”本身不保存另一套独立业务数据。

所有待办均来源于原业务单据。

用户点击待办后，直接进入对应业务详情完成操作。

二、操作人员

所有 ERP 用户都可以进入“我的待办”。

不同人员只看到与自己权限有关的待办。

三、待办数据来源

待办由系统根据其他模块自动生成，主要来源：

1. 销售模块；
2. 采购模块；
3. 物流模块；
4. 财务模块；
5. 质检模块；
6. 系统提醒。

例如：

采购订单提交上级确认  
→ 自动产生一条采购上级待办。

物流上传签署合同并进入核验  
→ 自动产生一条财务上级或老板的合同核验待办。

财务收到采购付款申请  
→ 自动产生一条采购付款待办。

系统自动产生质检任务  
→ 自动进入质检人员“我的待办”。

四、我的待办页面

进入“我的待办”后，默认显示当前用户全部未完成待办。

页面顶部显示：

- 全部待办；
- 紧急；
- 今日到期；
- 已逾期。

五、待办列表

每条待办主要显示：

1. 待办类型；
2. 待办标题；
3. 业务模块；
4. 业务单号；
5. 客户 / 工厂 / 货代等相关对象；
6. 当前业务状态；
7. 产生时间；
8. 要求完成时间；
9. 紧急程度；
10. 来源人员；
11. 操作。

六、查询条件

页面只保留简单筛选：

1. 搜索业务单号、客户、工厂或货代；
2. 业务模块；
3. 待办类型；
4. 紧急程度；
5. 时间范围；
6. 查询。

七、主要待办类型

销售：

- 客户询盘待处理；
- 客户报价待处理；
- 外销合同被退回；
- 合同待签署；
- 签署合同待上传。

销售上级：

- 外销合同待确认。

采购：

- 新采购询价；
- 最终工厂报价待确认；
- 采购订单被退回；
- 采购合同待签署；
- 付款相关待处理事项；
- 工厂交货相关事项。

采购经理：

- 采购最终条件待确认；
- 部分合格质检异常；
- 不合格质检异常；
- 工厂处理待跟进。

物流：

- 新物流询价；
- 最终货代报价待确认；
- 船期任务被退回；
- 货代合同待签署；
- 待订舱；
- 待更新船期；
- 船期异常。

物流上级：

- 最终货代费用和船期待确认。

财务：

- 合同执行条件待确认；
- 采购付款待处理；
- 物流付款待处理；
- 出差付款待处理；
- 船期提前资金待准备；
- 收付款到期提醒。

财务上级 / 老板：

- 采购签署合同待核验；
- 货代签署合同待核验。

质检：

- 待质检；
- 待复检。

八、待办操作

每条待办主要只保留一个明显操作：

“去处理”

点击后直接进入原业务详情。

“我的待办”页面本身不复制业务模块中的操作按钮。

九、待办完成规则

待办不允许用户简单点击“完成”来人为关闭。

待办是否完成，由原业务状态自动决定。

原业务完成后，对应待办自动完成。

如果有下一处理人，系统自动产生下一条待办。

十、退回待办

如果业务被上级退回：

原审批待办完成  
→ 系统自动给原业务处理人员生成新的“退回修改”待办。

十一、紧急待办

以下情况可以标记为紧急：

- 已逾期；
- 船期提前导致资金需要提前准备；
- ETD 临近；
- ETA 临近；
- 船期发生异常；
- 系统设置中定义的其他紧急情况。

紧急规则使用系统设置中的时间阈值。

十二、已完成

页面可以提供：

- 未完成；
- 已完成。

已完成待办只用于查询历史。

已完成待办不能在这里重新修改业务。

十三、权限

待办完全继承原业务权限。

“我的待办”不能让用户因为收到一条待办而获得原本没有的业务权限。

十四、完整流程

业务模块产生需要某人处理的事项  
→ 系统自动生成待办  
→ 待办进入对应人员“我的待办”  
→ 用户点击“去处理”  
→ 进入原业务模块  
→ 完成业务操作  
→ 原业务状态发生变化  
→ 对应待办自动完成  
→ 如有下一处理人，再自动产生下一条待办。

# 角色与权限

本节只根据五个模块及已经确认的业务规则整理需要存在或调整的角色权限。

一、销售

销售人员：

- 负责自己创建或收到邮件转入的询盘；
- 查看和处理自己的询盘、客户报价和外销合同；
- 生成客户报价 PDF；
- 提交外销合同上级确认；
- 上传签署合同并开始执行；
- 查看相关采购、物流和质检进度；
- 不查看具体客户收款金额、未收金额和收款明细；
- 不能修改采购、物流、财务和质检业务数据。

销售上级：

- 查看其管理范围内销售的询盘、客户报价和外销合同；
- 在新合同签字前进行一次确认；
- 只保留“同意”和“退回修改”。

老板：

- 可以查看全部销售合同；
- 可以承担销售合同上级确认；
- 可以按照已确认规则核验采购和货代签署合同。

二、采购

采购人员：

- 查看全部有效采购询价；
- 添加和提交工厂报价；
- 查看其他采购人员已经提交的报价；
- 已提交后，同部门其他有权限采购人员可以继续处理；
- 查看全部采购订单；
- 处理待确认工厂报价的采购订单；
- 上传签署采购合同；
- 在待付款状态申请付款；
- 查看付款进度；
- 查看质检进度和报告；
- 不能修改财务付款记录和质检结果。

采购经理 / 采购上级：

- 对采购最终价格和采购合同条件进行一次上级确认；
- 只保留“同意”和“退回修改”；
- 作为质检任务中的采购负责人；
- 接收部分合格和不合格质检提醒；
- 负责联系工厂处理返工、补货或更换等问题。

三、物流

物流人员：

- 查看全部有效物流询价；
- 添加和提交货代报价；
- 查看其他物流人员已经提交的报价；
- 已提交后，同部门其他有权限物流人员可以继续处理；
- 查看和处理正式船期任务；
- 上传签署货代合同；
- 在待付款状态申请付款；
- 查看财务付款进度和“已准备”结果；
- 更新订舱、进仓、报关、ETD、ETA、开船和到港信息；
- 查看与发货有关的质检结果；
- 不能修改采购、财务和质检专业数据。

物流上级：

- 对最终货代费用、船期和货代合同条件进行一次确认；
- 只保留“同意”和“退回修改”。

四、财务

财务人员：

- 管理入账和出账；
- 登记客户收款；
- 确认合同执行条件；
- 处理采购付款、物流付款和出差付款；
- 登记实际付款；
- 处理船期提前资金提醒；
- 使用“已准备”确认资金已经准备；
- 按权限维护人工确认的有效汇率。

财务上级：

- 查看相关财务业务；
- 核验采购签署合同；
- 核验货代签署合同；
- 按权限维护或确认有效汇率。

五、质检

质检人员：

- 查看全部待质检任务；
- 自行负责实际质检任务；
- 开始质检；
- 填写质检结果；
- 上传照片、视频和报告；
- 完成质检；
- 处理复检；
- 不能修改销售、采购、物流和财务业务数据。

六、权限继承原则

1. 普通销售不能查看其他普通销售的询盘和合同；
2. “全部”均按当前账号原有业务权限理解；
3. 采购和物流询价不需要提前指定具体人员；
4. 采购和物流正式任务不设置整份外销合同固定负责人，以实际经办人为记录；
5. “我的待办”只聚合用户本来有权限处理的业务，不增加额外权限。
