## 建议依次验收

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 销售进入客户询盘，新建并提交含多个产品的询盘 | 采购和物流收到同一份产品需求；仍沿用 D1 模板、Excel 导入和附件 |
| 2 | 采购录入工厂原始报价、币种和贸易条款，先保存再提交 | 保存不对销售可见；提交后销售可查看并选择，可有多家工厂报价 |
| 3 | 物流录入海运费、港杂费、内陆运输费等原始费用、币种和贸易条款，提交两个方案 | 销售页列出两个来源报价、分币种费用合计、适用货物、提交人和时间；货代公司和方案名称保留在“更多信息” |
| 4 | 管理员进入有效汇率，确认 USD/CNY 为 7.05 | 有效汇率、确认人和时间保存；销售不能修改 |
| 5 | 销售进入客户报价，为各产品选择工厂来源，点击产品表顶部“统一选择公式并计算”，再选择用于计算的物流报价 | 一份报价只选择一次公司公式；五个正式公式按编号显示完整表达式，美元海运费和运输天数从物流报价带入。系统用各产品对应的工厂价批量计算全部单价；销售仍可逐项议价修改 |
| 6 | 将原 100 MT 改为成交 60 MT，把最终单价改为 120 | 保存总额 7200 USD；原询盘仍为 100 MT；可以重算、保存及重新导出 |
| 7 | 导出 PDF | 当前修改先保存；只包含对客信息，不显示工厂成本和内部计算公式；多产品自动分页 |
| 8 | 在常驻物流报价表格加入两个运输候选，选中其中一个并分配 60 MT | 单币种原始费用合计带入方案费用，可供客户比较；未选来源报价仍可见且不成为候选/实单；分配超过成交数量会被拒绝 |
| 9 | 点击客户已确认 | 按最终内容生成并打开同一张外销合同；重复请求不重复建单；报价进入已确认且不再可编辑 |
| 10 | 更新有效汇率或源报价后重看已确认报价 | 历史成交价格、数量、来源及汇率快照保持不变 |
| 11 | 销售补充合同条款及原合同号，提交上级 | 上级待办出现；负责销售不能批准自己的合同 |
| 12 | 上级打开合同并退回，填写原因 | 回到负责销售待处理；合同内可看到确认意见；修改后重提仍是同一张合同 |
| 13 | 上级点击同意 | 仅需一次上级确认，进入待签字；不会自动开始执行 |
| 14 | 未传签署件尝试开始执行，再上传测试签署 PDF 后执行 | 前者拒绝；上传成功后负责销售可开始执行；执行后签署件不能删除 |
| 15 | 其他销售、采购、物流尝试查看或修改该合同及客户最终报价 | 其他销售按范围拒绝；采购/物流不能取得最终销售价格；上级可以查看和确认，不能替代负责销售修改、上传或开始执行 |
| 16 | 外销合同列表按状态、编号、客户、负责人筛选 | 四个主要状态：待上级确认、待签字、执行中、已完成；原合同号与系统合同号并存 |
| 17 | 录入执行中历史合同：手填产品、合同量 10、已采购 6、已到货 4、已发货 2、已收款 50、上传签署件 | 不强制原采购人员/供应商，不强制产品主数据；合同与签署件一起保存，已完成量不被强制改为全量 |
| 18 | 销售与管理员分别查看历史合同 | 销售不显示收款金额；财务权限账号可查看；保留历史开账数量 |
| 19 | 负责销售查看执行中合同并补充允许的信息 | 销售页面不提供“完成合同”；合同继续保持执行中，等待后续财务、采购、物流流程共同完成后由系统判断完结；不增加签署后产品/价格变更流程 |
| 20 | 查看我的待办、我发起的、已处理，点击跳转 | 报价、上级确认、退回、签署执行事项随实际状态更新，跳转到相应单据 |

## 大数据与布局

- `evidence/d2-api-result.json` 记录本次 101 产品测试询盘和合同 ID；PDF 为 `evidence/D2-101-products.pdf`。
- 客户报价产品表每页 20 项，固定最大高度，搜索后分页；运输候选采用紧凑表格，分配在抽屉中操作。
- 合同产品及发货汇总限制表格高度，窄屏抽屉宽度随屏幕收缩；横向字段可在表格内部滚动。
- `evidence/d2-multiple-plans.json` 为两家工厂、两个运输方案的测试记录；`evidence/d2-historical.json` 为历史合同测试记录。
