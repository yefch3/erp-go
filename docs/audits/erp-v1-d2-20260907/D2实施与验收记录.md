## 用户已确认的业务边界

用户在本任务中已明确确认以下三项，不再作为待确认事项：

1. Q1：上级同意 → 双方签署 → 上传签署合同 → 销售点击开始执行 → 进入财务入账。采用正式详细规则；保留财务简写流程的文字差异，不改正式文件。
2. Q9：正式确认前可以调整产品、购买数量、最终价格和交付条件，重新计算、保存、重新出报价；最初询盘不被覆盖。客户正式确认时以最终成交内容生成合同并保存当时的报价依据。确认后修改源报价不覆盖已确认客户价或合同，不在此增加确认后合同变更流程。
3. Q10：客户确认时由销售记录实际接受的运输方案及对应产品数量；未选中的 PDF 方案保留为候选。后续物流仍可按正式需求重新询价，不锁定最终货代，不把全部候选变成实单。

## 本轮发现并修复

- 旧“全部可见”被误当成“全部可写”，改为负责销售独占写入。
- 历史合同允许无签署件先落库，改为先验证真实上传再原子保存。
- 管理员实际编码为 SUPER_ADMIN，新增迁移 62 修正有效汇率权限。
- 合同确认意见受全局审批权限限制，新增按合同自身范围授权的历史接口。
- 导出客户报价前保存当前修改，避免沿用旧价格或旧数量。
- 已完成合同不能再改附件，附件删除与开始执行使用并发保护。
- 历史上传 RPC 使用独立请求/响应类型，通过接口规范检查。
- 上级负责人筛选改从可见合同返回选项，不要求员工目录权限；数据库用例验证不越过销售范围，前端类型检查通过。
- PR #386 首轮 CI 固定比较 main，将 main 后加的邮箱接口误判为本轮删除；改为比较 PR 实际目标分支，兼容性检查保留。
- 隔离库只产生 ContractStarted / ContractImportedExecuting 交接事件；采购实单数量为 0，未进入 D3。
- 第二轮 CI 识别旧采购测试到期日写死为 2026-09-05；已核对并复用 main 的 3bf97839（#374）测试修复，保留原提交来源，隔离采购库全应用回归通过。业务到期校验不变。
- 静态检查识别旧报价写入口停用后的未使用转换函数，已删除该遗留函数。
