# D6 详细人工验收清单

更新日期：2026-09-12

## 1. 验收目标

验证 D6 的完整业务链路：物流实单已委托后建立一条正式船期，补充订舱和运输资料，按港口记录预计与实际时间，自动推进状态，保存运输附件，并把日期变化产生的事项准确送达采购或财务。

本轮状态流程为：

`已委托 → 建立正式船期 → 待订舱 → 待开船 → 运输中 → 已到港`

当前一份合同只允许一条有效正式船期，不测试分批运输。

## 3. 时间名称

| 页面名称 | 缩写 | 含义 |
| --- | --- | --- |
| 预计到港（ETA） | ETA | 预计抵达某港口的时间 |
| 预计离港（ETD） | ETD | 预计离开某港口的时间 |
| 实际到港（ATA） | ATA | 实际抵达某港口的时间 |
| 实际离港（ATD） | ATD | 实际离开某港口的时间 |

所有港口时间必须按弹窗顶部显示的港口时区填写。上海使用 `Asia/Shanghai`，汉堡使用 `Europe/Berlin`。

## 5. M02 已委托实单与唯一船期

**账号：物流 L1；合同：`CT-D6-ACCEPT-001`**

1. 在“物流 → 实单”选择“合同与委托”。
2. 搜索 `CT-D6-ACCEPT-001` 并打开。
3. 核对客户、产品、规格、数量、签约货代、实际承运方、物流费用、起运港和目的港。
4. 如果显示“建立正式船期”，点击并保存；如果显示“查看正式船期”，说明该验收合同已经建立船期，直接进入。
5. 返回实单再次查看同一合同。

**预期结果：**

- 合同资料完整带入，不需要重复录入客户和物流费用。
- 建立后按钮变成“查看正式船期”。
- 同一合同不会出现第二条有效正式船期。
- 船期详情与实单指向同一份合同。

## 6. M03 正式船期基础资料

**账号：物流 L1**

1. 在船期详情点击“编辑基础信息”。
2. 补充或修改船公司/货代、船名、航次、订舱号、提单号、进仓日期、报关日期和备注。
3. 保存后刷新页面，再次打开编辑弹窗。
4. 可再修改一次船名或航次，用于检查历史。

**预期结果：**

- 保存成功，不出现 `contractHandoffId` 或其他 ID 格式错误。
- 刷新后数据仍存在。
- 编辑原船期，不生成第二条船期。
- “变更记录”保留修改前后值、操作人和时间。

## 7. M04 港口路线与字段规则

**账号：物流 L1；页面：船期详情 → 港口路线**

1. 查看起运港 Shanghai。
2. 查看目的港 Hamburg。
3. 如需验证中转港，点击“添加中转港”添加一条测试港口，验收后可移除。

**预期结果：**

- 起运港显示预计到港（ETA）、实际到港（ATA）、预计离港（ETD）、实际离港（ATD）。
- 目的港只显示预计到港（ETA）和实际到港（ATA），不显示离港字段。
- 中转港同时显示到港和离港四个字段。
- 起运港状态未离港时显示“待离港”；目的港未到港时显示“待到港”。
- 添加中转港不会改变起运港和目的港的角色。

## 8. M05 港口时间编辑与时区

**账号：物流 L1**

1. 点击 Shanghai 的“更新时间”。
2. 确认顶部显示 `Asia/Shanghai`。
3. 填写或调整预计到港（ETA）、实际到港（ATA）、预计离港（ETD）、实际离港（ATD）。
4. 不填写原因；备注可留空，保存。
5. 点击 Hamburg 的“更新时间”。
6. 确认顶部显示 `Europe/Berlin`，且只填写预计到港（ETA）和实际到港（ATA）。

**预期结果：**

- 页面不要求填写“更正原因”或“操作原因”。
- 上海时间不会因为电脑时区而显示成前一天。
- Hamburg 不出现预计离港或实际离港输入框。
- 原始预计时间一直保留；最新预计时间可以更新。
- 每次保存都会自动写入变更记录。
- “当前港口时间”总表明确列出每个港口的 ETA、ATA、ETD、ATD 和当地时区。
- “预计时间变更记录”显示港口、ETA 或 ETD、变更前后日期，并用“提前 N 天”“延后 N 天”或“首次补充”说明变化。
- 实际时间不能破坏路线先后顺序；不合理时间应给出明确中文提示。

## 9. M06 状态自动流转

**账号：物流 L1**

按顺序操作，并在每一步返回船期列表核对状态：

1. 暂无订舱号时查看状态。
2. 补充订舱号并保存。
3. 在 Shanghai 填写实际到港（ATA），但暂不填写实际离港（ATD）。
4. 在 Shanghai 填写实际离港（ATD）。
5. 最后在 Hamburg 填写实际到港（ATA）。

**预期结果：**

| 操作 | 预期船期状态 |
| --- | --- |
| 尚无订舱号 | 待订舱 |
| 已有订舱号、尚未从起运港离港 | 待开船 |
| 仅填写起运港实际到港 | 仍为待开船 |
| 填写起运港实际离港（ATD） | 运输中 |
| 填写目的港实际到港（ATA） | 已到港 |

状态由港口实际时间自动计算，不增加审批步骤。

## 12. M09 个人提醒与周末倒推

**账号：先物流 L1，再财务 F1**

1. 物流在船期编辑页设置多个运输提醒，例如提前 14、7、3 天。
2. 选择业务时区并保存。
3. 退出后重新登录，确认设置保留。
4. 财务登录并设置不同的提醒天数。
5. 再切回物流，确认物流的设置没有被财务覆盖。
6. 使用预计到港日期落在周一附近的船期检查提醒日期。
7. 修改起运港最新预计到港（ETA）或最新预计离港（ETD），保存后刷新详情和船期列表。
8. 将其中一个时间改到已进入提醒范围，观察页面右上角铃铛和右上角自动弹窗。

**预期结果：**

- 提醒天数允许用户自行添加和删除。
- 不同用户的设置相互独立。
- 计算按各自业务时区执行。
- 提醒日期落在周六或周日时向前移动到工作日。
- 港口最新预计时间保存后，船期摘要和未发送提醒自动按新时间重建；原始预计时间继续保留为历史基线。
- 起运港和中转港分别支持预计到港（ETA）及预计离港（ETD）提醒，目的港支持预计到港（ETA）提醒。
- 到达触发日后，右上角铃铛增加未读数，并按“弹窗开启”和“本条弹窗”设置自动显示通知；点击“查看详情”进入对应船期。
- 修改时间时若一次越过多个提醒点，只即时补发最近的一条，避免同一港口事件连续弹出多条重复通知。
- 当前版本不连接 Google Calendar，也不使用国际公共节假日，因此不会出现外部日历同步失败。

## 13. M10 采购联系工厂提醒

**账号：物流 L1 → 采购 P1**

1. 确保船期尚未开航。
2. 物流将预计离港（ETD）或进仓日期改为更晚日期并保存。
3. 退出物流账号，以采购 P1 登录。
4. 打开“我的待办”，查找 `CT-D6-ACCEPT-001` 的联系工厂事项。
5. 填写处理结果，例如“已联系工厂并确认新的进仓安排”。
6. 切回物流 L1，打开船期详情的“协同提醒”。

**预期结果：**

- 采购收到与合同和船期对应的待办。
- “前往处理”能够进入可处理的位置，不是无响应链接。
- 采购可以提交本人待办的处理结果。
- 处理结果回写到原船期“协同提醒”。
- 该待办不会赋予采购查看物流费用或运输附件的权限。

## 14. M11 财务准备付款提醒

**账号：物流 L1 → 财务 F1**

1. 物流将目的港最新预计到港（ETA）调整为比当前日期更早。
2. 退出物流账号，以财务 F1 登录。
3. 在“我的待办”或运输提醒中查找对应事项。
4. 打开正式船期，核对客户、路线、预计到港日期和物流费用。
5. 打开“单证附件”，预览或下载物流上传的文件。

**预期结果：**

- 财务收到提前准备付款的提醒。
- 财务可以查看船期、物流费用和运输附件。
- 财务不能编辑船期、港口路线、进度或上传/作废附件。
- “准备付款”只表示准备工作，不等同于已经付款。

再次把目的港 ETA 调整为更晚日期并重复检查：财务应收到“ETA 延后，请调整付款安排”，船期“协同提醒”和财务“我的待办”显示相同的变更前后日期。起运港或中转港 ETA 变化只记录运输时间，不触发财务付款提醒。

## 15. M12 权限与数据隔离

分别使用三个账号检查：

| 功能 | 物流 L1 | 财务 F1 | 采购 P1 |
| --- | --- | --- | --- |
| 查看正式船期 | 可以 | 可以 | 仅通过本人协同待办查看必要信息 |
| 编辑船期和港口时间 | 可以 | 不可以 | 不可以 |
| 查看物流费用 | 可以 | 可以 | 不可以 |
| 查看/下载运输附件 | 可以 | 可以 | 不可以 |
| 上传、更新或作废附件 | 可以 | 不可以 | 不可以 |
| 处理采购联系工厂待办 | 不可以代替采购处理 | 不可以 | 可以处理本人待办 |

**预期结果：** 页面按钮和接口结果一致。手工输入受限地址时也不能越权，不应只靠隐藏按钮实现权限。
