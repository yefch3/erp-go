# D6 范围确认：物流运输执行与提醒闭环

更新日期：2026-09-11

## 一、阶段目标

D6 承接 D4 已完成审批、签约和委托的物流订单，并读取 D5 质检结果，完成正式船期建立、订舱、开航、运输、到港以及日期变化提醒。D6 不增加新的业务审批，也不建立与物流订单或船期管理重复的执行页面。

主流程：

`物流订单已委托 → 建立正式船期 → 待订舱 → 待开船 → 运输中 → 已到港`

货代提供实际船舶和船期安排后，物流在“建立正式船期”中确认并录入，不增加独立“宣船”页面或状态。付款未完成时是否可以继续订舱，按已签货代合同的付款条件判断。

## 二、单次运输与资料

当前 D6 按一份外销合同一次运输实施：每份合同只建立一条有效正式船期，不提供运输批次拆分、分批发运或累计发运数量计算。重复建立正式船期必须被阻止。正式船期记录：

- 合同产品及数量；
- 货代、船公司、船名和航次；
- 装货港、目的港、订舱号和提单号；
- 预计和实际备货日期、进仓日期、报关日期；
- ETD、ETA、实际开船日期和实际到港日期；
- 物流费用、运输附件和备注。

暂时不能确定的船名、航次、订舱号和提单号允许留空，并在后续节点补充。换船、延期或其他船期变化更新同一条正式船期并保留完整变更历史，不新建第二个运输批次。未来确需分批运输时另行确认和扩展，不在当前 D6 中预建复杂流程。

## 三、提醒与处理回传

- 各用户自行设置各类提醒需要提前多少天触发；设置只影响该用户收到提醒的时间，不改写业务日期和其他用户的设置。
- 当前运输提醒覆盖有效港口的预计到港和非目的港的预计离港，按用户选择的业务时区跳过周六、周日，不接入国际公共节假日日历。
- ETA 提前：在对应船期和财务出账记录中提醒财务准备付款；财务“已准备”只表示完成准备，实际付款登记后提醒结束。
- 货物实际提前到港：财务尚未处理时再次提醒。
- 未开航且 ETD 或进仓日期延后：提醒相关采购联系工厂；采购处理后回传“已通知工厂”。
- 已开航后 ETA 延后：更新船期并通知相关销售、物流和财务，不要求采购通知工厂停止发货。
- 预计开船、预计到港、实际开船、实际到港、提前到港、延误和付款准备提醒保留在原业务页面、对应财务记录和相关待办中，不新建独立提醒模块。

## 四、页面、待办与权限

物流订单、船期管理和“我的待办”必须指向同一运输业务记录，并准确定位到需要处理的批次和操作节点。提醒不增加新的业务状态；待办不授予额外权限。

物流和财务可以查看船期资料、运输附件和物流费用，并分别执行职责范围内的操作。采购、相关销售及上级只查看权限范围内的运输节点、日期、状态和提醒，不查看船期附件及物流费用。不同角色的列表、详情、附件、操作按钮和接口权限都需要分别验证。

## 五、业务时区与周末口径

- 每个用户选择业务时区并设置运输提醒提前天数；设置只影响本人的提醒时间。
- 提前天数按工作日倒推，当前只跳过周六、周日。
- D6 不依赖 Google Calendar，不选择国家或地区公共节假日日历；外部日历不可用不会影响运输业务和提醒。
- 未选业务时区时，页面应明确提示用户完成设置，不能静默采用开发环境日期。

## 六、不自动纳入 D6 的事项

- 五公式输入口径；
- 物流费用分摊规则；
- D5 暂缓的质检结果通知采购；
- 采购端查看质检资料；
- 部分合格货物先发流程。

这些事项继续保留为待确认项，只有用户明确确认后才进入相应阶段。
