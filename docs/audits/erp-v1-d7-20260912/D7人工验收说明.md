# D7 详细人工验收清单

更新日期：2026-09-13

## 1. 验收目标

D7 在既有“出账”页面内增加出差报销，流程为：

`草稿 → 待部门负责人确认 → 待财务负责人审批 → 待付款 → 已付款`

被退回的申请回到申请人修改后重新提交。报销人不能审批自己的申请；关键资料或主要凭证在审批通过后变化会使原审批失效并回到草稿。汇率页是独立参考工具，不把汇率写入报价、合同、收付款或公式。

## 3. M01 页面入口与 D1–D6 基础回归

1. 分别用 L1、B1、F1 登录。
2. 确认左侧导航可收起、展开、拖动排序，语言与账号区正常。
3. 进入“财务 → 出账”，确认顶部有“供应商付款”和“出差报销”两个页签。
4. 用 L1 登录时直接显示“出差报销”，不会因没有供应商付款权限而报 403。
5. 抽查销售合同、采购实单、仓库、质检、物流实单和正式船期页面。

预期：D1–D6 页面可打开，没有 401、403、404、500 或 15 秒超时；已有合同、质检和船期数据保持原样。

## 4. M02 新建草稿与必填校验

**账号：L1**

1. 进入“出账 → 出差报销”，点击“新建报销”。
2. 留空任一必填项点击保存，确认页面提示补齐。
3. 填写出差开始/结束日期、出发地、目的地、事由、金额、币种、收款账户和备注。
4. 暂不选择附件，保存草稿。
5. 刷新页面并展开该行。

预期：草稿保存且刷新后仍存在；报销人和部门自动取当前员工资料；金额按原币种保存，不做混合币种折算。处理记录保留在后台审计中，不在页面展开冗长历史。

## 5. M03 凭证与提交门槛

**账号：L1**

1. 对无附件草稿点击“提交审批”。
2. 确认系统拒绝并明确提示至少上传一份凭证。
3. 点击“编辑”，选择“发票”并上传 PDF/JPG，保存。
4. 展开记录，点击附件名称确认可打开。
5. 点击“保存并提交审批”，或保存后再提交。

预期：无附件不能提交；附件保存后可打开；状态变为“待部门负责人确认”。

## 6. M04 部门确认、待办与禁止自审

1. L1 打开“我的待办”，确认自己不会出现这张审批任务。
2. B1 登录，打开“我的待办”或“出账 → 出差报销”。
3. 找到 L1 的报销，核对行程、金额和附件，点击“同意”。
4. 刷新并查看状态。

预期：任务只到 B1；B1 能查看参与审批的这张报销；同意后状态变为“待财务负责人审批”。接口冒烟已额外验证报销人拿审批任务编号自审时返回 403。

## 7. M05 财务审批、退回与重新提交

**建议新建第二张测试申请，用于验证退回。**

1. B1 对第二张申请确认后，用 F1 登录。
2. 在“我的待办”找到该报销，点击“退回”。
3. 不填写原因直接确认，系统应不提交；填写“缺少住宿发票”后退回。
4. L1 登录，确认状态为“已退回”且能看到原因。
5. L1 编辑资料、增加凭证并重新提交；B1、F1 再依次同意。

预期：退回原因必填并对申请人清晰可见；修改后旧审批实例不继续使用；重新走完整两级审批，最终进入“待付款”。

## 8. M06 付款、冲销与审批失效

**账号：F1 与 L1**

1. F1 在“待付款”记录点击“登记付款”，填写付款日期、公司付款账户和流水号。
2. 刷新并展开记录，核对状态和付款资料。
3. F1 点击“冲销付款”，不填原因不得继续；填写原因后确认。
4. 确认记录回到“待付款”，再登记一次付款。
5. 对另一张已审批但未付款记录，用 L1 编辑关键字段或增加主要凭证。

预期：只有财务负责人能登记和冲销；付款后为“已付款”；冲销原因保留在后台审计；已付款记录不能再修改资料或凭证；待付款记录变更后回到草稿并要求重新提交。

## 9. M07 权限与可见范围

1. L1 只应看到自己的报销和自己参与审批的报销。
2. B1 能看到自己作为部门负责人处理的报销，不能浏览全公司无关报销。
3. P1 登录，确认看不到 L1 的报销 `TR-20260913-000003`。
4. F1 能看到全公司的报销并执行付款。
5. 尝试由普通员工调用付款入口，确认页面无按钮且接口返回 403。

预期：申请人、审批参与人和财务负责人的可见边界准确，没有跨租户或跨员工泄露。

## 10. M08 独立汇率参考页

1. 分别用 L1 和 F1 打开“财务 → 汇率”。
2. 核对来源、最近成功时间、最近尝试时间、同步状态、币种卡片、正反向数值与 30 日走势。
3. 点击“立即同步”，确认完成后时间更新。
4. F1 可进入“关注币种”调整 1–12 个币种；L1 可以查看和刷新，但不显示维护关注币种入口。
5. 核对页面提示“仅供参考”，并抽查报价、合同和收付款，确认没有被自动改写。

预期：所有员工可查看；当前验收环境已验证 Frankfurter / ECB 实时同步成功。外部网络不可用时显示橙色缓存提示并继续展示最近成功数据；接口冒烟也已验证该降级状态。

## 11. M09 旧银行流水退役与数据兼容

1. 用 F1 展开“财务”，确认没有独立“银行流水”或“历史银行流水”入口。
2. 在“入账”的“收款记录”核对已发生的客户收款；在“出账”的“付款记录”和“出差报销”核对已发生的付款。
3. 访问旧书签 `/bank-transactions`，确认自动回到“入账”，不会出现第二套登记页面。

预期：旧银行流水数据与只读接口只为历史兼容保留；旧写接口返回 404/405，新收付款只进入“入账”或“出账”，不能产生两套互相冲突的记录。

## 12. M10 历史合同与暂缓项边界

1. 打开一份历史合同，记录一笔实际发生的收款或付款。
2. 核对总额、已收/已付和剩余金额按实际发生金额展示。
3. 确认历史合同没有自动补采购、质检、运输批次或阶段数量。
4. 确认 D5 质检结果通知采购、采购查看质检资料和部分合格先发仍未新增；五公式输入口径、物流费用分摊、多币种混合汇总仍未改变。

预期：D7 不扩张历史合同或暂缓功能边界。
