# 历史采购单补录

采购订单右上角提供「补录历史采购单」。使用现有采购建单权限和采购订单 Data Scope，供应商沿用现有主数据访问校验，所有数据按登录上下文 tenant_id 隔离。

- 必填供应商、原下单日期、产品名称、数量和单位。原单号可留空自动生成，同公司重复单号拒绝。
- 保存草稿后可继续补录；确认补录进入 ORDERED，不发起新采购审批，不生成收货、库存或付款记录。
- 使用现有采购订单、产品行及附件表。历史元数据单独记录原日期、录入人和真实录入时间。为兼容现有需求外键，每行有一条已关闭的内部手工需求，不进入待采购队列，不关联客户报价或采购批次。
- 默认直接送达，收货地址可补填；本入口用于补录仍待履约的历史订单，不用于追溯生成已发生的库存和付款。
- 未填写单价通过 price_missing 与 prices_complete 明确区分；订单列表/详情不将未知价格显示为零。补齐前拒绝登记到货和申请付款。
- 已确认且未到货的单据可补齐资料和价格；不能更换供应商、币种、产品或数量。申请付款后停止编辑。
- 上传原合同或订单文件复用采购资料，单个上限 10 MB。草稿保存后上传，再确认，上传失败可在同一草稿重试。
- 补录订单可进入现有质检来源列表，质检仍在同一订单下记录。

部署先执行采购迁移 00075，再更新采购服务、网关和前端。

验证：数据库集成测试覆盖草稿/确认、补价、金额、跨 tenant 拒绝、负责人范围、重复单号、原审批入口拦截、附件、质检衔接及不产生待采购需求/收货记录；同时回归现有质检测试、Go 测试及 Vue 类型检查和构建。

补录表单与正常单据对齐：移除联系人、联系电话、收货地址；预计到货与应付到期日使用现有订单字段，采购员自动显示，金额汇总计算。产品支持现有目录选择并保存产品 ID、编码、单位关联，旧产品未建档时可输入历史名称。

Excel 明细导入：提供固定表头模板，支持 .xlsx/.xls；仅向当前草稿追加产品行，不自动建单。产品名称、数量、单位必填，价格可空；错误行显示原行号，正确行保留。供应商、原下单日期等单头信息仍由页面填写，权限和 tenant_id 继续在保存接口检查。总金额未齐时显示为空。

补录窗口不再显示应付到期日；产品明细采用横线分隔的紧凑行，无独立输入边框，聚焦时显示底线提示。已有应付日期在编辑时仍保留，不因移除输入项而清空。
