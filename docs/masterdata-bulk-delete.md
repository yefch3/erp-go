# 基础数据按创建日期批量删除

范围：客户、供应商、港口。仅当前公司的有效 SUPER_ADMIN 可访问，网关及 masterdata RPC 均验证权限。

在列表点击“按时间批量删除”，选择创建日期（含首尾两天，按页面显示的浏览器时区），预览后勾选资料。每页 100 条，可跨页全选可删除项，每次最多预览及删除 1000 条；超出时缩小日期范围。该范围包含停用资料，不继承列表上的其他筛选条件。

有关联业务的资料禁止删除。历史及取消业务同样参与检查；仅以名称保存的引用采用保守匹配，因此同名资料可能同时被拦截。系统不合并重复资料，也不迁移业务归属。执行前重新核验引用及主资料版本，任一所选资料不符合条件则整批不执行。关联服务不可用时禁止执行。

这是永久删除，包含所选资料自身的联系人、地址及负责人等从属信息。确认框会提示不可恢复；没有新增回收站。现有变更日志保留。

## 发布依赖

需要一并发布 gateway、masterdata、approval、export、inventory、mail、procurement、product、shipping，以及前端，并执行 masterdata 的 00032 迁移。后七个业务服务新增引用查询 RPC；旧版本或不可达会导致预览失败并阻止删除。Compose 已配置 masterdata 到这些服务的地址。

执行时锁定本地所选主资料，但跨服务引用检查不是分布式事务：不能提供与其他服务并发新建业务之间的全局串行化保证。清理期间应避免同时为所选资料建立新业务。

## 验证

- 独立 PostgreSQL 测试库：日期边界、跨公司隔离、引用保护、预览后变化、整批回滚、删除联系人及保留日志。
- 网关及 RPC：权限拒绝和预览不能触发执行。
- 前端：日期转换、跨页选择、类型检查与生产构建。
- 1366×768 视口包含侧栏，模拟 120 条数据检查跨页选择、禁止项和确认取消流程；未操作生产数据。
