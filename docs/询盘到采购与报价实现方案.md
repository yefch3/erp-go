# 询盘 → 工厂询价 → 客户报价实现方案

## 1. 结论

采购模块并不是空白。当前代码已经完成了合同生效后的采购执行链路：

- `purchase_requirements`：生效合同的全量采购需求与手工采购需求
- `purchase_orders`：合并需求后向供应商下单
- 审批：草稿采购单提交审批，批准后才占用需求数量
- 到港：采购侧登记工厂送达码头库，通过事件维护码头保管台账
- 前端：`/requirements` 和 `/purchase-orders`

这套模型回答的是“客户已经下单以后，还缺什么、向谁采购”。本次需求回答的是
“客户还在询价时，怎样向多家工厂询价并算出客户报价”。两者发生在销售漏斗的不同阶段，
不能把客户询盘直接塞进 `purchase_requirements`，否则未成交的询盘会污染真实采购缺口。

应在 `procurement` 服务内新增一条独立的“询价与成本核算”子域，最终只把确认后的客户报价
交给 `export` 服务。客户接受报价并形成合同后，采购直接按合同全量建立需求，不做自有库存
抵扣；工厂完工后送到指定码头库，再衔接船务出运。

这里的“码头库”是第三方港区/码头的货物保管地点，不是公司备货仓。`inventory` 可以暂时
保留为港口货物的数量和货权台账，供到港与出运交接使用，但不得参与采购需求核算，也不应
在业务界面表述为“可用库存”。

## 2. 服务边界

| 服务 | 职责 |
|---|---|
| `mail` | 读取有权限的选中文字/附件；调用 LLM 提取固定字段；提供预览和 Excel 下载 |
| `product` | 产品/SKU 候选召回、属性模板、客户叫法别名 |
| `procurement` | 询价案件、工厂询价单、供应商报价、港杂费/海运费快照、成本方案、合同全量采购 |
| `masterdata` | 客户、供应商、联系人；后续可增加港口字典，不保存有时效的运价 |
| `fx` | 成本方案创建时提供汇率；方案内保存快照 |
| `export` | 创建和发送正式客户报价；保持现有报价状态机 |
| `shipping` | 码头库到货后的实际船期和实际费用，不承担售前估算运价 |
| `inventory` | 仅维护码头库保管与出运交接台账；不做备货、可用量承诺或采购净额计算 |

LLM 只做“从非结构化内容提取事实”，不做价格、汇率、费用分摊、利润或总价计算。
所有金额使用 `decimal`，禁止 `float64`。

## 3. 公司固定询价表

固定列由服务端控制，LLM 无权修改顺序：

1. 产品
2. 材质/标准
3. 牌号/等级
4. 厚度
5. 宽度
6. 长度/形式
7. 表面要求
8. 涂层/镀层
9. 公差
10. 卷重
11. 卷内径
12. 包装
13. 交期
14. 付款条件
15. 贸易术语
16. 港口
17. 单位
18. 备注
19. 数量
20. 单价
21. 总价

“数量”是模型提取的最后一列；“单价”和“总价”由系统追加。单价为空，总价逐行写入
Excel 公式 `数量单元格 × 单价单元格`。模型返回缺失字段时必须给空字符串，不得猜测。

## 5. 业务流程

```text
邮件正文/附件
  → LLM 固定字段提取
  → 员工核对并确认产品/SKU
  → 建立询价案件
  → 选择多家供应商
  → 生成各供应商的工厂询价 Excel / 邮件
  → 手工录入或导入供应商报价
  → 选择每行采用的供应商报价
  → 加港杂费、海运费、保险、资金成本和利润
  → 确认成本方案
  → 调用 export 创建客户报价草稿
  → 导出/发送客户报价
  → 客户接受 → 合同全量采购需求 → 采购单 → 工厂生产 → 码头库到货 → 出运
```

工厂询价可以群发，但系统任务是主记录，邮件只是通知/传递方式。每次发送要记录收件人、
模板版本、附件 key、操作者和时间，不能只靠采购部门成员各自邮箱里的副本追踪进度。

## 6. 成本计算

费用分摊必须是可复核的确定性计算：

```text
到岸单位成本 = 工厂单位价
             + 每吨港杂费
             + 每吨海运费
             + 每吨保险/单证/资金成本
             + 每吨其他费用

客户单位价 = 到岸单位成本 + 利润
客户总价   = 客户单位价 × 数量
```

按柜、按票的费用先按方案中选择的分摊基准（吨数、金额或柜数）分到明细。分摊前后总额必须
对平，尾差落在最后一行并保留审计字段。利润支持“每吨固定金额”和“成本加成百分比”，但一份
方案只能选一种，避免双重加价。

- `procurement:sourcing:read`
- `procurement:sourcing:write`
- `procurement:sourcing:send`

## 8. 分阶段落地

### P0：邮件转固定询价 Excel

- 邮件正文/附件右键入口
- 图片、PDF、文本和常见办公附件输入
- 固定 21 列、单价空白、总价公式
- 预览和下载
- 两个 `_test_case` 样例作为回归基线

### P1：询价案件与人工复核

- 增加 `sourcing_cases/sourcing_lines`
- 保存原文来源与模型结果，人工决策单独存
- 对接产品候选召回；不允许 AI 结果自动确认
- 解析改为异步任务，SSE 通知完成

当前状态（2026-08-14）：**P1 已完成**。询价案件落库、重复附件保护、逐行修改全部固定字段、
基于内部产品目录的候选召回（仅供人工选择）、产品/SKU 匹配、确认/无匹配/跳过决策、复核人和
时间审计、未确认行禁止工厂询价均已实现。邮件解析已改为数据库持久化任务，后台 worker 支持
进程重启后的超时任务重新认领；完成或失败后通过 SSE 通知任务发起人，页面同时用轮询兜底，
刷新后可恢复进行中的任务并重新读取已持久化的预览和 XLSX 结果。

### P2：工厂询价与供应商报价

- 一案选择多家供应商
- 生成工厂询价 Excel、从采购部门公共身份发信
- 手工录价和固定模板 Excel 导入
- 报价对比页（价格、交期、付款、MOQ、有效期）

当前状态（2026-08-14）：**P2 已完成**。已实现“一案多供应商、工厂询价单、人工确认明细保护、
固定工厂询价 Excel 下载、采购公共邮箱发送、手工录入完整报价、供应商固定模板 Excel 回传、
确定性金额计算，以及价格、交期、付款、MOQ、有效期的同案报价对比”。固定模板以询价单号和
不可变明细 ID 校验回传身份；数量、单位、列名、行数被改或单价缺失时拒绝导入。公共发件身份
由 Gateway 的 `PROCUREMENT_MAIL_SENDER_ID` 指向一个已经配置邮箱的采购公共账号，浏览器不能
指定其他员工代发；未配置时下载和导入仍可使用，发送操作会给出明确提示。下一阶段进入 P3
费用与成本方案。

### P3：费用与报价计算

- 港杂费、海运费及其他费用快照
- 费用分摊与多个成本方案
- 汇率快照、利润规则、对平校验

### P4：生成客户报价

- 从已确认成本方案调用 `export` 创建报价草稿
- 在 export 报价明细中保存来源 `cost_scenario_id` 和成本快照引用
- 导出 Excel/PDF、发送、客户答复继续沿用现有流程

## 9. 必测不变量

- 邮件、附件、询价案件均验证租户和数据范围，不能用对象 key 越权读取。
- LLM 输出不能改变列名、列序或插入公式；客户文本以字符串写入，防公式注入。
- 数量、单价、费用和汇率不能用 `float64`。
- 未确认的 AI 解析不能生成工厂询价或客户报价。
- 同一来源重复点击要能识别并提示，不产生重复案件。
- 已发送的工厂询价和已确认成本方案不可原地改写，只能生成新版本。
- 客户报价金额必须等于成本方案快照计算结果，导出 Excel 公式与服务端结果抽样对账。
- 采购订单仍只能来自真实采购需求，不能由未成交询盘直接创建。
- 合同采购需求数量必须等于合同数量，不得减去任何库存或码头库现存量。
- 采购收货地点必须是 `PORT_TERMINAL` 类型，普通公司仓库不能用于采购到货。
