# “我的待办”需求清单

> 状态截至 2026-08-26。本文档是“我的待办”首页的功能盘点、产品设计、权限边界与开发台账：
> ✅ 已完成并实测；⬜ 未做；🔶 部分完成/存在缺口。
> 每完成并实际测试一项，再更新对应状态；页面存在不等于功能完成。

> 当前 `/todos` 已是员工登录后的默认页面，并具备审批待办基础能力。本次在现有页面、审批服务、
> 顶部提醒和各模块工作台上增量建设，不重新建立一套平行业务流程。

## 0. 定位

“我的待办”是每位员工登录后的个人工作首页，负责回答四个问题：

1. 我现在必须处理什么？
2. 什么事情已经逾期或即将到期？
3. 我发起或负责的事项进展到哪里？
4. 我应从这里进入哪个业务页面继续工作？

它不是审批中心、完整业务台账、经营驾驶舱或新的业务模块。业务事实仍由合同、采购、仓库、
物流和财务等来源模块维护；首页只按当前员工、权限和数据范围聚合与本人有关的工作项。

本期先覆盖普通员工、业务负责人和系统治理人员。老板/经营驾驶舱暂不纳入本期。

核心关系：

```text
审批 / 采购 / 销售 / 仓库 / 物流 / 财务 / 系统
                     ↓ 按员工、权限、数据范围聚合
              “我的待办”个人首页
       ├─ 待我处理
       ├─ 我发起的
       ├─ 我负责的
       ├─ 提醒我的
       └─ 已处理
                     ↓ 深链接
               返回来源业务页面操作
```

### 0.1 产品原则

1. **同一页面动态适配，不为角色复制页面。** 页面骨架固定，内容和动作根据当前权限、数据范围、分配关系和单据状态生成。
2. **角色名称不是业务判断条件。** “采购员”“财务”等只用于说明典型效果；自定义角色、多角色和临时授权必须自然生效。
3. **首页不是权限后门。** 无来源模块读取权限时，不返回数量、单号、客户、供应商、金额或其他摘要。
4. **首页不复制业务。** 收货、付款、库存调整、取消单据等高影响动作仍在来源页面完成。
5. **个人动作与业务终态分开。** 提醒已读、本人已处理和整张单据已结束是三种不同状态。
6. **固定布局、动态内容。** 权限变化只改变事项、筛选项和动作，不改变首页整体结构，避免 UI 跳动。
7. **同一事实只有一个口径。** 首页、顶部徽标和模块工作台共用统计与已读状态。

### 0.3 HOME0 审计结论（2026-08-26）

本轮已按最新 `main` 对前端路由、审批服务、网关权限、IAM 数据范围、实时事件、
采购/仓库工作台、合同执行、应收和船务提醒进行代码审计。结论如下：

1. `/todos` 可以继续作为登录首页，不另建第二个首页路由；现有审批页面在 HOME1 原位升级。
2. 当前 `GET /api/approvals/todos` 与审批动作共用 `approval:task:act`，因此没有审批操作权限的员工进入首页会看到无权限，而不是个人空状态；HOME1 必须拆开“查看与本人有关的任务”和“执行审批动作”。
3. 当前审批待办是按创建任务时保存的受理员工查询，能够保证个人隔离；但员工离职、角色改派、直属上级变化后，没有自动重算或转交既有待办，可能形成无人处理任务。
4. 采购工作台、仓库工作台、合同执行一览和应收页面都由前端分别拉取多个接口后统计；它们可以作为事项来源参考，不能直接拿页面统计当作首页统一口径。
5. 应收、到港、提单提醒已有个人收件箱和已读状态，但分散在不同顶部组件中；HOME2 再统一，HOME1 不修改其业务生成规则。
6. 后端业务接口会在每次请求时重新校验权限，前端菜单权限只在启动时刷新；在线授权或收权后，页面可能暂时保留过期入口，HOME5 需增加权限版本事件和自动刷新。
7. 现有实时流是“变化提示后重新读取”的 SSE，已支持 `todo.changed`、`doc.changed`、`requirement.changed` 和 `shipping.arrival_reminder` 等少量事件；没有权限变更事件，也没有跨模块统一事项事件。
8. 合同、采购单和船期已有可用详情地址；合同执行、仓库到货/收货及部分应收提醒缺少稳定的单条事项深链接，需要对应批次补齐。

### 0.5 权限变化后的既定处理

| 变化 | 业务接口现状 | 首页目标行为 |
| --- | --- | --- |
| 新增读取权限 | 后端下一次请求立即允许，前端权限可能仍是旧值 | 收到权限版本变化后刷新权限和来源，骨架不移动，新内容渐进出现 |
| 收回读取权限 | 后端下一次请求立即拒绝，前端入口可能暂时残留 | 立即清除该来源的数量、事项、筛选项和缓存，不保留敏感摘要 |
| 新增/收回动作权限 | 网关会重新校验 | 行仍可读时只增减动作；不得把可读事项一并隐藏 |
| 修改数据范围 | 后端按最新范围查询 | 重新计算数量和列表，删除超出范围的旧缓存 |
| 调整角色、上级或员工状态 | 新审批会使用新关系，既有任务不会自动迁移 | HOME5 检测无人处理任务，管理员人工确认转交并保留审计 |

页面保持固定摘要卡、标签和筛选区域；权限变化只改变数字、内容、可用筛选项和按钮，
不会按角色切换完全不同的页面模板。

### 0.7 HOME1 准确开发边界

HOME1 只完成以下内容：

- 将现有 `/todos` 原位改为固定首页骨架、四张摘要卡、五个主标签、筛选区、局部加载/错误和全员空状态。
- 定义统一前端事项模型和来源适配边界，但本批只接入审批来源。
- “待我处理”接入本人待审批任务；“已处理”接入本人审批历史；“我发起的”接入本人提交的审批及被退回/拒绝状态。
- 新增只返回与当前员工有明确关系的审批首页查询；读取本人事项不依赖审批动作权限，动作仍严格要求 `approval:task:act`。
- 保留通过、拒绝和退回前查看业务详情的流程，不修改审批定义、节点选择、回退规则或业务单据状态机。
- 统一合同和采购单审批深链接，未知业务类型只显示安全的只读摘要，不跳转到猜测地址。
- 复用 `todo.changed`、`doc.changed` 刷新审批区域；支持手动刷新和单来源失败重试。
- 增加无角色员工、普通只读员工、审批人、提交人、权限收回、空状态、深链接和动作显隐测试。

HOME1 明确不做：采购/仓库/物流/财务事项接入、提醒合并、权限实时事件、自动转交、经营指标、
首页个性化布局、复杂跨模块投影，以及在首页直接收货、付款、取消、作废或调整库存。

## 1. 首页结构与统一 UI

### 1.1 固定页面骨架

- ⬜ 顶部显示员工姓名、部门、当前日期、最近更新时间和手动刷新。
- ⬜ 固定显示四张摘要卡：**待我处理 / 今日到期 / 已逾期 / 未读提醒**。
- ⬜ 摘要卡数字变化时保持卡片宽度和位置稳定，不造成页面跳动。
- ⬜ 点击摘要卡直接筛选下方列表。
- ⬜ 主标签固定为：**待我处理 / 我发起的 / 我负责的 / 提醒我的 / 已处理**。
- ⬜ 没有任何业务事项时显示欢迎语、常用入口和“目前没有需要处理的事项”，不显示 403 或空白页。
- ⬜ 权限刷新和模块加载使用局部加载状态，不让整个首页白屏或闪回登录页。
- ⬜ 桌面端使用紧凑列表；移动端改为卡片，不保留横向大表格。
- ⬜ 中文、英文和西班牙文文案完整。

### 1.2 标签职责

- ⬜ **待我处理**只显示本人当前可以执行动作的任务和必须处理的异常。
- ⬜ **我发起的**显示本人提交的审批、被退回/拒绝的单据和仍在流转的事项。
- ⬜ **我负责的**显示本人负责合同、采购、物流、仓库或财务事项的关键进度和异常。
- ⬜ **提醒我的**显示到期、逾期、到港、提单和生产节点等提醒。
- ⬜ **已处理**显示本人已经完成动作的记录，默认最近 30 天，可按时间查询历史。
- ⬜ 正常且无须动作的业务流水不进入“待我处理”和“提醒我的”。
- ⬜ 已完成业务不长期堆积在首页，完整历史仍由来源模块查询。

### 1.3 列表、筛选与操作

- ⬜ 每条事项展示紧急程度、模块、类型、标题、业务单号和必要上下文。
- ⬜ 展示当前节点、截止日期、逾期天数、负责人和状态。
- ⬜ 支持按模块、类型、优先级、时间和状态筛选。
- ⬜ 支持按单号、客户、供应商、产品、仓库或负责人搜索。
- ⬜ 行内保留一个主要动作；其他允许动作收进 `···` 菜单，不使用“操作”文字按钮。
- ⬜ 无权执行时隐藏动作，但仍有读取权限的事项保持只读。
- ⬜ 当前筛选因权限变化失效时自动回到可用筛选，并提示“权限已更新”。

## 2. 工作项分类与生命周期

| 分类 | 业务含义 | 结束条件 | 示例 |
| --- | --- | --- | --- |
| 待处理 | 本人必须执行明确动作 | 动作成功、任务转交或来源单据关闭 | 审批、复核询盘、确认收货 |
| 异常 | 流程偏离预期，需要调查或纠正 | 异常解决、责任人确认或单据关闭 | 交期逾期、收货差异、匹配失败 |
| 提醒 | 提醒本人关注，不一定立即操作 | 已读、稍后提醒或来源事项结束 | 应收到期、预计到港、提单待签发 |
| 跟踪 | 本人发起、负责或被抄送，只查看进展 | 单据终态或停止关注 | 我提交的审批、我负责的合同 |

- ⬜ “已读”只改变提醒状态，不代表业务完成。
- ⬜ “已处理”只表示本人动作完成，不代表整张单据完结。
- ⬜ 退回、拒绝、取消、作废和结案分别保存真实业务状态，不混成一个“已处理”。
- ⬜ 已读提醒如果升级为逾期，产生新的状态变化并重新提醒。
- ⬜ 转交、忽略、稍后提醒和批量处理写入审计记录。

## 3. 典型人员看到什么

下表用于说明业务预期，实际必须按权限、数据范围、分配关系和单据状态计算，不能按角色名称硬编码。

| 典型人员 | 默认重点 | 不应出现 |
| --- | --- | --- |
| 销售/业务负责人 | 合同草稿或退回、客户报价反馈、本人合同执行异常和关键节点、本人客户应收风险 | 无关客户、完整采购成本、正常执行流水 |
| 采购专员 | 待复核询盘、询价逾期、报价比较、待建采购单、本人草稿/退回采购单、生产和交付节点 | 审批按钮、其他采购员仅本人范围单据 |
| 采购经理 | 分配给本人的采购审批、采购异常、询价确认、团队范围内逾期事项 | 未分配且超出数据范围的审批和单据 |
| 仓库人员 | 待到货、逾期到货、待收货、收货差异、待出库、库存异常 | 采购价格、信用额度等无关敏感字段 |
| 船务/物流人员 | 船期变更、预计到港、提单待签发、延误异常 | 无关仓库和财务待办 |
| 财务人员 | 应收到期/逾期、未认领流水、供应商发票差异、待付款、对账异常 | 未授权询价和库存操作 |
| 系统治理人员 | 无角色员工、无人处理任务、流程或连接异常；拥有业务权限时再叠加业务事项 | 仅因系统权限自动看到所有业务数据 |
| 多角色员工 | 合并全部生效权限允许的事项并去重 | 同一事项因多个角色重复出现 |
| 暂无角色员工 | 欢迎页、本人资料和联系管理员提示 | 403、空白首页或业务数据 |

## 4. 来源模块与页面联动

### 4.1 审批

- 🔶 已接入审批任务和审批历史，但需要迁移到统一事项结构。
- ⬜ 合同审批和采购单审批只对明确分配的员工显示。
- ⬜ 提交人可以在“我发起的”查看流转状态、退回或拒绝原因。
- ⬜ 审批必须先打开业务预览，不能在缺少上下文时一键通过。
- ⬜ 审批人只需要被分配单据的受限读取能力时，不扩大整个模块的数据范围。
- ⬜ 审批完成后首页、审批记录和来源单据同步更新。

### 4.2 采购

- ⬜ 接入待复核询盘、逾期工厂询价、待比较报价和待确认成本方案。
- ⬜ 接入客户报价反馈、待建立采购单和本人采购单草稿/退回事项。
- ⬜ 接入供应商确认、生产节点、交付节点、收货差异和采购异常。
- ⬜ 已到货但尚未满足结案条件的采购单进入负责人跟踪，不长期占据普通提醒。
- ⬜ 采购工作台和首页使用同一套统计定义。
- ⬜ 来源页面完成动作后首页数字和列表立即更新。

### 4.3 销售与合同执行

- ⬜ 销售模块中的“合同执行一览”继续作为完整合同执行台账，不整体搬入首页。
- ⬜ 首页只提取本人负责且需要关注的合同：被退回/拒绝、即将到期或关键资料缺失。
- ⬜ 合同生效但未建立采购需求、采购未订齐或到期未出运时生成相应事项。
- ⬜ 船期延误、关键时间变化和本人客户应收风险进入提醒或异常。
- ⬜ 正常执行合同可在“我负责的”显示简要阶段，但不进入“待我处理”。
- ⬜ 已完成合同不继续堆积在首页；完整历史从执行一览查询。
- ⬜ 点击事项进入 `/contract-execution` 并定位合同及采购、出运、船期或收款阶段。
- ⬜ 无采购成本或财务明细权限时只展示“采购未完成”“款项逾期”等允许公开的阶段结论。

### 4.4 仓库与库存

- ⬜ 接入预计到货、逾期到货、待收货、收货差异和待出库事项。
- ⬜ 接入冻结库存、负库存、异常调整和导入失败等异常。
- ⬜ 直接交付的采购单不产生仓库收货待办。
- ⬜ 只有进入启用并同步库存的实际仓库才产生收货和库存作业事项。
- ⬜ 虚拟仓不产生实际仓库作业待办。
- ⬜ 不使用仓库的公司仍可收到采购交付、签收和物流提醒，不显示库存作业。

### 4.5 船务与物流

- ⬜ 接入即将开船/到港、ETD/ETA 变化、船期延误和本人负责节点异常。
- ⬜ 接入已开船但提单未签发、出运资料缺失等事项。
- ⬜ 顶部到港和提单提醒与首页共享数据、未读数量和已读状态。
- ⬜ 在顶部标记已读后首页同步，在首页标记已读后顶部徽标同步。

### 4.6 财务

- ⬜ 接入应收今日到期、即将到期和已经逾期事项。
- ⬜ 接入未认领银行流水、匹配失败、供应商发票差异、待付款和对账异常。
- ⬜ 财务提醒优先按合同、付款或对账负责人定向；没有负责人时才按配置的部门或角色分配。
- ⬜ 汇率异常只对拥有汇率读取权限的员工显示。
- ⬜ 金额、银行账号和供应商结算字段分别按财务权限脱敏。

### 4.7 主数据与系统

- ⬜ 客户、供应商或产品资料缺失只有在阻塞当前业务时才成为待办。
- ⬜ 普通资料完整度不足只在主数据详情显示，不无限制造首页噪音。
- ⬜ 员工已激活但没有角色、审批节点无人可分配或角色停用产生无人处理任务时通知系统治理人员。
- ⬜ 邮箱授权失效、关键配置缺失和来源服务异常形成可处理的系统事项。

## 5. 权限、数据范围与动态调整

### 5.1 可见与可操作规则

一条事项只有同时满足以下条件才返回：

```text
能看到 =
  当前员工是处理人、发起人、负责人或被明确抄送人
  AND 拥有来源模块读取权限
  AND 单据落在当前数据范围
  AND 当前状态允许该类事项存在

能操作 =
  能看到
  AND 拥有对应动作权限
  AND 单据当前状态允许该动作
```

- ⬜ 首页对所有已登录员工开放，不新增可以读取所有模块的 `todo:read` 超级权限。
- ⬜ 每个来源继续使用自己的读取、动作和数据范围权限。
- ⬜ 前端根据服务端返回的动作渲染按钮，但每次操作仍由后端重新鉴权。
- ⬜ 无权查看时不返回事项和数量，不能用“0”暗示隐藏数据存在。
- ⬜ 系统管理员身份不自动获得合同金额、采购成本、银行或库存成本权限。

### 5.2 权限变化后的页面行为

| 调整 | 页面自动变化 | 后端要求 |
| --- | --- | --- |
| 新增读取权限 | 出现对应事项、筛选项和允许的菜单 | 下一次请求按新权限返回 |
| 新增动作权限 | 已可读事项出现相应动作 | 执行动作时再次鉴权 |
| 收回动作权限 | 保留只读事项，按钮和已打开操作弹窗消失 | 旧页面提交必须拒绝 |
| 收回读取权限 | 事项、数量和筛选项同时消失 | 不返回任何业务摘要 |
| 数据范围缩小 | 超出新范围的事项自动消失 | 下一次查询按新范围过滤 |
| 增加第二角色 | 合并新增内容并去重 | 采用所有生效授权的并集 |
| 停用员工 | 当前会话失效并退出 | 所有接口拒绝访问 |

- ⬜ IAM 调整员工角色、权限或数据范围后发布 `iam.permission.changed`。
- ⬜ 在线前端收到事件后刷新 `/me/permissions`、首页、左侧菜单和顶部提醒。
- ⬜ 实时事件上线前，在窗口重新聚焦、路由切换及每 60 秒自动检查权限版本。
- ⬜ 权限刷新保留固定页面骨架，仅局部加载，完成后提示“您的权限已更新”。
- ⬜ 正在查看的页面失去动作权限时转为只读；失去读取权限时退出详情并说明原因。

### 5.3 无人处理任务、转交与审计

- ⬜ 审批和明确分配任务记录分配来源：员工、直属上级、角色或部门。
- ⬜ 收回权限后任务可以不再对原员工可见，但不能直接丢失。
- ⬜ 无可用处理人的任务进入“待转交”异常队列并通知有权限的治理人员。
- ⬜ 管理员转交时记录原处理人、新处理人、原因、时间和操作者。
- ⬜ 直属上级或角色成员变化只影响未来分配，不静默改写已生成审批历史。
- ⬜ 只有明确设计为“角色公共池”的任务才随角色成员动态领取。

## 6. 优先级、统计与去重

### 6.1 优先级

| 等级 | 定义 | 展示 |
| --- | --- | --- |
| P0 紧急 | 已逾期、流程阻断或高风险异常 | 红色，排最前 |
| P1 今日 | 今天到期或必须当天处理 | 橙色 |
| P2 临近 | 未来 3 天内到期 | 黄色 |
| P3 常规 | 无明确期限或期限更远 | 蓝/灰色 |

- ⬜ 来源服务返回业务日期、期限和风险信息，统一查询层计算显示优先级。
- ⬜ P0 风险不能永久忽略，只能稍后提醒或在来源页面解决。
- ⬜ 同优先级按截止时间、创建时间和稳定 ID 排序，刷新后不随机跳动。

### 6.2 数量口径

- ⬜ “待我处理”只计算当前员工仍可执行动作的未完成事项。
- ⬜ “今日到期”按租户业务时区计算，不使用浏览器临时时区猜测。
- ⬜ “已逾期”只计算仍未解决且截止时间已过的事项。
- ⬜ “未读提醒”不包含普通待处理任务。
- ⬜ 同一单据的不同动作可以分别计数；同一动作从多个角色命中只能计一次。

### 6.3 去重键

统一事项建议使用以下稳定键：

```text
source_service + item_type + business_id + action_code + assignee_id
```

- ⬜ 重复事件和重复扫描不会生成重复事项。
- ⬜ 同一单据的不同动作可分组展示，但不能互相覆盖。
- ⬜ 首页、顶部徽标和来源工作台使用相同去重和关闭规则。

## 7. 深链接、实时同步与快捷操作

### 7.1 深链接

- ⬜ 每条事项返回页面路径、业务 ID、目标页签/状态、高亮明细行和返回参数。
- ⬜ 返回首页时保留原标签、筛选、搜索和页码。
- ⬜ 目标单据不存在、已经处理或权限变化时显示明确结果，不出现空白页。
- ⬜ 合同执行事项能定位到具体合同和执行阶段。

### 7.2 实时同步

- ⬜ 来源页面完成操作后发布领域事件。
- ⬜ 首页监听统一的 `work_item.changed` 并只刷新受影响摘要和列表。
- ⬜ 现有 `todo.changed` 在迁移期间兼容，最终统一事件名称。
- ⬜ 不能由首页、顶部提醒和工作台分别计算“逾期”。
- ⬜ 一个来源服务暂时不可用时只降级该模块，其他模块继续显示。

### 7.3 快捷操作边界

- ⬜ 首页允许标记提醒已读、稍后提醒和跳转来源页面。
- ⬜ 审批必须打开业务预览后操作。
- ⬜ 收货、付款、库存调整、取消和结案必须进入来源页面完成。
- ⬜ 快捷操作使用版本号或并发令牌，防止旧页面覆盖新状态。

## 8. 技术实现约束

### 8.1 推荐架构

业务服务继续拥有任务事实，首页只提供统一查询层：

```text
前端 /api/home
        │
        ▼
Home 聚合查询
  ├─ Approval: MyWorkItems
  ├─ Procurement: MyWorkItems
  ├─ Contract: MyWorkItems
  ├─ Inventory: MyWorkItems
  ├─ Shipping: MyWorkItems
  ├─ Finance: MyWorkItems
  └─ IAM: 当前权限与数据范围
```

- ⬜ 各来源在服务端按当前员工、权限和数据范围过滤，不能先返回全部再由前端隐藏。
- ⬜ 聚合层设置每个来源的独立超时和错误隔离。
- ⬜ 第一阶段实时查询现有服务，不提前建立复杂投影表。
- ⬜ 数据量增加后再引入事件投影；动作仍调用来源服务并最终鉴权。

### 8.2 统一事项字段

- ⬜ 至少包含：稳定 ID、来源、类型、分类、标题、摘要、业务对象、负责人、状态和优先级。
- ⬜ 包含创建时间、截止时间、逾期天数、已读时间、处理时间和业务终态时间。
- ⬜ 包含稳定深链接、服务端计算的允许动作、权限版本和业务版本。
- ⬜ 展示摘要保存最少必要信息，不复制完整合同、采购或财务数据。

### 8.3 建议接口

- ⬜ `GET /api/home/summary`：摘要卡和各模块数量。
- ⬜ `GET /api/home/items`：分页、筛选和搜索。
- ⬜ `GET /api/home/tracking`：我发起和我负责的事项。
- ⬜ `POST /api/home/reminders/read`：批量标记提醒已读。
- ⬜ `POST /api/home/reminders/snooze`：稍后提醒。
- ⬜ `GET /api/home/preferences`、`PUT /api/home/preferences`：个人显示偏好。

## 9. 个人偏好与通知

- ⬜ 用户可调整模块顺序，但不能显示无权模块。
- ⬜ 可配置每页数量、默认标签和是否显示已完成事项。
- ⬜ 稍后提醒必须保存恢复时间，到期后重新出现。
- ⬜ 高风险事项不能被个人设置永久关闭。
- ⬜ 站内首页是唯一必需渠道；邮件和外部消息不在第一阶段强制实现。
- ⬜ 调整偏好不改变后端任务分配、权限或审计。

## 10. 必须通过的测试

### 10.1 角色、权限与安全

- ⬜ 普通员工、采购、销售、仓库、物流、财务和系统治理账号分别验收。
- ⬜ 多角色账号内容合并且不重复。
- ⬜ 无角色员工可正常进入首页且不泄露业务数据。
- ⬜ 增加角色或权限后页面自动出现新增内容，无需重新登录。
- ⬜ 收回动作权限后按钮消失，旧页面提交被后端拒绝。
- ⬜ 收回读取权限后事项、数字和筛选项同时消失。
- ⬜ 修改 ID、深链接或前端请求不能越权访问其他员工和数据范围。
- ⬜ 角色停用、员工停用和直属上级变化不会产生无人处理且不可发现的任务。

### 10.2 业务联动

- ⬜ 审批、采购、合同执行、仓库、船期和财务来源各完成至少一条端到端验收。
- ⬜ 来源页面完成动作后首页和顶部数量同步。
- ⬜ 首页已读后顶部徽标同步，顶部已读后首页同步。
- ⬜ 合同执行异常进入首页，正常流水和完整历史留在执行一览。
- ⬜ 直接交付、虚拟仓和不使用仓库公司不产生错误库存作业。
- ⬜ 退回、拒绝、取消、作废和结案正确关闭或转换事项。
- ⬜ 重复事件、并发操作和重试不产生重复或错误状态。

### 10.3 UI、可靠性与构建

- ⬜ 权限和数据刷新期间页面骨架稳定，无明显跳动、空白和重复加载提示。
- ⬜ 单个来源超时或失败时首页局部降级。
- ⬜ 1366×768、常用桌面分辨率和移动端布局通过验收。
- ⬜ 中文、英文、西班牙文、长文本、空状态和错误状态通过验收。
- ⬜ 前端单元测试和生产构建通过。
- ⬜ 相关 Go 单元测试、权限测试、集成测试和 GitHub CI 通过。

## 13. 明确不做 / 暂缓

- 老板或公司级经营驾驶舱。
- 把合同执行一览、采购工作台、仓库工作台或财务台账整体搬进首页。
- 为每个角色复制一套首页组件或按角色名称硬编码业务判断。
- 在首页直接执行付款、收货、库存调整、取消和结案等高影响动作。
- 第一阶段发送邮件、短信、微信或 WhatsApp 通知。
- 第一阶段建设复杂事件投影、数据仓库和经营分析报表。
- 仅凭系统管理员身份读取全部合同、采购、库存成本或财务数据。
