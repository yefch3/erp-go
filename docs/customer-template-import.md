# 客户基本资料与 Excel 导入

模板：`frontend/public/templates/customer-import.xlsx`。第一行是表头，保留原《客户资料.xls》的 17 列，在客户名称后增加客户简称；空白模板没有示例客户数据。页面接受 `.xls`、`.xlsx`，一次最多 5000 行，文件最大 20 MB。

## 字段归属

| 模板字段 | 数据来源 |
| --- | --- |
| 客户代码、名称、简称、所属地区、类型、等级、来源 | `customers` 原有字段；国家代码用于国家分组，地区原文存入 `country` |
| 公司电话、传真号码、电子信箱、建档人 | `customers.company_phone/fax_number/company_email/archive_creator` |
| 通信地址、邮政编码 | 原地址模块 `customer_addresses` 的有效 OFFICE 地址；同步 `customers.address` |
| 分管人 | 原 `customer_owners`，支持分号分隔多个员工；导入只增加，不隐式移除原负责人 |
| 联系人姓名、邮箱、电话、手机 | 原 `customer_contacts`；公司邮箱与联系人邮箱分别保存 |

建档人保存 Excel 来源文字。真正操作人的 ID、时间、变更记录仍由登录上下文生成。00026 迁移将旧扩展字段里的公司联系资料复制到固定字段，保留原数据。

## 导入规则

- 表头和列顺序固定，不提供改映射、忽略列或新建字段入口。兼容用户原始 17 列和增加客户简称后的 18 列模板；表头首尾空格不影响识别。格式不一致时阻止预检并提示重新下载模板。新客户代码可留空自动编号。同一客户代码多行会合并为一个客户，分别导入联系人；非空公司信息冲突必须修正。
- 已有客户必须选择“更新非空资料”或“保留原资料”。同一客户各行的选择保持一致。
- 联系人按邮箱（忽略大小写）或“姓名＋电话/手机”匹配；完全无联系方式时使用姓名匹配。重复时选择“更新非空资料”“另增一人”或“跳过”；更新要求唯一匹配。
- 更新保留原联系人 ID，不改变业务记录引用；不修改历史询盘、报价、订单快照。空值不清除现有资料。联系人整组空白不创建，有联系方式而无姓名则阻止导入。
- 没有主要联系人的客户，首个导入联系人为主要联系人；已有主要联系人不被后续导入替换。
- 分管人必须匹配本公司有效员工。创建客户时自动把导入者加入原负责人关系。
- 预检和提交共用校验；提交再次校验，同批次全部通过才写入一个事务。公司级导入锁避免两批同时导入重复记录。
- `templateMode` 为新的确认更新流程；未传入的原 API 调用保持原新增逻辑，继续支持扩展字段映射。

## 权限与布局

所有读写使用登录上下文的 tenant ID。新基本资料 RPC 经过统一客户权限拦截器；已有客户导入也按当前有效负责人关系验证，最高权限角色仅绕过本公司的负责人限制。前端不提供 tenant ID 输入。

`GET/PUT /api/customers/{id}/basic` 读写模板对应公司资料；联系人和负责人入口进入原模块，不建立第二套关系。

列表列、详情标签复用 `useTableColumnOrder` 和 `ReorderableTableHeader`，悬停显示左右移动按钮，可恢复默认顺序。存储键包含 tenant、employee、页面标识。客户查询增加 `short_name` 搜索。

## 验证

- 独立 PostgreSQL 数据库运行迁移 Up → Down → Up。
- `TestCustomerTemplateImportIntegration` 验证一客多人、唯一主要联系人、创建者负责人、重复确认、空值保留、原联系人 ID 更新、权限与租户隔离、错误整批回滚。
- 前端测试读取实际原始 XLS、新下载模板，并校验前导零、公司/联系人字段分离、多负责人映射及移动顺序。
- Vue 类型检查及生产构建。

XLS 解析采用官方 SheetJS 0.20.3 发行包，参考 https://docs.sheetjs.com/docs/getting-started/installation/frameworks/ 。
