# 历史物流补录与财务关联建账

## 业务流程

历史物流：实单页面点击“补录历史物流订单” → 员工手工录入 → 保存后直接打开船期管理。

财务：出账 → 添加付款 → 选择“历史物流付款” → 选择历史物流订单 → 核对带出的货代、币种和费用 → 保存关联账目；后续在原账目登记付款。

历史物流补录不重新经过询价、审批、物流合同核验或付款申请，不自动建立财务账目。历史订单进入船期管理后仍按实际运输情况维护进度，不会因为“历史补录”自动标记已运输或已完成。

## 功能修改

- 入口统一为“补录历史物流订单”。移除运输批次选择、合同搜索、自动带入与自动跳转。
- 外销合同号选填，仅作手工参考；保存时不会因编号相同自动关联系统销售合同。
- 产品名称、规格、数量、单位由员工录入；去掉全空行，填写了资料的产品行必须有名称、有效数量及单位。
- 付款条件支持常用选项及直接输入，订单只保留一个备注框，旧运输说明及备注在回显时保留。
- 起运港、目的港、预计开船及到港日期必填。历史物流记录与船期在同一事务内创建，失败时不留下半张草稿。
- 船期优先显示历史物流订单号与“历史补录”，保留船期编号作为次要信息；新增历史订单资料页签查看货物及付款条件。
- 财务新增历史物流来源选择。采用稳定的物流记录 ID 建立关联，保存时后端重新读取物流快照，不信任客户端伪造的货代、币种、费用及合同参考信息。
- 货代、币种和费用已有数据时自动带出，缺失资料允许财务补齐；已付金额留空为 0，不产生实际银行付款。
- 复用物流来源唯一索引防止重复建账。并发重复、已完成后重建均被拦截，重复请求不会覆盖已记金额。
- 财务账目可打开对应船期，船期可定位对应财务账目；保留原有“其他付款”功能。
- 两个表单均在 1366×768（含侧栏）实际检查，收紧控件、统一对齐并保留可见的保存按钮。

## 部署说明

本次无需新增数据库迁移，使用现有历史物流表和财务物流来源唯一索引。部署时仍需按项目标准执行主分支已有迁移；本地原先缺少采购迁移 87，补齐后恢复采购单查看。该迁移只为历史采购资料增加默认空值的参考字段，不推进单据。

只读快照核对排除了临时签名下载链接及服务升级新增的只读投影字段；原始业务状态、附件和金额未作修改。
