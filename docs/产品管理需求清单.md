# 产品管理需求清单

> 状态截至 2026-08-19。本文档是产品管理模块的功能盘点、设计边界与开发台账：
> ✅ 已完成并实测；⬜ 未做；🔶 部分完成/存在缺口。
> 每完成并实际测试一项，再更新对应状态；页面存在不等于功能完成。

> 本模块已有 `product` 服务、产品页面、分类、计量单位、SKU、规格属性和附件基础能力，
> 不从零重做。开发时优先复用现有权限、对象存储、编号、多语言和审计规范，不修改无关模块。

## 0. 定位

“产品管理”是独立业务模块，负责维护公司可以销售、采购、报价和管理库存的产品主数据。
询盘、报价、合同、采购、仓库和出运只能引用产品 ID / SKU ID，不应在各模块重复建立产品资料。

核心关系：

```text
产品分类 → 规格字段定义 → 产品 → SKU/规格型号
                               ├─ 图片、图纸、质检标准等附件
                               ├─ 销售/采购/库存计量单位
                               └─ 税则、税率、参考价格等业务资料

询盘/报价/合同/采购/仓库引用 → 产品 ID、SKU ID + 当时的业务快照
```

面向未来对外销售时，每家公司拥有独立的产品分类、字段、编号规则、单位和产品数据；
不能为每个客户公司复制一套代码。AI 可以作为匹配或录入建议，但不是产品新增、查询、
报价、采购或库存流转的必需条件，关闭 AI 后核心流程仍必须完整可用。

### 0.1 当前已有能力摘要

- ✅ 已有独立 `product` 微服务、PostgreSQL 数据库迁移、Proto/gRPC 接口和 Gateway 接入基础。
- ✅ 已有产品分类树、计量单位、产品、SKU、启用/停用和分页查询接口。
- ✅ 已有产品编码、中文/英文名称、品牌、产品类型、基础单位、参考价、币种、HS Code、税率、退税率和说明字段。
- ✅ 已有按分类配置规格属性的基础能力，属性支持继承、类型、单位、枚举、必填和匹配策略。
- ✅ 已有产品和 SKU 规格属性保存及候选产品召回基础能力。
- ✅ 已有产品附件的预签名上传、登记、查询和移除接口。

## 1. 模块与菜单结构

- ⬜ 左侧提供独立“产品管理”菜单，不归入采购或仓库子页面。
- ⬜ 产品模块包含“产品列表 / 产品分类 / 计量单位 / 规格字段”四个二级入口。
- ⬜ 默认进入产品列表；二级入口在产品模块内部切换并保持菜单高亮。
- ⬜ 产品列表和详情使用独立路由，刷新后仍停留在当前筛选或产品。
- ⬜ 页面提供“产品管理 / 产品详情”等面包屑，但不重复展示冗长业务流程图。
- ⬜ 桌面端、窄屏和常用浏览器布局均可用。
- ⬜ 中文、英文和西班牙文菜单及核心字段完整。

## 2. 产品分类与规格字段

### 2.1 产品分类

- ⬜ 支持多级分类树，例如“钢材 → 卷材 → 镀锌卷”。
- ⬜ 分类保存系统 ID、租户内唯一编码、名称、多语言名称、上级分类、显示顺序和状态。
- ⬜ 禁止把分类移动到自身或后代节点下，避免循环层级。
- ⬜ 有启用产品或启用子分类时禁止直接停用，并显示受影响数量。
- ⬜ 分类停用后保留历史业务快照，但不能用于新建产品。
- ⬜ 分类列表支持搜索、折叠、展开和仅显示启用项。

### 2.2 可配置规格字段

- ⬜ 每个分类可配置自己的规格字段，不把钢材、服装、化工等行业字段写死在代码中。
- ⬜ 字段保存稳定内部键、显示名称、多语言名称、数据类型、单位、是否必填、默认值和显示顺序。
- ⬜ 数据类型至少支持：文本、数值、范围、尺寸、日期、布尔值、单选和多选。
- ⬜ 子分类可以继承上级字段，并新增字段或收紧校验；继承字段的来源必须清楚显示。
- ⬜ 已被产品使用的内部键不能直接改名或删除；显示名称可以修改，删除改为停用。
- ⬜ 修改字段类型、单位或枚举值前显示受影响产品数量，禁止无提示破坏已有数据。
- ⬜ 规格字段用于录入与校验；AI 只能建议映射，不得绕过必填和数据类型校验。

## 3. 计量单位与换算

- ⬜ 统一维护计量单位编码、名称、多语言名称、单位类型和状态。
- ⬜ 产品必须设置基础库存单位，例如 `KG`、`MT`、`PCS`。
- ⬜ 可分别设置默认销售单位和采购单位。
- ⬜ 需要换算时保存“产品/SKU + 来源单位 + 目标单位 + 换算系数”，不能假设所有产品共用同一换算率。
- ⬜ 数量和换算系数使用 decimal，禁止使用浮点数造成累计误差。
- ⬜ 已被业务引用的单位不能物理删除；停用后历史单据仍按原单位显示。
- ⬜ 报价、采购和仓库调用统一换算规则，不在各模块重复计算。

## 4. 产品与 SKU

### 4.1 产品基本资料

- ⬜ 产品保存系统 ID、租户内唯一编码、名称、英文名、分类、品牌、产品类型、说明和状态。
- ⬜ 产品编码支持“系统自动生成”为默认方式，并允许租户管理员配置前缀和流水规则。
- ⬜ 可允许具有权限的租户使用手工编码，但同一租户内必须唯一。
- ⬜ 产品名称用于业务显示，产品编码用于稳定引用；二者不能混为同一字段。
- ⬜ 支持参考售价/成本、币种、HS Code、税率和出口退税率，但必须标明参考性质和生效时间。
- ⬜ 产品列表支持按编码、名称、分类、品牌、状态和规格关键词筛选。
- ⬜ 产品详情按“基本资料 / 规格与 SKU / 附件 / 业务引用 / 变更记录”展示。
- ⬜ 列表只显示识别和选择所需字段，详细规格进入详情查看。

### 4.2 SKU 与规格型号

- ⬜ 明确产品与 SKU 的区别：产品是公共品类，SKU 是可以报价、采购或计库存的具体规格。
- ⬜ SKU 保存系统 ID、产品 ID、租户内唯一编码、规格摘要、规格属性和状态。
- ⬜ SKU 编码支持系统自动生成，并允许按租户配置规则。
- ⬜ 同一产品下不能建立规格属性完全相同的两个启用 SKU；相似项保存前给出警告。
- ⬜ SKU 必须满足所属分类的必填规格和类型校验。
- ⬜ 已被合同、采购单或库存引用的 SKU 不能物理删除，只能停用。
- ⬜ 停用 SKU 后禁止用于新业务，但历史单据和库存流水仍可查看。

### 4.3 状态与重复检查

- ⬜ 产品状态至少区分：草稿、启用、停用。
- ⬜ 草稿可以继续补资料，但不能用于正式合同、采购和库存收发。
- ⬜ 启用前必须满足分类、基础单位、名称、编码和分类必填规格。
- ⬜ 新增或导入时检查编码精确重复，并按名称、品牌、分类和关键规格提示相似产品。
- ⬜ 相似提示允许有权限的员工确认后继续，精确编码冲突必须禁止保存。
- ⬜ 停用前显示未完成合同、采购订单、库存和其他业务引用数量。

## 5. 附件、导入与批量维护

### 5.1 产品附件

- ⬜ 支持图片、规格书、图纸、质检标准、证书和其他附件分类。
- ⬜ 文件存入私有对象存储，数据库只保存元数据和对象键。
- ⬜ 下载使用短期签名地址，不暴露永久公开链接。
- ⬜ 同类文件允许保留版本，旧版本不被新文件静默覆盖。
- ⬜ 上传、下载、作废和版本替换写入变更记录。
- ⬜ 文件类型、大小和名称由服务端校验，不能只依赖浏览器扩展名。

### 5.2 Excel/CSV 导入导出

- ⬜ 提供当前租户可下载的产品导入模板，模板包含租户启用的分类和规格字段说明。
- ⬜ 导入先预检，显示新增、更新、重复、警告和错误数量，员工确认后才写入。
- ⬜ 默认以产品编码/SKU 编码识别更新，禁止仅按名称静默覆盖。
- ⬜ 整批导入支持事务或明确的部分成功策略，错误必须定位到行和字段。
- ⬜ 导出遵守当前用户权限、筛选条件和语言，不泄露其他租户数据。
- ⬜ 大文件采用异步任务并可查看进度、失败原因和操作人。

## 6. 跨模块复用与历史快照

- ⬜ 建立统一产品/SKU 选择器，供询盘、报价、合同、采购、仓库和出运复用。
- ⬜ 选择器默认只显示已启用且当前用户有权查看的产品/SKU。
- ⬜ 支持按编码、名称、分类、品牌和关键规格搜索，不要求使用者记住产品 ID。
- ⬜ 业务单据保存产品 ID / SKU ID，同时复制当时的编码、名称、规格和单位快照。
- ⬜ 产品后续改名或停用不能修改历史合同、采购单和库存流水显示内容。
- ⬜ 询盘中的自由文本可以人工匹配到产品/SKU；AI 候选召回仅作为可选辅助。
- ⬜ 采购收货和仓库库存必须引用具体 SKU；无法确定 SKU 时进入待处理状态，不能生成模糊库存。
- ⬜ 产品停用后，各业务模块的新建选择器同步排除，但历史查询保持可见。

## 7. 多租户、权限与审计

- ⬜ 所有分类、字段、单位、产品、SKU 和附件都必须带 `tenant_id`，唯一约束包含租户范围。
- ⬜ 任一接口都不能通过修改 ID 读取或修改其他租户产品。
- ⬜ 每家公司可独立配置分类、规格字段、编号规则、默认币种和启用功能。
- ⬜ 预置行业模板只能“复制到租户后修改”，不能让多个租户共享可变业务数据。
- ⬜ 权限至少拆分：查看、维护分类、维护规格、维护产品、批量导入、附件管理、启停。
- ⬜ 普通员工、产品管理员和系统管理员的操作范围分别验收。
- ⬜ 关键变更统一记录字段、修改前值、修改后值、操作人、时间和原因。
- ⬜ 产品/SKU 启停、分类移动、规格结构调整和批量导入必须有独立审计记录。

## 8. 必须通过的测试

- ⬜ 分类树新增、移动、循环阻止、停用影响检查和租户隔离测试。
- ⬜ 规格字段继承、必填、类型、枚举、单位和历史兼容测试。
- ⬜ 产品/SKU 编码唯一、相似提醒、启停、并发版本和引用保护测试。
- ⬜ 计量单位及产品专属换算精度测试。
- ⬜ 产品附件上传、下载权限、版本、非法文件和跨租户访问测试。
- ⬜ Excel/CSV 预检、重复、错误行、更新确认、事务和大文件测试。
- ⬜ 产品选择器在报价、合同、采购和仓库中的启用/停用联动测试。
- ⬜ 历史单据快照不随产品改名、改规格或停用而变化。
- ⬜ 前端三语、窄屏、空状态、异常提示和生产构建通过。
- ⬜ 数据库迁移 Up/Down/Up、Go 测试、Proto lint/生成和 GitHub CI 通过。

## 9. 排期中（按小批次开发）

- ⬜ **PD0：现状审计与规则确认**——盘点现有服务、页面、表、接口、权限、引用关系和数据迁移，不修改功能代码。
- ⬜ **PD1：独立模块与基础体验**——菜单、路由、产品列表/详情、状态、搜索分页和统一 UI。
- ⬜ **PD2：分类、规格字段与计量单位**——分类树、字段继承、单位和换算规则。
- ⬜ **PD3：产品、SKU 与生命周期**——完整资料、编码、重复检查、启停和历史记录。
- ⬜ **PD4：附件与批量导入**——私有附件、版本、导入预检、导出和批量维护。
- ⬜ **PD5：跨模块选择与快照**——询盘、报价、合同、采购、仓库和出运统一引用。
- ⬜ **PD6：多租户、权限与联合验收**——租户配置、越权测试、审计、性能、三语和端到端验收。

每次只开发一个批次。完成后运行该批次测试、更新本文档状态并单独提交 GitHub；
未经确认，不自动开始下一批。

## 10. 上线前置

- ⬜ 数据库迁移不会破坏现有产品、合同、采购或库存数据，并具备回滚方式。
- ⬜ 产品与 SKU 的业务边界经过真实数据验证。
- ⬜ 租户隔离、唯一约束和跨租户越权测试通过。
- ⬜ 产品编号、分类、规格、单位和导入规则允许租户管理员配置。
- ⬜ 停用产品后，新业务禁止选择且历史记录完整保留。
- ⬜ 对象存储、文件权限和备份恢复方式确认。
- ⬜ 核心自动测试、浏览器验收和 GitHub CI 全部通过。

## 11. 明确不做 / 暂缓

- AI 自动创建产品或未经人工确认修改主数据。
- 为每个客户公司复制一套产品代码或独立开发页面。
- 完整 PLM、研发项目、配方、BOM、工艺路线和工程变更管理。
- 电商商城、商品推荐、促销和面向消费者的商品详情页。
- 实时供应商价格抓取和自动调价。
- 删除已经被合同、采购或库存引用的产品/SKU。
- 在产品模块内重复开发报价、采购、仓储和出运流程。
