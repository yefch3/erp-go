# 采购管理优化需求清单

> 状态截至 2026-08-22。本文档是采购管理模块的现状盘点、UI 优化及后续功能需求台账：
> ✅ 已完成并实测；⬜ 未做；🔶 部分完成/存在缺口。
> 每完成并实际测试一项，再更新对应状态；页面存在不等于功能完成。

> 本模块已有大量功能，不从零重做。开发时优先复用现有 `mail`、`procurement`、
> `export`、`masterdata`、`inventory`、权限体系和 UI 组件，不修改无关模块。

## 0. 定位

采购管理负责接收已经标准化的客户询盘，组织多工厂询价、报价比较、成本与利润测算，
并在客户接受报价及销售合同生效后，完成采购需求、采购审批、正式下单、履约、收货、
质检、入库和供应商应付对账。

邮件和采购的边界已经确认：

```text
客户 Email
└─ 邮件模块：LLM 标准化客户要求并生成标准 Excel（已经完成）
   └─ 自动转入采购管理 ─┐
员工已有的标准文件 ─────┴─→ 待复核询盘 → 页面人工复核/修正 → 进入询价项目
                              （采购不负责模板，不下载或重新上传修正版）

采购询价项目
├─ 多工厂 RFQ → 工厂报价导入 → 价格与交期比较
├─ 码头费 / 海运费 / 汇率 / 利润测算 → 客户报价
├─ 客户拒绝 → 返回原询价项目继续调整
└─ 客户接受 → 销售合同 → 采购需求 → 审批 → 正式下单
                                      → 跟单 / 收货 / 质检 / 入库
                                      → 供应商应付对账与采购结案
```

本次采购优化不重新开发邮件接收、LLM 标准化或标准 Excel 生成，也不删除已有采购数据。

已确认的模块边界：

- ✅ 客户 Email、LLM 标准化和标准 Excel 生成属于邮件模块，现有功能保留。
- ✅ 采购模块的正式起点是已经生成的标准 Excel。
- ✅ 标准询盘允许“邮件自动转入”和“员工手工上传标准文件”两个入口。
- ✅ 两个入口必须进入同一个“待复核询盘”列表，并使用同一套解析与人工复核逻辑。
- ✅ 询盘模板归邮件标准化模块管理，采购模块不提供模板管理、模板选择或模板下载。
- ✅ 采购人员直接在页面修正标准询盘，不采用下载、修改、重新上传的往返流程。
- ✅ 确认标准 Excel 后才生成正式采购询价项目。
- ✅ 现有询价、RFQ、报价、成本、采购需求和采购订单能力优先复用。
- ✅ 新版 UI 先解决流程不清晰和操作拥挤，不重构无关模块。

## 2. 已标准化询盘进入采购

### 2.1 邮件自动转入

- ✅ 邮件模块已经生成统一标准 Excel。
- ✅ 标准询盘生成成功后自动转入“待复核询盘”，无需采购人员操作邮件模块。
- ✅ 邮件生成任务固定保存本次使用的询盘格式 ID、编码、版本和字段快照；采购接收后沿用该版本，后续格式改版不改变历史询盘。
- ⬜ 记录源邮件 ID、源附件 ID、发件人、文件名和生成时间。
- ⬜ 对有来源邮件的询盘保留邮件追溯关系；采购页面不提供标准文件下载和修正版重传。
- ✅ 同一邮件转换结果只能生成一条有效待复核询盘；数据库唯一约束负责防并发重复。
- ⬜ 自动转入失败不得影响邮件和标准 Excel 已有数据。

### 2.2 员工手动上传

- ✅ 采购工作台和待复核询盘页面提供一个“手工上传标准询盘”入口。
- ✅ 文件应已由邮件模块或员工按公司生效中的询盘格式生成；采购模块不负责把客户原始文件标准化。
- ✅ 默认根据完整表头自动识别生效中的询盘格式；无法唯一识别时允许员工明确选择，不要求每次重复选择。
- ✅ 匹配成功后固定保存格式 ID、编码和版本；格式后来改版不改变本次询盘字段。
- ⬜ 支持系统规定的 `.xlsx` / `.csv` 标准文件格式。
- ⬜ 校验文件大小、工作表、表头、必填字段、数量和单位。
- ⬜ 上传失败时显示工作表、行号、字段和错误原因。
- ⬜ 记录上传员工、上传时间、原文件名和文件摘要。
- ⬜ 手动上传与邮件自动转入调用同一个后端解析服务。

### 2.3 统一状态

- ⬜ `PENDING`：等待预览确认。
- ⬜ `WARNING`：存在可修正警告。
- ⬜ `CONFIRMED`：已确认并生成采购询价项目。
- ⬜ `VOIDED`：已忽略或作废，保留历史但不进入后续业务。
- ⬜ 状态变更记录操作人、时间、原因及关联询价项目。

- ⬜ 操作保持简洁：人工复核、查看问题、作废；其他信息进入详情。

### 3.2 防止重复

- ⬜ 同一源邮件和附件不能重复转入。
- ⬜ 对 Excel 内容生成稳定摘要，同一内容重复上传时给出警告。
- ⬜ 相同客户、相近时间和高度相似产品明细提示可能重复。
- ⬜ 重复检查默认提示而不是覆盖已有数据。
- ⬜ 有权限员工确认继续时必须填写原因，并写入变更记录。

### 3.3 页面人工复核

- ⬜ 显示客户、联系人和来源邮件追溯信息；原文件仅作为审计来源保留，不作为日常操作入口。
- ✅ 表格、新增产品表单和必填规则均由该询盘绑定的格式版本动态生成；不默认假设所有公司都采购钢材。
- ⬜ 支持修改单行错误，忽略空白行、说明行和不需要采购的行。
- ⬜ 提示数量缺失、单位不明、重复行和无法识别字段。
- ⬜ 采购人员直接在页面修正错误、忽略无效行；不下载或重新上传修正版文件。
- ⬜ 正常询盘支持一次确认，不要求员工逐行重复点击。
- ⬜ 至少保留一条有效产品明细才能确认。
- ✅ 未完成资料允许保存草稿；每行直接显示“完整 / 缺少 N 项 / 已忽略”，并可查看缺少的具体字段。
- ✅ 只有所有未忽略行均满足该格式的必填规则时才能进入询价，后端再次校验，不能依赖前端绕过。
- ⬜ 确认后生成正式采购询价项目，并保留来源追溯关系。
- ⬜ 同一待复核询盘只能成功进入一次采购询价项目。
- ⬜ 修改前后值、忽略原因、确认人和时间写入变更记录。

### 4.5 业务进度

工作台按三个阶段展示，不把十多个节点挤在一条长流程线上：

1. **询盘进入**：待复核询盘、人工复核并进入采购询价项目。
2. **询价与客户报价**：多工厂 RFQ、报价比较、成本利润测算、客户报价。
3. **合同后采购**：采购需求、审批、正式下单、生产质检、到货入库、对账结案。

- ⬜ 每个阶段显示进行中或待处理数量。
- ⬜ 每个节点可以进入对应列表。
- ⬜ 当前待处理节点使用明显但克制的状态色。
- ⬜ 客户拒绝报价后回到原询价项目继续调整，不复制无关记录。
- ⬜ 常用桌面分辨率和窄屏下没有文字重叠或操作遮挡。

## 16. 询盘统一方案手工验收清单（2026-08-20）

1. 使用邮件模块生成一份询盘并转入采购，复核页应显示邮件当时绑定的格式名称与版本。
2. 手工上传一个表头只匹配一种生效格式的 `.xlsx` 或 `.csv`，保持“自动识别”，上传后应直接进入复核。
3. 上传表头不属于任何生效格式的文件，应拒绝创建询盘并提示检查格式；已有数据不能被修改。
4. 在复核页清空一个必填字段，该行应显示“缺少 N 项”；“保存修改”允许成功，“进入询价”必须被阻止并列出具体字段。
5. 补齐所有未忽略行后进入询价，询价项目应继续显示原询盘的动态字段与格式版本。
6. 管理员创建新格式版本后，再打开历史询盘，历史页面仍应使用旧版本字段，不随当前默认格式变化。

本轮自动验证结果：Gateway `internal/httpapi` 测试通过，采购服务 `internal/app` 测试通过，前端 45/45 测试通过，前端生产构建通过；构建仅有既存的大 chunk 提示，无编译错误。
