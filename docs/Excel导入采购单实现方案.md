# Excel 导入生成采购单实现方案

## 1. 目标

员工在邮件正文或附件转换出的 Excel 预览窗口中，点击“导入采购单”，经过供应商选择、
采购需求匹配和数据校验后，由系统创建一张采购单草稿。创建成功后系统自动生成全局唯一的
采购单号，并直接打开新采购单详情。

本功能只生成 `DRAFT` 状态的采购单，不自动提交审批，也不代表已经向供应商正式下单。

## 2. 关键业务约束

### 2.1 采购单必须来源于真实采购需求

现有采购模型要求采购单明细引用 `purchase_requirements`。Excel 中的一行产品不能绕过采购
需求直接成为采购单明细，否则客户尚未成交的普通询盘也可能触发真实采购承诺。

因此导入时必须满足以下任一条件：

1. Excel 行携带系统采购需求 ID，并且该需求仍有未下单数量；
2. 系统根据产品、规格、单位和数量找到候选采购需求，由员工手工确认匹配；
3. 找不到采购需求的行不能导入采购单，应继续走“建立询价案件”，或由有权限的员工先建立
   手工例外采购需求。

Excel 导入不得自动创建采购需求，也不得自动把询价案件转成采购单。

### 2.2 一张采购单只能对应一个供应商

导入向导必须先选择一个启用中的供应商。供应商 ID 来源于系统主数据，供应商名称和编码在
创建时保存快照，不能直接相信 Excel 中填写的显示文本。

如果同一个 Excel 中包含多个供应商，应拆成多张采购单，每张单分别确认后创建。

### 2.3 导入后直接进入采购单草稿

创建成功后后端返回：

```json
{
  "id": 123,
  "poNo": "PO-202608-0001",
  "status": "DRAFT"
}
```

前端关闭 Excel 窗口并跳转到：

```text
/purchase-orders?order=123
```

采购单页面读取 `order` 参数并自动打开该采购单详情或编辑窗口。页面同时提供“返回 Excel
来源”的链接，方便员工重新核对原始邮件。

## 3. 采购单号与唯一性

### 3.1 复用现有单号服务

系统已经配置采购单编码规则：

```text
业务类型：PURCHASE_ORDER
前缀：PO
周期：MONTHLY
流水位数：4
示例：PO-202608-0001
```

创建采购单时继续由 procurement 服务调用 masterdata 的：

```go
numbering.Next(ctx, "PURCHASE_ORDER")
```

不允许前端调用 `/numbering/next` 预取单号，也不读取 Excel 中的采购单号作为正式单号。
只有所有导入行、供应商和采购需求校验通过以后，后端才取号并写入采购单。

### 3.2 唯一性的三层保证

1. `number_sequences` 使用原子 `INSERT ... ON CONFLICT DO UPDATE` 递增，同一租户、业务类型、
   月份下的并发请求不会得到相同流水号；
2. `purchase_orders` 已有数据库唯一约束 `UNIQUE (tenant_id, po_no)`；
3. 创建接口收到唯一冲突时不得静默覆盖旧单，应记录错误并安全重试一次取号；仍失败则返回
   明确错误，不创建半张采购单。

系统只保证单号唯一，不追求绝对连续。校验失败时不应取号；服务异常导致少量跳号可以接受，
但绝不能重复或复用已经发出的单号。

## 4. Excel 格式

当前询盘 Excel 的系统兼容模板继续保留：

1. 产品
2. 材质/标准
3. 牌号/等级
4. 厚度/壁厚(mm)
5. 宽度/直径/边长1(mm)
6. 高度/边长2(mm)
7. 长度(mm)
8. 表面要求
9. 涂层/镀层
10. 公差
11. 卷重
12. 卷内径
13. 包装
14. 交期
15. 付款条件
16. 贸易术语
17. 港口
18. 单位
19. 备注
20. 数量
21. 单价
22. 总价

同时提供“钢材详细尺寸模板”，将兼容模板中的混合尺寸改为八个独立列：厚度(mm)、
壁厚(mm)、宽度(mm)、高度(mm)、直径(mm)、边长1(mm)、边长2(mm)、长度(mm)。
不适用于当前产品的列必须留空，不允许把直径写入宽度或把壁厚写入厚度。客户可在
询盘模板管理页选择或设为默认，也可直接在邮箱生成入口切换模板。

用于采购单导入时，系统还需要以下内部匹配信息：

| 字段 | 必填 | 处理方式 |
|---|---:|---|
| 采购需求 ID | 条件必填 | 系统导出的模板可写入；客户原始 Excel 通常没有，需要人工匹配 |
| 产品/SKU | 是 | 根据内部产品目录确认，不能只保存客户自由文本 |
| 数量 | 是 | 必须大于 0，且不能超过采购需求未下单数量 |
| 单价 | 否 | 空值按 0 保存草稿；必须为非负数 |
| 单位 | 是 | 必须与采购需求单位一致，暂不自动换算 |
| 交期 | 否 | 可作为采购单预计交期的候选值 |

不建议随意改变面向客户询盘的 22 列格式。内部的采购需求 ID、产品 ID、SKU ID 可以保存在系统
生成的专用采购导入模板中，或仅保存在导入预览会话中，不必暴露在客户看到的表格里。

## 5. UI 设计

### 5.1 Excel 预览窗口

在现有按钮区域增加：

```text
[关闭] [建立询价案件] [导入采购单] [下载 Excel]
```

“导入采购单”显示规则：

- 用户拥有 `procurement:order:write` 时显示；
- Excel 已成功解析且存在明细行时可点击；
- 预览只返回前 200 行而不是完整文件时置灰，并说明“请下载核对或上传完整采购模板”；
- 当前文件没有可识别的数量列时置灰，并直接显示原因；
- 如果来源明显是普通客户询盘，按钮仍可进入匹配向导，但不能跳过采购需求确认。

### 5.2 导入向导

点击按钮后打开三步向导。

#### 第一步：采购单基本信息

- 供应商：必填，从启用中的供应商主数据选择；
- 币种：默认使用供应商币种，可修改；
- 预计交期：从 Excel 交期提取，可修改；
- 备注：自动写入来源邮件主题、邮件 ID、附件 ID 或文件名；
- 采购单号：显示“保存后由系统生成”，不提供输入框。

#### 第二步：明细匹配

逐行展示：

| Excel 产品/规格 | Excel 数量 | Excel 单价 | 匹配采购需求 | 可下单数量 | 结果 |
|---|---:|---:|---|---:|---|
| 镀锌卷 G60 0.8×1500 | 1600 |  | CT-xxx 第 2 行 | 1600 | 已确认 |

匹配状态：

- `MATCHED`：唯一候选，仍需员工确认；
- `MULTIPLE`：多个候选，必须手工选择；
- `NOT_FOUND`：没有采购需求，不能提交；
- `QTY_EXCEEDED`：数量超过剩余需求，必须修改或拆分；
- `UNIT_MISMATCH`：单位不一致，不能自动换算；
- `DUPLICATED`：同一采购需求在本次导入中重复出现，应合并或删除一行。

#### 第三步：创建确认

展示供应商、币种、明细数量、总吨数和总金额。员工确认后才调用创建接口。创建成功显示：

```text
采购单 PO-202608-0001 已建立为草稿
```

随后自动进入该采购单。

## 6. 后端接口

建议使用“预览”和“确认”两个接口，禁止上传后未经确认直接写正式业务表。

### 6.1 导入预览

```text
POST /api/purchase-orders/imports/preview
权限：procurement:order:write
```

请求可以引用邮件 Excel 转换结果，也可以上传 `.xlsx`：

```json
{
  "sourceMailId": 2020,
  "sourceAttachmentId": 88,
  "convertedFileKey": "...",
  "supplierId": 12
}
```

响应返回临时 `importToken`、解析行、候选采购需求和错误信息。预览阶段不生成采购单号，也不
修改采购需求。

### 6.2 确认创建

```text
POST /api/purchase-orders/imports/{importToken}/confirm
权限：procurement:order:write
```

```json
{
  "supplierId": 12,
  "currency": "USD",
  "expectedDate": "2026-09-01",
  "remark": "来源邮件 #2020",
  "lines": [
    { "rowNo": 2, "requirementId": 301, "qty": "1600", "unitPrice": "520" }
  ]
}
```

后端必须再次读取并锁定采购需求，重新验证剩余数量，不能信任预览时的旧结果。确认接口最终
复用现有 `CreateOrder` 用例，而不是另写一套采购单创建规则。

## 7. 幂等与重复导入

网络超时或员工双击不能生成两张采购单。建议新增导入记录：

```text
purchase_order_imports
  tenant_id
  import_token
  source_type: MAIL_EXCEL / UPLOAD
  source_mail_id
  source_attachment_id
  file_sha256
  status: PREVIEWED / CREATED / EXPIRED
  purchase_order_id
  created_by
  created_at / expires_at
  UNIQUE (tenant_id, import_token)
```

确认接口在事务中锁定导入记录：

- 第一次确认创建采购单并写入 `purchase_order_id`；
- 相同 token 再次确认直接返回已经创建的采购单；
- 相同文件哈希再次导入时提示“这个文件曾生成采购单 PO-xxx”，由员工决定是打开旧单还是
  创建新的导入会话；
- 不能仅以文件哈希绝对禁止重复，因为同一个模板经过业务确认后可能确实需要再次采购。

## 8. 安全与数据校验

- 只接受 `.xlsx`，限制文件大小、工作表数量和总行数；
- Excel 公式按计算结果读取，不执行宏、外部链接或嵌入对象；
- 文本以普通字符串处理，防止公式注入；
- 金额、数量使用 decimal 字符串，禁止 `float64`；
- 供应商、采购需求、邮件和附件都必须校验租户；
- 邮件来源还要校验当前员工是否有权读取该邮件；
- 创建前重新验证采购需求状态和未下单数量；
- Excel 中的产品名、供应商名、采购单号都不能作为可信主键；
- 创建动作写审计日志，保存来源邮件、附件、文件哈希、操作者和解析结果版本。

## 9. 错误处理

| 错误码 | 提示 |
|---|---|
| `PO_IMPORT_FORMAT_INVALID` | Excel 格式无法识别 |
| `PO_IMPORT_TOO_LARGE` | 文件行数或大小超过限制 |
| `PO_IMPORT_REQUIREMENT_REQUIRED` | 有明细尚未匹配采购需求 |
| `PO_IMPORT_QTY_EXCEEDED` | 导入数量超过采购需求未下单数量 |
| `PO_IMPORT_UNIT_MISMATCH` | Excel 单位与采购需求不一致 |
| `PO_IMPORT_ALREADY_CREATED` | 本次导入已经生成采购单 |
| `PO_IMPORT_EXPIRED` | 导入预览已过期，请重新导入 |
| `PO_NUMBER_CONFLICT` | 采购单号生成冲突，请重试 |

任何一行失败时整张采购单不落库，不允许只创建部分成功的采购单。

## 10. 分阶段实施

### P1：当前 Excel 预览增加入口

- 增加“导入采购单”按钮；
- 基本信息和明细匹配向导；
- 复用当前 22 列解析结果；
- 只允许匹配现有采购需求；
- 创建草稿并跳转采购单详情。

### P2：采购单专用 Excel 模板

- 在待采购页面勾选需求并导出内部模板；
- 模板携带采购需求 ID 和内部产品标识；
- 支持员工填写供应商报价后重新导入；
- 减少产品和需求的人工匹配。

### P3：审计与大文件异步处理

- 持久化导入会话和重复导入提示；
- 大文件通过异步任务解析并使用 SSE 通知；
- 增加导入历史、失败报告 Excel 和管理员审计页面。

## 11. 必测场景

1. 100 个并发创建请求得到 100 个不同采购单号；
2. 同一 `importToken` 重复确认只生成一张采购单；
3. 两人同时导入同一采购需求时，后确认者因剩余数量变化失败；
4. 数量超额、负数单价、重复需求、单位不一致均不创建采购单；
5. 跨租户供应商、需求、邮件或附件均返回无权访问；
6. 普通客户询盘没有采购需求时不能直接生成采购单；
7. 创建失败不留下采购单头、孤立明细或半完成导入记录；
8. 创建成功后自动打开正确采购单，单号、金额和 Excel 明细一致；
9. 导入只创建草稿，不自动提交审批；
10. 中英文和西班牙文按钮、错误提示和向导字段完整。

## 12. 本阶段明确不做

- 不修改现有采购单创建和审批代码；
- 不允许 Excel 指定正式采购单号；
- 不从普通客户询盘自动建立真实采购需求；
- 不自动提交审批或发送供应商邮件；
- 不因为 Excel 导入而改变码头到货、出运或库存台账逻辑。

## 13. 完整后续路线图

Excel 导入不是一个孤立按钮。最终业务链路应当是：

```text
客户邮件 / 工厂报价 Excel
  → Excel 解析与预览
  → 询价案件或采购需求匹配
  → 导入采购单草稿
  → 采购单审批
  → 向供应商正式发单
  → 工厂生产进度跟踪
  → 工厂送达码头库
  → 码头到货确认
  → 衔接出运
  → 供应商付款与采购分析
```

本节按业务能力描述阶段目标，只维护汇总状态，不在这里打 tick。实际开发、测试、提交和验收进度
统一以第 14 节的“实施批次清单”为准，避免同一事项在两个位置重复勾选。

- 增加采购工作台；
- 工作台内展示“询价案件、待采购、采购订单”三个阶段；
- “采购管理”使用与“基础数据”一致的悬浮子菜单；
- 保留旧路由和旧链接；
- 根据用户现有读取权限隐藏无权访问的菜单项。

- 重新提交同一个导入 token 返回同一张采购单。

### 阶段 C：采购角色与细粒度权限

目标：不再依靠超级管理员完成所有采购工作。

新增标准角色：

- `BUYER`：采购专员；
- `PROCUREMENT_MANAGER`：采购经理；
- 继续使用 `LOGISTICS`：物流/码头操作；
- 继续使用 `FINANCE`：财务。

建议新增权限：

- `procurement:sourcing:send`
- `procurement:sourcing:price`
- `procurement:sourcing:approve`
- `procurement:requirement:exception`
- `procurement:order:submit`
- `procurement:order:cancel`
- `procurement:receipt:write`
- `procurement:payment:read`
- `procurement:payment:write`

当前状态（2026-08-17）：**阶段 C 已完成，对应批次 4。** 已增加采购专员和采购经理标准角色，拆分采购需求
例外、订单提交/取消、码头到货和付款权限，并在前端按钮与后端 API 使用相同权限。

职责划分：

| 操作 | 采购专员 | 采购经理 | 物流/码头 | 财务 |
|---|---:|---:|---:|---:|
| 导入和编辑采购单草稿 | 是 | 是 | 否 | 否 |
| 提交采购单审批 | 是 | 是 | 否 | 否 |
| 审批采购单 | 否 | 是 | 否 | 按流程参与 |
| 取消已下达采购单 | 否或受限 | 是 | 否 | 否 |
| 登记送达码头 | 否 | 可查看 | 是 | 否 |
| 采购付款与对账 | 可查看 | 可查看 | 否 | 是 |

需要修正当前“码头到货也要求维护采购单权限”的问题。到货登记应使用独立的
`procurement:receipt:write`，使物流人员能登记到货但不能修改供应商订单。

验收标准：

- 每个按钮和 API 都执行相同的后端权限检查；
- 物流角色不能创建、改价或提交采购单；
- 采购专员不能自行审批自己提交的订单；
- 财务不能修改采购数量和供应商；
- 超级管理员继续拥有所有权限。

### 阶段 D：询价案件数据范围和价格隔离

目标：销售只能看到自己或本部门的询价案件，采购部门可以集中处理全公司的询价，但工厂底价
不能因为拥有普通读取权限而暴露给所有人。

交付内容：

- 询价案件列表和详情按 `owner_id` 执行 `SELF / DEPT / DEPT_AND_SUB / ALL` 范围；
- 角色权限页面增加“采购询价数据范围”；
- 采购专员和采购经理默认为 `ALL`；
- 其他新授予询价权限的角色默认 `SELF`；
- 工厂单价、成本和利润字段在后端响应层要求 `procurement:sourcing:price`；
- 普通销售可以查看自己的需求和客户报价，但接口不返回工厂底价；
- 列表、详情、工厂询价 Excel 和所有询价子资源 API 使用同一数据范围规则。

当前状态（2026-08-17）：**阶段 D 已完成，对应批次 5。** 案件列表、详情和所有子资源已经按负责人数据范围
过滤，范围外对象统一按不存在处理；采购标准角色默认使用 `ALL`。工厂底价、成本和利润字段在后端响应层按
`procurement:sourcing:price` 脱敏，普通销售仍可查看自己的需求和客户报价。

验收标准：

- 修改 URL 中的案件 ID 不能越权打开他人案件；
- 列表分页总数不泄露范围外案件数量；
- 没有价格权限时，接口响应本身不包含工厂底价，而不只是前端隐藏；
- 管理员修改角色范围后，用户刷新权限即可生效。

### 阶段 E：采购单专用 Excel 模板

目标：减少从任意客户 Excel 进行产品和需求匹配的人工工作。

交付内容：

- 在“待采购”页面勾选采购需求并导出工厂询价/采购导入模板；
- 模板带有隐藏或受保护的采购需求 ID、产品 ID、SKU ID 和单位 ID；
- 员工填写供应商单价、交期、MOQ、付款条件后重新导入；
- 系统验证模板版本、列头和内部 ID；
- 支持一个模板拆分给不同供应商；
- 导入失败时生成带错误列的结果 Excel。

当前状态（2026-08-17）：**阶段 E 已完成，对应批次 6。** “待采购”页面支持按所选需求导出带版本和内部 ID
的采购模板，重新导入后会校验列头、版本、需求身份和可采购数量，按供应商拆分预览并沿用幂等确认流程创建
采购单草稿；错误数据可下载带错误列的结果文件。

模板需要有明确版本号，例如：

```text
template_type = PURCHASE_ORDER_IMPORT
template_version = 1
exported_at = 2026-08-14T10:00:00+08:00
```

旧版本模板不能静默按新规则解析，应提示升级或使用对应解析器。

### 阶段 F：采购单审批和正式发单

目标：草稿不等于已经向供应商承诺；审批通过后才正式下单。

交付内容：

- 导入完成的采购单保持 `DRAFT`；
- 采购单可以点击“提交审批”；
- 按金额、币种、供应商风险或产品类型选择审批流；
- 审批通过后状态变为 `ORDERED`；
- 审批驳回后回到可编辑状态并保存审批意见；
- 正式发单时生成供应商版 Excel/PDF；
- 从采购部门公共邮箱或指定员工邮箱发送；
- 保存收件人、附件、模板版本、发送人和发送时间；
- 发单失败不改变订单为“已发送”，允许安全重试。

当前状态（2026-08-17）：**阶段 F 已完成，对应批次 7。** 采购单支持草稿、提交、审批、驳回和下单；
审批通过后可生成供应商版 Excel/PDF，并从采购公共邮箱或当前员工邮箱正式发送。系统独立保存收件人、附件、
模板版本、发送人、发送时间和发送状态，发送失败可安全重试，已发送订单会阻止重复发送。

建议增加状态或独立发送状态，区分：

```text
审批通过但未发送
已发送供应商
供应商已确认
```

审批状态和邮件发送状态不能混用为一个字段。

### 阶段 G：工厂确认与生产进度

目标：采购单发出后能够持续跟踪，而不是只在预计交期当天才发现延误。

交付内容：

- 记录供应商确认的数量、价格和交期；
- 与采购单原值不一致时生成差异确认；
- 生产节点：待排产、已排产、生产中、质检、待发货、已发往码头；
- 每个节点保存计划日期、实际日期、负责人和备注；
- 支持供应商提供的质检报告、装箱单和照片附件；
- 预计延期时向采购负责人和相关销售发提醒；
- 重要价格或数量变更重新走审批，不允许直接覆盖历史订单。

当前状态（2026-08-17）：**阶段 G 已完成，对应批次 8。** 已支持供应商数量、价格和交期确认，差异内容进入
独立审批且不覆盖原采购单；六个生产节点均可维护计划/实际日期、负责人、备注和附件，逾期未完成节点会生成
提醒并保留审计记录。

### 阶段 H：码头到货与出运衔接

目标：工厂生产完毕后直接送到码头库，不建立公司自有库存核算。

交付内容：

- 到货地点只能选择 `PORT_TERMINAL` 类型；
- 按采购单和明细登记分批到货；
- 保存码头库、参考号、到货时间、数量和操作人；
- 阻止超收；
- 为错品、单位不一致建立异常处理流程；
- 到货记录只维护码头保管和货权台账，不减少合同采购需求；
- 采购需求按合同全量采购，不用码头现存数量抵扣；
- 到货货物能够衔接后续出运和码头放货流程；
- 支持短装、破损、质量异议和退货记录。

当前状态（2026-08-17）：**阶段 H 已完成，对应批次 8。** 到货登记使用独立的
`procurement:receipt:write` 权限，物流人员无需采购单写权限即可登记到货；支持错品、单位不一致、短装、破损、
质量异议和退货异常的登记、处理结果与处理人审计。

### 阶段 I：供应商付款与采购对账

目标：在采购执行完成后形成可追踪的应付和付款记录。

交付内容：

- 采购订单金额、到货金额和供应商发票三方核对；
- 支持预付款、进度款、尾款和多次付款；
- 每次付款保存币种、汇率、银行流水、付款日期和操作人；
- 不允许累计付款超过批准金额，例外需审批；
- 订单取消或价格变更后重新计算应付余额；
- 财务角色可操作，采购角色原则上只读；
- 支持供应商对账单导出。

当前状态（2026-08-17）：**阶段 I 未开始，对应批次 9。**
